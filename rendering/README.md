# Code Atlas — 저장소를 걷다

DEMOS_CODEX의 실제 소스·문서 스냅샷을 3D 건물로 탐색하는 로컬 웹 앱입니다. 2,063개 파일, 866,762줄, 10개 기능 구역을 표시합니다. 데이터에 있는 8,672개 내부 import 발생 위치는 화면에서 파일 쌍별로 합쳐 표시합니다. 스냅샷 생성 시각은 2026-10-08 01:14:22 KST입니다.

## 실행

저장소 루트 `D:\AI_Agent\DEMOS_CODEX`의 PowerShell에서:

```powershell
npm.cmd --prefix .\rendering run setup:debug
npm.cmd --prefix .\rendering run dev
```

`setup:debug`는 최초 한 번 실행합니다. 프로젝트 전용 `.venv`에 debugpy 1.8.22를 설치합니다. 브라우저는 **http://127.0.0.1:4173/**이며, `dev`가 지도와 로컬 디버거 서버(4174)를 함께 시작합니다. 종료는 실행한 터미널에서 `Ctrl+C`입니다.

지도·설명·가상 예제만 사용할 때는 빌드 결과물을 Python으로 열 수 있습니다. 디버깅·실행 녹화는 Node 서버와 Python이 필요합니다. 위 서버를 종료한 뒤 실행하세요.

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory .\rendering\dist
```

패키지를 다시 설치해야 하는 환경에서는 `npm.cmd --prefix .\rendering ci`를 먼저 실행합니다. Node 24에서 제작·검증했습니다. 분석기는 Python 표준 라이브러리만 사용합니다.

## 사용

- **조감도:** 드래그 회전, 휠 확대·축소, 우클릭 드래그 이동.
- **걷기:** WASD 또는 방향키 이동, 마우스로 시점 전환, Esc로 멈춤. 마우스 잠금을 허용하지 않는 내장 브라우저에서는 드래그로 시점을 전환합니다.
- **구역 탐색:** 왼쪽 구역 또는 지도 표지판을 선택합니다. 전체 보기 버튼으로 돌아옵니다.
- **구역 이해:** 10개 구역 모두 역할·동작 개요·먼저 볼 주요 파일을 제공합니다. 주요 파일을 선택하거나 **이 구역 따라가기**로 해당 경로를 시작합니다.
- **파일 찾기:** `/` 또는 검색창에서 파일명·경로·선언 이름을 검색합니다. 검색 결과나 건물을 선택하면 줄 수·선언·참조/역참조 파일을 확인할 수 있습니다.
- **연결선:** 녹색은 선택 파일이 참조하는 파일, 파란색은 선택 파일을 참조하는 파일입니다. 화살표는 import 방향입니다.
- **코드 탐색 가이드:** 기존 채팅 여정과 각 구역의 경로를 포함한 11개 경로·44단계입니다. 앱 조립, 에이전트 컨텍스트, 권한 범위 검색, 페이지 저장, 도구 실행, Hermes 모델 조회는 실제 호출을 확인한 **실행 흐름**입니다. UI 모듈·테스트·설계 문서·독립 화면은 **읽기 경로**로 구분합니다. 다음·이전·자동 재생·종료를 지원하고 자동 재생은 15초 간격입니다.
- **주요 코드 설명:** 34개 파일에 입력·처리·결과, 핵심 선언 설명과 코드 근거를 붙였습니다. 파일 정보에서 **이 코드가 등장하는 경로**를 선택하면 해당 파일부터 따라갑니다. **구역 역할 보기**로 돌아갈 수 있습니다. 작은 화면에서는 투어의 출처를 누르면 파일 설명으로 전환됩니다.
- **요청 데이터 예제:** 사이드바에서 텍스트 질문 6단계, 이미지 첨부 7단계, Hermes 외부 API 6단계, Hermes 웹 채팅 7단계의 총 26단계를 탐색합니다. 비교 버튼으로 예제를 바꾸고 단계 버튼이나 다음·이전으로 이동합니다. 각 단계의 입력·처리·출력, JSON 예시와 코드 근거를 확인하고 마지막 단계에서 예시 결과를 봅니다. 이미지 예제에는 가상 오류 화면 미리보기가 표시됩니다.

건물 높이는 전체 줄 수의 로그 스케일이며 상한이 있습니다. 파일 유형은 색상으로 표현하고, 실제 줄 수는 파일 정보에 표시합니다. 미니맵에서 구역 및 걷기 위치를 확인할 수 있습니다.

## 실제 디버거 · 실행 녹화

사이드바의 **디버거 · Playback**에서 `텍스트 query`, `이미지 query`, `Hermes HTTP API` 중 하나를 선택하고 질문을 입력합니다. 기존 **요청 데이터 예제**는 설명용 가상 데이터이고, 이 화면은 Python을 실행하면서 수집한 값입니다.

- **실제 디버깅:** 원본 코드 줄 번호 옆을 눌러 breakpoint를 추가·제거하고 **디버거 시작**을 누릅니다. 확인된 breakpoint는 채운 빨간 점으로 표시됩니다. **다음 줄**, **함수 안으로**, **함수 밖으로**, **계속**, **중단**, **종료**를 사용합니다. 강조된 줄은 실행 직전 위치입니다. 지역 변수의 이전 관측값과 달라진 값, 호출 스택, 실제 원본 소스를 봅니다. 스택을 선택하면 해당 프레임의 변수를 조회할 수 있습니다. 원본 범위 밖으로 진입한 경우 이를 표시하며 계속 실행해 다음 breakpoint로 이동할 수 있습니다.
- **녹화 · 재생:** **쿼리 녹화**로 같은 격리 경로를 한 번 실행합니다. 함수 진입·줄 실행·반환·예외·HTTP·SSE와 값의 복사본을 `recordings/*.json`에 저장합니다. 이전·다음, 주요 동작/줄 단위, 타임라인 위치 이동, 1×/2×/4× 재생과 일시정지를 지원합니다. **저장된 실행**에서 다시 열 수 있고, 재생은 코드를 다시 실행하거나 API를 호출하지 않습니다. 기록은 현재 프레임의 변수만 보장하므로 조상 프레임을 선택할 때 당시 변수 미수집을 안내합니다.

텍스트/이미지 경로는 실제 모델 후보 선택, 질문 추출, 프롬프트·하네스·컨텍스트 구성, 중첩 메시지 조립, API 스트리밍 함수 본문을 실행합니다. 이미지에는 내장된 작은 테스트 PNG를 붙이며, 이미지가 `text + image_url` 구조로 유지되는 과정과 MIME·길이를 표시합니다. OCR을 실행하지 않습니다. Hermes 경로는 실제 `_forward`와 `_build_headers`의 헤더 필터링·인증 주입·원시 SSE 중계를 실행합니다. HTTP/SSE 관측 데이터에서 요청 payload와 응답을 펼쳐 볼 수 있습니다. 금색 지도 연결선은 관측된 호출 스택을 나타내며 정적 import 연결선과 구분됩니다.

이 기능의 범위는 **격리된 원본 함수 실행 · 외부 API는 모의 응답**입니다. 원본 파일을 AST로 읽고 선택한 함수 본문을 원래 파일명·줄 번호로 컴파일합니다. Flask 앱 전체, 운영 프로세스, 브라우저 JavaScript, Hermes CLI, 실제 모델은 실행하지 않습니다. 설정·사용자 데이터·지식/메모리 저장소와 외부 HTTP 전송 경계는 fixture로 대체합니다. 전체 앱 실행과 일치하는 종단간 추적을 의미하지 않습니다. debugpy의 실제 DAP 연결이 전용 Python 프로세스만 멈추며, 화면을 닫거나 서버를 종료하면 해당 프로세스도 종료합니다.

서버는 `127.0.0.1`에만 바인딩하고 실행 대상·소스 파일을 허용 목록으로 제한합니다. 기록에는 소스 SHA-256과 실행 식별자를 저장하고, 다른 소스 버전이면 화면에 알립니다. 인증 값은 마스킹하며 이미지 원본과 세션 한정 DAP 핸들은 기록하지 않습니다. 값은 깊이·길이·항목 수를 제한하고 녹화는 6,000개 이벤트, UI 타임라인은 한 번에 400개만 표시합니다. 전체 기록은 위치 슬라이더로 탐색합니다. 실행은 최대 2개 동시·15분 제한이며, 줄 단위 기록은 개발용 격리 실행에만 사용합니다. 로컬 측정에서는 녹화가 텍스트/이미지 약 0.8초, Hermes 약 0.02초였으며 운영 성능 수치가 아닙니다.

데이터 예제는 읽기 전용 가상 입력·응답이며 실제 API를 호출하지 않습니다. 기본 Code 채팅은 이미지가 있으면 `text`와 `image_url`을 원래 구조로 API에 전달하며 OCR을 수행하지 않습니다. 선택한 API 모델의 이미지 지원이 필요하고 Canonical 지식 대화는 이미지 입력을 거부합니다. Hermes 직접 `/v1/chat/completions`는 HTTP 프록시 경로이고 웹 `/api/chat`은 CLI 실행·터미널 출력·자체 token SSE 경로입니다. CLI 내부 API 호출은 이 저장소에서 확인된 범위에 포함하지 않습니다.

## 갱신 · 검사

디버깅 소스 화면에는 원본 파일 전체가 보이지만 실행 대상에 선정한 함수와 도달하는 분기만 중단할 수 있습니다. `line`/DAP 중단은 실제 실행 직전 줄이며, `checkpoint`와 호출 스택이 없는 SSE 기록은 반환된 값의 관측 snapshot에 설명용 코드 근거를 붙인 것입니다. 재생 속도는 기록당 기본 0.85초의 보기 간격을 조절하며 원래 실행 시간은 각 이벤트의 ms에 표시합니다.

```powershell
npm.cmd --prefix .\rendering run scan
npm.cmd --prefix .\rendering run test
npm.cmd --prefix .\rendering run build
```

`scan` 후 개발 서버의 페이지를 새로고침합니다. 정적 `dist`로 사용할 경우 `build`도 다시 실행합니다. `public/tour.json`, `public/guides-*.json`, `public/scenarios-*.json`은 확인한 실제 코드 흐름·설명·데이터 예제를 별도로 관리해 재스캔으로 덮어쓰지 않습니다. 원본 함수가 바뀌면 근거 위치와 예제의 메시지·요청·응답 구조를 점검해야 합니다. 검사는 파일 존재 여부·줄 번호·10개 구역 커버리지와 이미지 메시지·Hermes 전송 경로를 확인합니다. 사라진 파일은 주요 파일과 경로에서 제외하며, 필요한 파일이 하나라도 사라진 데이터 예제는 전체를 제외합니다.

## 분석 범위

중앙 `app.py`와 루트 소스, `demos_v1`, `code_assist_v1`, `harness-mvp`, `hermes-web`, `uio`, `beno`, 프로젝트 문서를 선정해 분석합니다. 백업·사용자 데이터·런타임·의존성·외부 스킬 라이브러리·검증 산출물·루트의 독립 HTML 보고서·비밀정보 파일·지도 자체는 제외합니다. 링크나 Windows junction으로 저장소 밖을 따라가지 않습니다. 원본 앱을 실행하거나 데이터를 변경하지 않습니다.

Python은 AST로 선언과 정적 import를 분석합니다. JS/TS는 휴리스틱이며 경로 별칭과 계산된 동적 import는 완전하게 해석하지 못합니다. 일부 파일 유형은 메타데이터만 표시합니다. 주요 파일 34개와 모든 구역의 경로는 코드 본문을 확인한 설명이며 근거 위치를 제공합니다. 나머지 파일 설명은 이름·경로·선언을 기준으로 요약하고 구조 분석 설명으로 구분합니다. 외부·미해결 참조와 정적 import는 런타임 실행 흐름으로 단정하지 않습니다.

원본 코드 본문·문자열 값·docstring은 지도 메타데이터에 넣지 않습니다. 디버깅 화면은 실행 대상의 원본 파일을 별도 API로 읽기 전용 표시합니다. 성능과 가독성을 위해 지도 연결선은 60개, 패널의 방향별 참조는 40개, 선언은 20개, 검색 결과는 40개까지 표시하고 해당 제한을 화면에 명시합니다. 건물은 실제 대상 파일 전체를 렌더링합니다.

## 검증
