# Hermes에서 Second Brain 연결 설치

이 안내는 사용자가 요청한 Second Brain MCP 연결을 클라이언트 PC에 설정하는
절차입니다. 서버 주소와 토큰 파일 경로 또는 직접 입력한 토큰을 사용자에게서
받아 사용합니다. 사용자의 기존 Hermes 설정과 다른 MCP 연결을 유지합니다.

## 입력

- `서버 주소`: 사용자가 지정한 HTTPS 원점 주소. 예: `https://brain.example.com`.
  `/api` 경로, 사용자 이름/비밀번호, 쿼리 문자열은 붙이지 않습니다.
- `토큰 파일`: 현재 클라이언트 PC의 파일 경로. 또는 사용자가 제공한 토큰 값.
- 선택적으로 `어댑터 파일`: 사용자가 이미 복사한 `hermes_mcp.py`의 로컬 경로.

서버와 Hermes가 같은 PC에 있거나 로컬 터널을 쓰는 경우에만 loopback HTTP를
사용할 수 있습니다. 다른 PC에서 `127.0.0.1`은 클라이언트 자신입니다.
현재 10221 개발 실행기는 호스트 loopback에만 바인딩됩니다. 다른 PC 접근에는
관리자가 설정한 HTTPS 진입 주소가 먼저 필요합니다.

## 실행 순서

1. 현재 Hermes 프로필과 실제 `config.yaml`, Hermes Python 실행 경로를 찾습니다.
   `HERMES_HOME`이 설정되어 있으면 그 프로필을 따릅니다. 기존 설정을 백업합니다.
   서버 PC의 `G:`·`D:` 경로를 클라이언트 경로로 간주하지 않습니다.
2. Python 3.10 이상과 `mcp` 2.x를 확인합니다. Hermes가 쓰는 환경과 호환되면
   해당 Python을 사용합니다. 별도 설치가 필요하면 프로필 아래 전용 가상환경에
   `mcp>=2,<3`을 설치해 기존 Hermes 런타임 의존성을 바꾸지 않습니다.
   `from mcp.server import MCPServer`가 성공하는 Python을 선택합니다.
3. 사용자가 로컬 어댑터 경로를 제공했다면 그 파일을 사용합니다. 그렇지 않으면
   다음 두 주소에서 파일을 받아 프로필의 `tools/second_brain/` 아래에 저장합니다.
   - `{서버 주소}/static/integrations/hermes/manifest.json`
   - `{서버 주소}/static/integrations/hermes/hermes_mcp.py`
   다운로드에는 토큰이나 로그인 쿠키를 보내지 않습니다. 사용자가 지정한 원점의
   파일만 받고 다른 원점으로의 리디렉션은 따르지 않습니다. 인증서를 정상 검증하며,
   응답이 로그인 HTML이나 오류이면 실행하지 않습니다. `schema_version=1`,
   `filename=hermes_mcp.py`인 manifest의 파일 크기와 SHA-256이 다운로드와 일치해야
   설치합니다. SHA-256은 다운로드 일관성을 확인하며 별도 발행자 서명은 아닙니다.
4. 토큰 파일이 제공되면 그 경로를 사용합니다. 토큰 값을 직접 제공받았다면
   프로필 아래 별도 `second-brain.token` 파일에 토큰만 저장합니다. 토큰을 출력하거나
   확인 응답·명령줄 인수·설정 백업 설명에 포함하지 않습니다.
5. 기존 YAML의 `mcp_servers.second_brain` 항목만 추가하거나 갱신합니다.
   `command`, `args`, 토큰 경로는 모두 클라이언트의 실제 절대 경로로 지정합니다.
   다른 서버 항목과 사용자 설정은 유지하고 같은 이름을 중복 생성하지 않습니다.

```yaml
mcp_servers:
  second_brain:
    command: '선택한 클라이언트 Python의 절대 경로'
    args:
      - '클라이언트 hermes_mcp.py의 절대 경로'
    env:
      SECOND_BRAIN_URL: '사용자가 지정한 서버 주소'
      SECOND_BRAIN_TOKEN_FILE: '클라이언트 토큰 파일의 절대 경로'
    enabled: true
    timeout: 420
    connect_timeout: 30
    supports_parallel_tool_calls: false
    tools:
      resources: false
      prompts: false
```

6. 직접 토큰 변수 `SECOND_BRAIN_TOKEN`과 토큰 파일 변수를 함께 전달하지 않도록
   MCP 자식 프로세스의 환경을 확인합니다. 기존 `tools.include`/`tools.exclude`가
   있다면 사용자의 명시적 제한을 유지하고 어떤 도구를 차단하는지 알립니다.
   설치 예시의 플레이스홀더가 실제 경로·주소로 바뀌었는지 확인합니다.
7. 선택한 Python으로 `hermes_mcp.py --check`를 실행합니다. 위 두 환경변수는
   검사 프로세스에 전달합니다. 성공한 응답의 `enabled`, `connection_id`, `scopes`를
   확인합니다. 실제 MCP 초기화와 도구 목록 조회도 수행하고 상태 도구를 호출합니다.
   기본 어댑터는 10개 도구를 제공합니다. 이 검사는 메일 발송이나 자료 제출 없이
   상태만 확인합니다. 자동 연장을 켠 연결은 성공한 API 검사로 만료가 연장됩니다.
8. 필요할 때 쓰는 `second-brain` 스킬을 현재 프로필의
   `skills/second-brain/SKILL.md`에 설치합니다. 같은 이름의 기존 스킬이 있으면 위치와
   내용을 먼저 확인해 사용자 수정본을 보존합니다. 다운로드 주소는
   `{서버 주소}/static/integrations/hermes/second-brain/SKILL.md`입니다.
   3번과 같은 원점·인증서·무인증 다운로드 규칙을 적용하고 manifest의
   `skill.name=second-brain`, `skill.filename=second-brain/SKILL.md`, 크기·SHA-256을
   확인합니다. manifest가 임의 경로나 실행 명령을 지정하도록 허용하지 않습니다.
   기존 MCP 연결에 스킬만 추가할 때는 1번의 프로필 확인과 이 단계만 수행하면 됩니다.
   토큰 재발급이나 MCP 재설치는 필요하지 않습니다. 스킬은 추가 Python 의존성이 없습니다.
9. 사용한 서버 주소, 설치한 파일 위치, 인증 성공/실패, 허용된 기능을 요약합니다.
   이미 실행 중인 Hermes가 새 MCP 설정을 로드하지 않았다면 재시작 필요를 알립니다.
   스킬만 추가했다면 Hermes 대화창의 `/reload-skills`로 새 스킬을 등록할 수 있습니다.
   지원하지 않는 Hermes 버전은 다음 시작 때 로드합니다. 진행 중인 사용자 대화를
   강제로 종료하지 않습니다. 실제 `/second-brain` 발견과 스킬 로드를 확인합니다.

다운로드가 404라면 해당 서버에는 클라이언트 배포 파일이 아직 없습니다.
다른 서버나 추측한 사이트에서 대신 내려받지 말고 정확한 실패 원인을 알립니다.
서버 접속 실패, 인증서 오류, 토큰 만료·폐기, MCP 런타임 오류를 구분해서 보고합니다.
서버의 데이터·권한·방화벽 설정을 임의로 변경하는 설치 절차는 아닙니다.

## 사용

Hermes 대화창에서 `/second-brain 우리 프로젝트 기준으로 이 질문에 답해줘`로 시작합니다.
“Second Brain 지식으로 확인해줘”처럼 자연어로 스킬 사용을 요청해도 됩니다.
같은 주제의 후속 질문에는 스킬을 다시 부르지 않아도 됩니다. 이미 받은 근거는 재사용하고
추가 정보가 필요할 때만 조회합니다. “Second Brain 그만” 또는 “일반 대화로”로 끝내며,
무관한 주제나 새 대화에는 상시 조회 규칙을 이어가지 않습니다.

스킬은 Hermes의 대화 지침입니다. MCP 초기 연결은 Hermes 시작 때 일어날 수 있으며,
Ask API의 새 요청은 독립 요청이므로 Hermes가 필요한 앞선 맥락을 함께 전달합니다.
Wiki·Notion 사용 범위는 토큰을 발급할 때 서버 계정에서 선택한 범위입니다.
도구나 스킬 설치 자체가 자동화나 지식 등록을 시작하지는 않습니다.

새 연결의 조회 모드는 **내 지식** / **내 지식+공유 지식** 두 가지입니다. 개인 Wiki는
복수 선택할 수 있으며 공유 범위는 권한 있는 파트·팀·담당 뷰 하나입니다. `status`의
`knowledge_sets.version=2`이면 어댑터에서 조회 모드와 허용된 등록 대상을 지정할 수
있습니다. 초기 상태 확인은 범위 정보만 받고 검색은 전체 세트에 하나의 응답 예산을
적용합니다. `read`에는 검색 결과의 `view_space_id`를 함께 보냅니다.

기존 토큰은 기존 단일 Wiki 범위를 유지합니다. 복수 Wiki·공유 지식을 쓰려면 본인
계정의 에이전트 연결에서 원하는 범위를 선택한 새 연결을 만들고 로컬 토큰 파일을
교체합니다. 기존 설정을 보존하며 어댑터와 스킬을 갱신한 뒤 Hermes를 재시작합니다.
새 토큰을 발급하지 않은 상태를 복수 Wiki 연결 완료로 보고하지 않습니다.
