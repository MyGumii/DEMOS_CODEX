# 에이전트 지식 연결 사용 안내

## 조회와 등록 범위

조회 모드는 **내 지식** / **내 지식+공유 지식** 두 가지입니다. 두 모드 모두 선택한
개인 Wiki를 하나 이상 포함합니다. 개인 Wiki는 여러 개 선택할 수 있습니다.
공유 모드는 소속에 따라 조회 가능한 파트·팀·담당 뷰 하나를 함께 선택합니다.
팀·담당 뷰는 권한 있는 하위 조직 지식을 포함하며 다른 사람의 개인 Wiki는 포함하지
않습니다. 상위 문서를 하위 공간마다 복제하거나 반복 조회하지 않습니다.

조회와 등록 권한은 별도입니다. **지식을 등록할 Wiki**는 기본 개인 대상이며,
**추가로 등록을 허용할 개인 Wiki**는 제출할 때 선택 가능한 개인 대상입니다.
**본인 조직에 등록 허용**을 켜면 현재 등록 권한이 있는 본인 파트·팀·담당을 선택할
수 있습니다. 팀장·담당장은 본인의 조직에 등록하고 하위 조직에 대신 쓰지 않습니다.
**개인+파트 동시 등록 허용**은 파트 대상일 때만 표시됩니다.

직접 자료 제출에서 **자료 정제 시 조회 모드**, **등록 대상**, **등록할 개인 Wiki**를
선택합니다. 등록 대상의 개인·조직·개인+파트는 해당 연결에 허용된 선택지만 나옵니다.
조회 모드가 내 지식이어도 명시적으로 허용한 조직에 결과를 등록할 수 있습니다.
반대로 공유 지식을 조회했다는 이유로 조직에 자동 등록하지는 않습니다.

기존 단일 Wiki 연결은 범위가 바뀌지 않습니다. 새로운 범위를 쓰려면 새 연결을
만들어 Hermes의 토큰 파일을 교체합니다. 새 어댑터와 스킬도 함께 갱신해야 합니다.

## 토큰 유효 기간과 자동 연장

이미 발급한 토큰은 **연결 설정 → 내 연결 → 토큰 보기**에서 다시 확인할 수
있습니다. 펼친 영역의 **토큰 복사**로 복사하거나 **토큰 숨기기**로 닫습니다.
본인 로그인과 현재 연결 권한을 확인하며 만료·폐기된 연결은 조회하지 않습니다.
기존 연결에도 적용되므로 토큰을 다시 만들거나 Hermes 설정을 바꿀 필요가 없습니다.
조회는 토큰 값·권한·유효 기간을 변경하지 않으며, 조회 이력에는 원문을 저장하지
않습니다. 서버의 기존 서명 키로 값을 복원할 수 없는 경우에는 새 연결이 필요합니다.

유효 기간은 토큰을 사용할 수 있는 기간입니다. 기본 30일이며 1~365일을
선택할 수 있습니다. **사용 중인 토큰 자동 연장**을 켜면, 유효한 토큰으로
Hermes가 API를 성공적으로 사용할 때 만료 시각을 `그 사용 시각 + 설정한 기간`으로
갱신합니다. 같은 토큰 문자열을 계속 사용하므로 파일을 매번 바꾸지 않습니다.

예를 들어 30일짜리 토큰을 9월 11일에 만들고 9월 20일에 성공적으로 사용하면
그 사용 시각부터 다시 30일간 사용할 수 있습니다. 브라우저에서 연결 목록을
보는 행위, 서버의 정제 작업, 실패하거나 권한이 없는 API 요청은 연장하지 않습니다.
만료 전에 사용하지 못한 토큰은 자동 복구되지 않습니다. 사용자가 폐기했거나
계정 권한이 변경된 경우도 새 연결이 필요합니다.

기존 연결의 **자동 연장 켜기/끄기** 버튼으로 모드를 변경할 수 있습니다.
이 버튼은 토큰·Wiki·권한·등록 위치를 바꾸지 않습니다. 켜기만 하면 당장
만료 시각이 늘어나는 것은 아니며, 이후 성공한 API 사용부터 연장합니다.
끄면 마지막으로 갱신된 만료 시각까지 사용할 수 있습니다.

## Notion 페이지 선택

10221은 10322에서 사용하는 기존 Notion 저장소와 연결되어 있습니다.
본인 소유의 활성 페이지를 `상위 / 하위 / 손자 페이지` 경로로 표시합니다.
같은 제목의 페이지가 여러 곳에 있어도 상위 경로로 구분할 수 있습니다.
경로가 표시된 선택 목록이며, 펼치고 접는 별도 트리 탐색기는 아닙니다.

예를 들어 `Projects / Alpha / 회의 기록`을 선택하면 작업 기록은 **회의 기록
페이지의 바로 아래**에 생성됩니다. 제목은 `작업 제목 · 기록 v버전`입니다.
위치를 선택한 것만으로 모든 질문·메일을 기록하지는 않습니다. Hermes가
`second_brain_record_notion`을 호출하거나 사용자가 **현재 기록을 Notion에 저장**을
눌러야 합니다. 기존 연결에서 사용 안 함을 선택했다면 원하는 위치와 권한을
포함한 새 연결을 만듭니다.

기록에는 제출된 원본, 에이전트의 제안, 액션과 완료 기준, 확인 근거,
Second Brain의 지식 후보가 포함됩니다. 같은 작업 버전의 재시도는 중복 페이지를
만들지 않습니다. 새로운 근거나 결과로 작업 버전이 바뀌면 별도 기록을 만듭니다.
Notion 기록은 작업 이력이며, 그 자체가 검증된 Wiki 지식이나 실행 완료 증거는 아닙니다.

## Outlook 연결

Hermes의 메일 도구를 사용하는 흐름은 그대로 사용할 수 있습니다. 읽은 메일을
출처가 붙은 원본으로 Second Brain에 제출하면 됩니다.

**Second Brain의 Outlook 연결**은 이 서버 계정에 Microsoft 로그인을 연결하는
별도 기능입니다. 연결·해제·상태 확인은 본인이 로그인한 화면에서 수행합니다.
Hermes 토큰으로 Microsoft 계정을 연결하거나 해제할 수 없습니다. 기존의 암호화된
OAuth 상태·토큰 저장과 `Mail.Read` 권한을 사용합니다. 연결 자체는 메일 동기화,
발송, cron, 지식 자동 등록을 시작하지 않습니다.

서버 설정이 끝나면 **Microsoft 계정 연결** 버튼이 나타납니다. Microsoft 로그인과
동의를 완료하면 이 서버로 돌아옵니다. **Hermes의 서버 Outlook 읽기·회신 관측 허용**은
이 메일함을 Hermes API 도구에서도 사용할지 정하는 별도 권한입니다.

관리자는 서버에 다음 항목을 설정해야 합니다. 비밀값을 연결 토큰 파일이나
Hermes 프롬프트에 넣는 설정이 아닙니다.

- `CODE_ASSIST_MS_TENANT_ID`: Microsoft 조직 Tenant ID
- `CODE_ASSIST_MS_CLIENT_ID`: 등록한 앱의 Client ID
- `CODE_ASSIST_MS_CLIENT_SECRET_FILE`: 서버의 앱 비밀값 파일 경로
- `CODE_ASSIST_MS_REDIRECT_URI`: Microsoft 앱에 등록한 콜백 주소
- `msal`, `cryptography` 런타임 패키지

현재 10221 콜백은
`http://127.0.0.1:10221/api/integrations/v1/outlook/callback`입니다.
화면에서 접속한 원점과 설정 주소가 일치해야 합니다. 개발 서버와 다른 배포에서는
그 배포의 주소와 계정을 따로 설정합니다. 현재 호스트에는 Microsoft 앱 설정이
없으므로 **기능은 활성화되었지만 실제 Microsoft 계정 연결은 아직 미완료**입니다.

## 원문 인용 자동 등록의 실제 흐름

1. Hermes 또는 사용자가 작업을 제출합니다. 원본 자료·출처, 제안, 액션과 완료
   기준은 구분해서 저장합니다. 이 단계에서 Wiki에 지식을 바로 쓰지 않습니다.
2. Second Brain이 선택한 Wiki 맥락과 기존 작성 규칙으로 지식 후보를 만듭니다.
3. 각 주장에 연결된 인용이 제출 원본에 정확히 존재하는지, 액션 결과에 적절한
   확인 근거가 있는지, 등록 형식에 문제가 없는지 검사합니다.
4. 자동 등록 옵션이 켜져 있고 모든 후보가 원문 기재 유형이며, 인용 검사 통과·
   경고 없음 등의 조건을 충족하면 **출처가 표시된 원문 인용 기록만** 자동 등록합니다.
   모델이 쓴 요약과 바꿔 쓴 문장은 자동 기록의 본문에 넣지 않습니다.
5. 모델의 판단·권장·결정·실행 결과나 불확실성이 있으면 사용자 검토로 보냅니다.
   원문 일치가 실패한 후보는 승인할 수 없습니다. 자동 조건에 맞지 않는다는
   이유로 검사 기준을 낮추지 않습니다.
6. 등록은 기존 Wiki 서비스의 등록·정제·공개 경로를 거칩니다. 실제 지식탭에서
   공개 상태를 확인합니다. 등록 접수와 공개 완료는 구분됩니다.

메일에 “금요일까지 검토 부탁드립니다”가 있으면 그 구절과 출처를 기록할 수 있습니다.
그 메일과 Hermes의 제안만으로 “사용자가 검토를 완료했다”고 등록하지 않습니다.
원문에 인용이 있다는 검사는 원문 주장 자체의 사실성을 증명하지 않습니다.

## 탭과 버튼

| 위치 / 버튼 | 클릭하면 하는 일 |
|---|---|
| 연결 설정 | 연결 생성 폼과 기존 연결 목록, Second Brain의 Outlook 상태를 불러옵니다. |
| 연결 만들기 | 선택한 Wiki·Notion 위치·권한·유효 기간을 가진 연결과 토큰을 발급합니다. 작업은 실행하지 않습니다. |
| 토큰 보기 | 내 연결 목록에서 현재 유효한 본인 연결의 기존 토큰을 조회해 펼칩니다. 목록 로딩만으로 토큰을 가져오지는 않습니다. |
| 토큰 숨기기 | 펼친 토큰 입력란과 복사 버튼을 지웁니다. 토큰을 폐기하는 버튼은 아닙니다. |
| 토큰 복사 | 발급 직후 또는 토큰 보기로 표시한 토큰을 클립보드에 복사합니다. Hermes 설정은 별도로 저장합니다. |
| 연결 목록 | 생성 화면에서 내 연결 목록으로 돌아갑니다. 토큰은 기본적으로 숨겨져 있습니다. |
| 자동 연장 켜기/끄기 | 해당 연결의 이후 성공한 API 사용에 대한 만료 갱신 모드를 변경합니다. |
| 연결 폐기 | 해당 토큰의 이후 접근을 막습니다. 기존 작업·Wiki·Notion 기록은 유지됩니다. |
| Microsoft 계정 연결 | Microsoft 로그인 화면으로 이동합니다. 서버 앱 설정이 완료되어야 표시됩니다. |
| Outlook 연결 해제 | 이 서버 계정의 Outlook 로그인 정보를 해제합니다. Hermes 자체 메일 연결과는 별개입니다. |
| 작업·근거 검토 | 접수된 작업 목록과 상태를 표시합니다. 작업 제목을 누르면 상세 화면으로 이동합니다. |
| 새로고침 / 이전 작업 더 보기 | 최신 상태나 이전 목록을 조회합니다. 모델을 다시 호출하는 버튼이 아닙니다. |
| Second Brain으로 정제 | 대기·실패한 작업의 원본·근거·Wiki 맥락으로 지식 후보를 생성하거나 다시 처리합니다. |
| 근거 추가 후 다시 정제 | 선택한 액션에 승인·완료 보고·취소·결과 보고·메모를 추가하고 기존 초안을 무효화하여 재정제 대기로 돌립니다. 10221에서는 서버 작업자가 처리하며 수동 정제도 가능합니다. |
| 이 버전 검토 승인 | 현재 표시된 초안 버전과 해시를 승인합니다. 액션 실행 완료를 선언하거나 즉시 Wiki에 등록하지는 않습니다. |
| 후보 보류 | 현재 후보를 등록하지 않도록 보류 상태로 바꿉니다. |
| 지정 Wiki에 등록 | 승인된 후보를 지정 Wiki의 기존 등록 서비스로 제출합니다. 처리 중 재시도도 동일 작업으로 다룹니다. |
| 현재 기록을 Notion에 저장 | 현재 작업 버전의 원본·제안·근거·후보를 선택한 Notion 위치에 기록합니다. Notion 위치와 권한이 필요합니다. |
| 후속 결과 기록 만들기 | 등록·보류된 작업을 참조하는 새 작업을 만듭니다. 기존 지식을 덮어쓰지 않고 나중에 확인한 결과를 이어서 검토합니다. |
| 선행 작업 보기 | 후속 작업이 참조하는 이전 작업을 조회합니다. |
| 직접 자료 제출 | 사용자가 연결, 제목, 원본 자료, 제안·결과를 직접 입력하는 화면입니다. |
| 자료 제출 | 입력한 원본을 새 작업으로 접수합니다. 이후 정제·검토·등록 흐름은 Hermes 제출과 동일합니다. |
| 닫기 | 연결 창을 닫습니다. 이미 접수된 서버 작업은 계속 처리됩니다. |

“검토하겠다”는 승인, “검토했다”는 사용자 보고, 서버가 확인한 발송 회신,
실제 업무 결과는 서로 다른 기록입니다. 아무 기록이 없으면 미확인 상태를 유지합니다.
