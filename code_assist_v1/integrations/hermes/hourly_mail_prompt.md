# 매시간 메일 분류 예시

공통 `knowledge_loop_prompt.md` 지침을 적용한다. 이번 실행에서는 새 메일의
중요도, 판단 근거, 필요한 액션과 회신 초안을 작성한다. 메일을 발송하지 않는다.

1. 이전 실행에서 성공적으로 처리한 받은 편지함 커서를 읽는다. 서버 Outlook 도구를
   사용한다면 `second_brain_outlook_inbox`를 호출한다. 첫 실행의 `since_utc`는 사용자가
   정한 조회 시작 시각을 UTC `YYYY-MM-DDTHH:MM:SSZ`로 지정한다. 반환된 다음 페이지를
   모두 확인하고 `cursor_complete`가 되기 전에는 수집이 끝났다고 보고하지 않는다.
2. 각 메일의 발신자, 프로젝트, 기한, 요청과 관련된 맥락을 선택 Wiki에서 조회한다.
   메일 제공자의 importance 표시와 실제 업무 중요도를 구분한다. 근거 없는 긴급성,
   인물 관계, 약속이나 마감일을 만들어내지 않는다.
3. 처리한 각 메일을 `kind=email.triage` 작업으로 접수한다. 원문 본문을 `kind=email`로
   보존하고 `external_id=entry_id`, `revision=modified_at`을 넣는다.
   안정적인 `external_key`와 UUID `operation_id`를 기록해 중복 처리를 막는다.
   결과에는 중요도·판단 근거·액션·초안을 넣고, 액션의 `source_id`를 해당 메일에 연결한다.
4. Notion 사용이 설정돼 있으면 작업 버전을 기록한다. 각 메일의 접수·기록 성공과
   작업 ID를 저장한 뒤에만 커서를 다음 값으로 전진시킨다. 실패한 페이지는 같은
   작업 ID로 재시도한다. 커서가 만료돼 재수집하더라도 원본 버전의 중복을 구분한다.
5. 기존 미확인 액션에 실제 회신 후보가 생기면 `second_brain_observe_outlook_reply`로
   서버 검증을 요청한다. 원본 ID·직접 회신 헤더·보낸 편지함·발송 시각이 일치해야
   관측 기록이 생긴다. 이동된 메일이나 불충분한 헤더 때문에 검증할 수 없으면
   미확인으로 유지하고 사용자 확인을 요청한다. 회신 발송을 업무 완료로 확대 해석하지 않는다.
6. 새 근거가 추가된 작업은 Second Brain이 다시 정제하도록 하고 현재 버전을 Notion에
   기록한다. 이미 등록된 작업은 `followup_of`로 후속 작업을 만든다.
   검토할 지식 후보와 근거가 부족한 액션을 사용자에게 보고한다.

외부 메일 도구를 사용할 경우에도 원본 식별자·본문·버전과 실행 근거의 구분은 동일하다.
서버 Outlook 검증은 해당 서버에 연결된 동일 사용자 사서함에서만 동작한다.
