# Parent inserts during row/page placement

This continuation covers the parent link body when selected owned-DB rows
become ordinary child pages, and when one such page returns to its database.
The existing stable row/page identity, hidden property cells, attachments,
comments, relation values and exact placement receipt contracts remain in
`database_row_page_move_contract.md`. This packet does not replace them.

Before correction, an isolated same-parent two-row move retained the canonical
new paragraph but omitted it from the resulting durable Yjs body. The new
retention test reproduced that missing paragraph rather than inferring it
from source alone. Both placement writers now capture the existing authorized
current-generation post-frame insert witness alongside their parent snapshot,
frames and stamp. The reverse root-page path still has no parent link writer.

The shared parent validator independently replays old and old-plus-delta
outside SQLite. For a batch, it derives the exact proven base and appends only
the server-selected child links, in selected order. Existing visible IDs and
page identities must not conflict. The first structural anchor is the last
canonical ID in the current projected body; every later anchor is the preceding
inserted link ID. The complete batch metadata, body and title must match.
Single-link return uses the existing exact-current-child deletion validator.
No new JavaScript transformer behavior is needed; its existing batch branch
already supports the same proven-insert reconciliation.

The existing writer rechecks source/parent/page sequences, generations and
security/permission/lock scope, selected row versions, titles and reusable
shells before committing. All domain placement, structural commands, frames,
exact operation/hash receipt, audit and outbox remain atomic. A note added
after preparation must fence the commit while retaining that late note.
Retries must return one result with one link per selected row.

This is insertion-only reconciliation for the parent link body. Page-to-item
body transfer retains its existing separate shape guards. Typed deletion,
reordering, older gaps, nested child/DB transfers, synced item/template scope
and operating activation are not silently generalized by this change.

Testing uses synthetic catalogs and isolated applications. The browser fixture
adds only opt-in test arguments for the staged2424 row/page capabilities; normal
capability defaults remain false. Gates and qualified failures will be recorded
in `outputs/row-page-parent-rebase-20261003/phase-evidence.json` in the chat
workspace. Until those receipts pass, this packet remains in progress and full
original Notion goal completion remains unproven.
