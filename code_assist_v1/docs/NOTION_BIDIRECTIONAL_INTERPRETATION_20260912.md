# 두 언어 양방향 통역 자막

2026-09-12 사용자 요청: 한국어·영어·일본어 중 서로 다른 두 언어를 선택하고,
한·영 / 한·일 / 영·일 조합에서 서로 반대 언어로 통역한다. 세 언어 동시 출력,
음성 합성, 다른 SBE 계약 변경은 범위에 포함하지 않는다.

## 사용법

1. AI 노트의 `번역` 탭에서 `번역 방식 → 두 언어 통역 · 양방향 자막`을 선택한다.
2. `통역 언어 1`, `통역 언어 2`에서 서로 다른 두 언어를 선택한다.
3. 모델을 선택하고 `새 전사 자동 번역`을 켠 뒤 사용자가 소리 입력을 시작한다.
   기존 텍스트만 처리할 때는 `미번역 원문 번역`을 누른다.
4. 결과는 `[한국어 → 일본어]`와 같은 방향, 해당 원문, 번역으로 누적된다.
   기존 번역 다운로드·비우기 기능을 그대로 사용한다.

기존 노트는 단일 언어 번역을 유지하며 자동으로 모드·원문·저장 설정을 바꾸지 않는다.
기존 번역이 있는 상태에서 모드/언어 쌍을 바꾸면 이전 결과를 보존하고 재사용을 막는다.
필요한 번역을 다운로드한 후 사용자가 명시적으로 번역을 비워야 새 설정으로 처리한다.
녹음/전사 및 자동 번역 중에는 모드·언어 쌍 변경을 잠근다.

## 처리 계약

- Whisper/STT는 원문 전사를 담당한다. 두 언어 모드에서는 기존에 한국어 등 특정
  음성 언어를 골랐더라도 실제 업로드에는 자동 감지(`language=""`)를 사용한다.
  단일 언어 모드로 돌아오면 기존 세션의 음성 언어 선택을 보존한다.
- 번역은 한 원문 구간을 한 요청에 넣는다. LLM이 언어 전환 지점별로 구분하여 각
  문장을 선택한 쌍의 반대 언어로 한 번만 번역한다. 언어별 병렬 요청은 추가하지 않는다.
  자동 모델의 실패 시 기존 Gemma4 → Qwen3.6 → 활성·연결된 Codex fallback은 유지한다.
- 명시적 Codex 선택, `--codex` 미지정 시 완전 숨김, 읽기 전용·ephemeral 호출 및
  권한 재검증은 `NOTION_CODEX_DIRECT_SELECTION_20260912.md`의 정책을 유지한다.
- 입력: 기존 translate route에 `translation_mode="pair"`, `language_pair=["ko","ja"]`
  등을 추가한다. 서버는 허용 코드 세 개 중 서로 다른 정확히 두 개만 받는다.
  모드 생략은 기존 단일 번역과 호환된다. 언어 쌍의 순서를 뒤집어도 같은 설정이다.
- 모델 결과의 연속 `segments`는 원문을 공백·타임스탬프까지 정확히 재구성해야 한다.
  선택 쌍의 반대 방향인지, 필수 필드/형식/길이가 맞는지 확인한 뒤 서버가 표시 문자열을
  만든다. 누락·중복·잘못된 방향은 실패로 처리하고 원문 진행 위치를 건너뛰지 않는다.
- 모델이 선택 외 언어 또는 불명확한 구간으로 분류하면 `und`로 돌려주며 번역을
  만들어내지 않고 `[언어 확인 필요]`와 원문을 표시한다. 이 구간은 처리된 원문에
  포함되므로 재처리하려면 기존 번역을 비운 뒤 다시 요청한다.
- 기존 원문 80,000자, 요청 2,000자/앞 문맥 1,200자, 응답 12,000자,
  번역 누적 240,000자 한도 및 번역 슬롯/시간 제한을 유지한다.
- 결과는 기존 `translation_text`에 방향·원문·번역을 함께 저장한다. 새로운 구조화
  언어별 DB를 만들지 않는다. `translation_config`로 단일/쌍 설정을 구분해 늦은 응답과
  이전 결과 혼합을 막는다. 기존 페이지 저장 adapter와 다운로드·clear를 사용한다.
- 자동 번역은 페이지가 열린 동안만 동작하고 재접속 시 자동 전송을 재개하지 않는다.
  실제 사용자 페이지/DB, 녹음 장치, 기존 결과는 개발 테스트 대상으로 사용하지 않는다.
