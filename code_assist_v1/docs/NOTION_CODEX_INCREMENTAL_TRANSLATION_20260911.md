  표시한다. 공통 모델 registry/기본 모델/공유 bridge 코드는 변경하지 않았다.

## 사용자 사용 순서

1. 저장할 편집 내용이 있으면 저장한 뒤 10322 페이지를 새로고침한다.
2. AI 노트의 `번역` 탭에서 언어와 `Codex Local Agent`를 확인한다.
3. `새 전사 자동 번역`을 켠 뒤 `소리 공유로 회의 시작`으로 소리 입력을 직접 선택한다.
   로컬 Whisper는 녹음 시작 시 자동 번역이 켜져 있으면 4초 구간으로 동작한다.
   이미 녹음 중에 켜면 그 녹음의 기존 12초 구간 길이는 그대로 유지된다.
4. 원문은 `원문`, 번역은 `번역`에 따로 누적된다. 자동 요약과 호스트 비교는 별개다.
   자동 번역을 켜지 않고 `미번역 원문 번역`을 눌러 기존 원문 전체를 번역할 수도 있다.
5. `번역 중지`, `번역 비우기`, 다운로드 내용의 `번역`을 사용할 수 있다.
   새로고침·페이지 이동 뒤 자동 번역은 다시 직접 켜야 한다.

자동 번역은 원문에 새 텍스트가 들어올 때만 처리하며, 켜기만 해도 마이크나 공유
picker를 열지는 않는다. 이 작업에서는 실제 사용자 페이지 수정·회의 녹음·음악 재생을
시작하지 않았다. Codex에는 전사 텍스트와 직전 문맥만 전달하며 오디오를 보내지 않는다.

## 처리 및 안전 계약

- POST `/api/notion/ai-notes/translate`: 로그인·페이지 편집/잠금·workspace 권한 확인,
  모델 호출 전/도중/후 재확인. 읽기/댓글 권한에는 제공하지 않는다.
- 원문 구간 최대 2,000자, 앞 문맥 최대 1,200자, 목표 언어 최대 80자,
  HTTP 요청 최대 64,000바이트, 응답 번역 최대 12,000자.
- 문장/줄바꿈 경계를 선호해 나누되 긴 구간도 빠짐없이 순차 처리한다. 원문 누적은
  기존 80,000자 한도, 번역 누적은 240,000자 한도다.
- 전사 큐와 번역을 분리했다. 번역이 느려도 전사를 기다리게 하지 않는다.
  번역 요청은 노트당 한 번에 하나이며, 늦게 쌓인 원문은 다음 요청에서 묶어 처리한다.
- 서버 번역 동시 슬롯은 2개. 자동 모델 선택은 최대 3개 후보 각 1회;
  사내 API 호출 60초, Codex 호출 180초 한도다. 실패한 구간 이후를 건너뛰지 않는다.
- 저장된 `translation_source`와 원문의 정확한 prefix를 비교해서 기존 완료 구간을
  다시 번역/append하지 않는다. 사용자 원문 수정, 언어/모델 변경, 페이지·권한 변경
  또는 취소가 있으면 늦게 도착한 결과를 반영하지 않는다.
- 원문/번역은 기존 페이지 저장 adapter만 사용한다. 새 route 자체는 페이지나 SBE
  지식을 쓰지 않는다. 저장 실패는 화면 초안 상태로 명시하고, 재시도 시 먼저 저장한다.
- 중지는 브라우저 fetch를 취소하고 이후 구간 전송·결과 반영을 막는다. 서버에 이미
  전달된 모델 계산은 시간 한도 안에서 끝날 수 있으며 사용량도 발생할 수 있다.
- 자동 번역은 세션 메모리 상태이며 재접속 시 자동으로 재개하지 않는다.
- Codex 호출은 이번 번역 invocation에만 빈 임시 작업 디렉터리, read-only sandbox,
  ephemeral 설정을 적용한다. 공유 bridge의 일반 개발 권한 계약은 변경하지 않는다.
  입력은 실행 지시가 아닌 번역 자료로 취급하며 도구 사용·파일 접근을 금지하는 지침을
  전달한다. 이는 모델의 의미적 번역 정확성을 보증하는 검사가 아니다.
- 전사 원문/메모/요약은 서로 덮어쓰지 않는다. 번역 비우기는 번역만 삭제하며,
  전체 내용 비우기는 번역도 포함한다. 호스트 비공개 비교 기록은 비우지 않는다.
- 별도 번역 탭·페이지 저장·다운로드에 보이는 번역은 비공개 비교 요약과 다르다.
  일반/지식 연동 비교 요약 두 개를 사용자 화면에 표시하지 않는 기존 요구는 유지한다.
