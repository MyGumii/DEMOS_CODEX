# Notion 번역의 이전 2초 원문 대기열 혼입 수정

2026-09-13. `NOTION_UI_AUDIO_WIKI_REFINEMENTS_20260913.md`의 12초 수집 변경 이후
실제 사용 중 확인한 후속 결함이다. 기존 완료 증거, AGENTS, SBE hot contract 및
제품 전체 goal 상태를 변경하지 않는다.

## 관찰과 원인

Computer Use로 사용 중인 Chrome의 AI 노트 화면을 읽기 전용 확인했다.
음성 처리 간격은 12초이고 새 원문 타임스탬프도 00:00, 00:12, 00:24 순서였다.
그러나 기존 노트에는 이전 녹음의 2초 간격 원문이 남아 있었고, 번역 cursor는 그
미번역 대기열부터 처리하고 있었다. 따라서 새 수집 간격만 바꾸어도 사용자는 계속
이전의 짧은 원문에 대한 번역을 보게 됐다. 기존 검증에는 이 혼합 이력 재현이 빠졌다.
실제 원문 내용은 이 문서 또는 테스트 fixture에 복제하지 않았다.

## 변경

- 기본 번역 범위는 **이번 녹음만**이다. 이전 녹음을 포함한 전체 원문은 별도
  선택으로만 처리한다. 범위를 바꾸면 선택한 범위의 처음부터 번역하고 기존 결과는 보존한다.
- 성공적으로 녹음이 시작된 시각과 당시 원문 길이(`audio_started_at`,
  `audio_transcript_start`)를 저장한다. 새 범위에 이전 미번역 원문이나 이전 문맥을
  섞지 않는다. 녹음 시작이 실패하면 경계도 바뀌지 않는다.
- 경계가 없는 이전 노트는 녹음 시각이 있을 때 마지막 `[00:00] ` 줄에서 경계를
  복구한다. 이는 legacy 호환 추론이며, 수동 원문 편집/가져오기는 경계를 무효화한다.
- 새 녹음 중 이전 요청이 늦게 완료되어도 현재 결과에 반영하지 않는다. 기존 원문과
  번역은 삭제하지 않으며 이전 번역은 닫힌 `이전 번역 기록 (보존됨)`에 표시한다.
  다운로드에는 보존된 전체 번역을 포함한다.
- 자동 번역은 서버의 기존 2,000자 제한까지 대기 원문을 묶는다. 직전 문맥은
  현재 녹음 범위 안의 최대 1,200자다. 12초 수집 결과를 다시 2초 단위로 나누지 않는다.
  모델이 느리면 여러 수집 구간이 한 요청에 합쳐질 수 있다.
- `translation_source`는 전역 원문의 prefix cursor다. 명시적으로 건너뛴 이전 원문도
  prefix에 포함될 수 있으므로, 이것만으로 전체 이력이 번역되었다고 판단하면 안 된다.
  실제 범위는 `translation_scope_key`와 녹음 경계로 구분한다.
- 수동 원문 변경은 `audio_scope_invalid`를 기록한다. 원문/전체 비우기는 녹음 경계도
  제거한다. 번역 비우기는 번역 결과와 범위/표시 cursor를 함께 지운다.

## 적용 상태와 한계

수정은 정적 frontend만 해당한다. index의 관련 3개 script 버전은
`20260913-recording-scope`이며 서버 재시작은 필요하지 않다.
확인 시 원래 사용자 탭은 계속 녹음 중이었다. 따라서 그 탭을 새로고침하거나 서버를
종료하지 않았고, 회의 종료로 잔여 음성을 처리한 뒤 새로고침할 승인을 요청했다.
이 문서 작성 시 해당 승인은 아직 도착하지 않아 원래 탭의 적용은 보류 상태다.

12초는 수집 묶음 크기다. 전사와 LLM 응답 시간이 추가되므로 결과가 정확히 12초마다
도착하는 성능 보장은 아니다. 실제 모델의 지연은 합성 모델 테스트의 성공과 구분한다.
사용자가 회의를 종료하면 12초보다 짧게 남은 마지막 구간도 보존하여 처리한다.

### 사용자 승인 후 실제 탭 적용

후속 `승인해` 응답을 받고 기존 Chrome 녹음 탭을 다시 확인했다. 소리 공유 연결은
이미 종료되어 있었으며 미전사 음성 1구간이 남아 있었다. `미전사 음성 재시도`로
대기 구간을 처리하고 `전사 완료`, 회의 시작 버튼 활성화, 대기 음성 UI 해제를
확인한 뒤 원래 탭을 새로고침했다. 서버 프로세스는 재시작하지 않았다.

새로고침 후 번역 탭에서 12초, `이번 녹음만 (기본)`, 접힌 이전 번역 기록을 확인했다.
새로고침 직전과 이후의 DOM 값을 비교하여 기존 원문 전체와 번역 전체가 보존된 것을
확인했다. 새 녹음과 자동 번역은 시작하지 않았으며 사용자가 다음 회의를 시작할 수
있는 대기 상태다. 위의 적용 보류는 이 승인/적용 기록으로 해소됐다.
