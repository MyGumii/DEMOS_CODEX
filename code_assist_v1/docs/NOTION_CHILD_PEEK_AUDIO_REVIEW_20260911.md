# 하위 페이지 사이드 보기 교정 및 회의 음성 검토

2026-09-11. 이전 메뉴/수식 교정과 별개인 사용자 후속 요청이다.

## 하위 페이지: 구현·검증

- `child_page`의 기존 사이드 보기 진입점을 패널 아이콘 + `열기`로 명확하게 표시.
- `link_to_page`에도 같은 버튼 추가. 두 종류 모두 Alt+클릭으로 사이드 보기 지원.
- 마우스 hover 및 키보드 focus-within에서 버튼을 표시. 터치 환경은 상시 표시.
- 데이터베이스의 기존 사이드 보기 버튼에 정확한 이름/아이콘을 부여하고,
  collaborative presentation CSS에서 이 버튼을 숨기던 규칙을 좁게 교정.
- 부모 페이지 URL·내용을 유지하고 기존 `openSidePeek` 및 DB row context를 재사용.
  읽기 권한과 쓰기 권한을 혼동하지 않으며, 서버 접근제어는 변경하지 않음.
- 격리 브라우저 테스트 3개 통과(29.70초). child/link/DB 경로, Alt+클릭,
  읽기 전용, 키보드 버튼 노출, 부모 URL 유지 검증.
- Node UI runtime / slash reference / editor core 3종 및 JS 구문 검사 통과.
- 합성 화면: `.tmp/notion-child-peek-20260911/`.

## `/` 추천: 현 상태 설명, 코드 변경 없음

우리 앱의 추천은 `notion_slash_menu.js`의 `AI 노트 → HTML` 고정 목록이다.
사용 횟수를 수집하거나 개인별 빈도순 정렬하지 않는다. 실제 Notion에서 관찰한
추천 목록만으로 그 내부 추천 알고리즘이 빈도순이라고 단정할 수 없고,
검색한 공식 자료에서도 해당 계산 규칙을 확인하지 못했다.
사용 빈도/최근 사용 기반 개인화는 별도 요구사항이며 이번에는 추가하지 않았다.

## 회의 음성: 구현돼 있는 것과 남은 것

현재 입력은 마이크의 `getUserMedia`와 음성 파일이다. Zoom/Webex가 재생하는
시스템·탭 오디오를 직접 가져오는 코드는 없다. 현재 실행 화면에서도 STT 미설정으로
음성 시작/파일 입력 버튼이 비활성화된 것을 확인했다.

설정 후의 기존 경로는 12초 WAV 구간 → 서버 STT → 원문 누적/저장 → 연결된
텍스트 LLM의 잠정 요약(30초 간격 점검) → 종료 후 최종 요약이다.
Gemma4/Qwen3.6은 등록된 텍스트 모델로서 요약·결정·할 일 정리를 담당한다.
모델 이름만으로 STT 가능 여부를 추정하지 않는다.

요약 프롬프트는 기본 한국어이며, 사용자가 다른 언어를 요청할 수 있게 되어 있다.
즉 외국어 원문의 한국어 요약은 모델 연결·역량에 따라 가능하지만,
전체 문장 대응 번역이나 실시간 번역 자막 UI는 별도 구현되지 않았다.
실제 STT endpoint 및 회사 LLM의 연결 성공/품질을 이번에 검증하지 않았다.

확장 경로는 사용자가 선택한 회의 탭/시스템 오디오를 `getDisplayMedia`로 받아
기존 STT/요약 파이프라인에 연결하는 것이다. 브라우저·OS마다 오디오 지원이 다르고,
사용자가 매번 소스 선택과 공유 승인을 해야 한다. 설정 힌트만으로 오디오 트랙의
존재를 보장할 수 없으므로 무음/트랙 없음·공유 중지·마이크 혼합·이중 녹음 방지
등의 처리가 필요하다. 브라우저가 회의 시작을 알아서 탐지하여 무단으로 계속
녹음하는 기능과는 구별해야 한다. 녹음/전사 동의 및 승인된 처리 서버 범위도 유지한다.

[MDN getDisplayMedia — 권한·오디오 트랙 제한](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia).

이번 변경에서는 실제 마이크/시스템 음성을 수집하거나 외부 STT/LLM에 보내지 않았다.
회의 앱 캡처와 번역 기능은 설계 검토만 했으며 구현 완료로 표시하지 않는다.
10322 프런트엔드는 저장 후 새로고침으로 적용한다. AGENTS/SBE/API 계약·서비스 설정·
기존 immutable receipt는 변경하지 않았고 전체 goal 완료를 선언하지 않는다.
