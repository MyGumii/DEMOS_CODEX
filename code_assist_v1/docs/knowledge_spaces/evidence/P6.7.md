## Review and authority boundary

- The management candidate surface is the review queue. Summary rows contain
  finding kind/status, risk, severity, visibility, and reviewer requirement;
  they contain no source body.
- Finding detail performs a fresh `CURATE` authorization check and returns
  detector/rule/model versions, fixed revision IDs, evidence hashes/codes,
  proposed-action evidence, and review lifecycle. Foreign or stale authority is
  nondisclosing.
- Pending human-reviewable findings expose approve, reject, and ignore with a
  required reason. Reviewed, rejected, ignored, and obsolete findings expose no
  repeat action control.
- Proposal and merge preview/rebase/apply routes bind exact row/revision
  versions. Source and target lease tokens/fences use separate named headers;
  secret tokens never appear in request or response JSON.
- `CurationReviewFacade` is dependency-only. It owns no authorization or
  transaction and only delegates to the finding, proposal, merge, and metric
  services.
- The canonical curation route group is absent unless a curation facade is
  explicitly bound and a personal- or part-write rollout is enabled. Default
  and read-only compositions register no curation routes.

## Shadow/proposal-only evidence

- `CurationMetricsRepository` derives counts in a read transaction from the
  immutable finding ledger. The service requires current `CURATE` authority.
- The deterministic sample is ID-ordered, body-free, and bounded to 1..100.
  It includes only model proposals with a recorded human adjudication; obsolete
  proposals are counted separately and excluded from precision.
- Accepted precision outcomes are approved/applied/apply-failed; rejected and
  ignored remain explicit denominator outcomes. A zero denominator reports
  `precision_ppm=null` rather than inventing a score.
- The report separately counts all model automatic effects, risky semantic/
  merge/replace/deactivate/purge effects, and T3 effects. `report_status=pass`
  requires every one of these counts to equal zero.
- No detector/model execution or domain action surface was added. The mode is
  exactly `shadow_proposal_only`.
