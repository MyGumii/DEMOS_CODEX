# P5.5 lease editor UI evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P5.5 passes its tested canonical lease-route and browser-editor implementation
gate behind disabled write traffic. The existing P5.1/P5.2 transaction-owned
lease/save services are now exposed through an optional five-route surface,
and the canonical browser implements one exclusive editor session with
heartbeat, completion, cancel/release, conflict draft recovery, and audited
force-release confirmation.

This is not a rollout. Production feature-flag parsing still rejects canonical
writes, no live database or source/blob root was opened, no production HMAC key
provider was configured, and no worker, web service, personal write, or part
write was enabled. P2.8 remains separately dependent on operator-approved
rehearsal inputs.

## Frozen route and browser contract

- `register_canonical_routes(..., item_edit_service=None)` retains the exact
  21-route read surface. Supplying a service that exposes all five editing
  methods atomically adds only item PUT plus acquire, heartbeat, release, and
  force-release POST routes. Partial services fail registration.
- The authenticated server principal is converted to `SessionPrincipal`; no
  actor, role, or epoch is accepted from client JSON. All mutation queries and
  JSON shapes are exact and duplicate members remain rejected by the shared
  parser.
- Acquire binds body operation/editor-session IDs to a client-generated
  43-character canonical base64url token carried only in
  `X-Knowledge-Lease-Token`. Heartbeat binds editor session and lease ID plus
  token/fence headers and remains the sole non-idempotency-keyed mutation.
- Release binds operation, session, lease, token, and fence. Save additionally
  binds expected row version/revision, Markdown, and reason; optional
  `If-Match` must be the quoted exact expected revision. Force release requires
  operation, bounded reason, and exact `FORCE_RELEASE` confirmation before the
  service revalidates leader/administrator capability and audits the result.
- Lease service errors retain only their already-sanitized holder/expiry and
  draft-recovery details. Raw token and local draft are absent from responses,
  errors, request metadata, command repr, public browser state, and browser
  events.
- The transport generates exactly 32 random bytes with
  `crypto.getRandomValues`, base64url-encodes them without padding, sends token
  and fence only in dedicated headers, and validates exact response shapes and
  request/result identities.
- The browser owns at most one in-memory active editor. After acquire it reads
  the item again and requires the current revision to equal the lease base; a
  mismatch is released and rejected before editing. It heartbeats every 30
  seconds and stops heartbeat on completion, conflict, cancel, or leave.
- A foreign lock is read-only and shows holder, last heartbeat, and expiry.
  Completion creates one immutable revision and releases through P5.2. Cancel
  offers copy-and-release or discard-and-release. A rejected save keeps the
  draft and exposes exactly view-current, copy-draft, and
  reacquire-and-compare; no force overwrite exists.
- Page-leave release is best effort only. Canonical expiry and monotonically
  increasing fencing remain authoritative if the browser disappears.
- The force-release control appears only with the returned capability and a
  live lock, and requires both a reason and typed exact confirmation.

does not itself re-prove or claim the aggregate P5 two-process/40-client gate,
enable any write flag, configure production secrets, or touch live state. P5.6
owns permanent purge. P5.7 owns actual web-process lifecycle races, aggregate
lease results, and the final P5 gate. P6/P7 still own curation, workers,
projections, recovery, and production operations; P8 plus explicit approval
owns activation.
