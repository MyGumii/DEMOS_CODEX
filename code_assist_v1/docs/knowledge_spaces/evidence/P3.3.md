# P3.3 one-space canonical FTS retrieval evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P3.3 passes its inert canonical retrieval repository/service boundary. Every
query resolves exactly one currently authorized personal or current-part space
inside the same read snapshot as FTS. Only current active/published revisions
from that space can become hits; relevant graph neighbors and recent events are
bounded to the returned same-space item set.

This evidence closes only the P3.3 implementation task. It does **not** register
HTTP/SSE routes, assemble an Agent prompt, revalidate P3.2 live context during a
turn, remove live legacy retrieval, change a feature flag, or claim the P3/G-07
gate. P3.4-P3.7 retain those responsibilities.

## Frozen behavior

- Conversation retrieval accepts no `space_id`; it derives the immutable space
  from an owned active conversation. Management retrieval accepts exactly one
  requested space and resolves it through the canonical scope resolver.
- Actor status, scope epoch, current personal/part authority, conversation scope,
  and read capability are checked inside the same `DEFERRED` snapshot as search.
  A moved part, foreign space, archived conversation, or disabled rollout fails
  before a result is returned.
- User text is NFKC-normalized, length/term bounded, control-free, and compiled
  only as quoted FTS literals. Caller FTS operators cannot alter query structure.
- FTS is joined to `search_document`, item, current revision, and body. Exact
  space, active/published visibility, current-revision identity, title, and
  inline-body equality are rechecked; a deliberately stale FTS body returns no
  canonical hit.
- Hits and semantic-neighbor excerpts are bounded and labelled
  `untrusted_reference`. No system instruction, raw audit details, growing
  index/log projection, external file, or vector cache is read.
- Semantic neighbors require one active edge and two current active/published
  endpoints in the exact authorized space. Recent events are selected only for
  the returned hit/neighbor item IDs and revision references are item-bound.
- Missing, building, lagging, or errored Markdown projection state is surfaced
  as `canonical_fallback_used`; retrieval remains on transactional DB FTS and
  never falls back across spaces or to stale files.

## Residual ownership

compose the bounded untrusted references into the Agent boundary, and remove the
parallel legacy KB/SB path. P3.5-P3.7 own read compatibility adapters, scope UI,
API/Agent canaries, session regression, and final traffic cutover. Until those
gates pass, legacy Flask chat/session routes remain authoritative and all
Knowledge Core traffic/write flags remain fail-closed.
