# P2.5 conversation and operational-state importer evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P2.5 passes its isolated reviewed-plan-bound conversation, job-history, and
Notion session-link boundary. The production apply service accounts for every
reviewed P2.5 import effect and commits each canonical effect with an immutable
checkpoint, audit event, and outbox event.

This evidence does **not** claim that a production snapshot was migrated. It
does not claim P2.6 observed one-of-five verification or projection rebuild,
P2.7 dirty/large fault scenarios, P2.8 frozen rehearsal, any
`MIG-001..008` completion, traffic cutover, worker startup, or enabled
personal/part reads or writes.

## Frozen implementation boundary

- Physical schema v6 preserves v1-v5, adds nullable canonical conversation,
  message, summary, and context-binding targets to the immutable record ledger,
  and adds an immutable Notion session-page relationship ledger.
- Exact reviewed session JSON is duplicate-key rejected and reconciled against
  the P2.1 child counts, per-kind aggregate hashes, logical hash, ordinals, and
  payload hashes. Core metadata, messages, metadata, compact summaries, uploads,
  and bindings are each represented exactly once before the physical session
  parent can close its dependency set.
- Conversations are always bound to the reviewed user's personal space.
  Messages and summaries become canonical rows; remaining legacy child evidence
  is preserved in canonical conversation migration metadata and each logical
  child receives an immutable target-verified checkpoint.
- Terminal job records and queued/running records are stored only as labelled,
  content-addressed historical artifacts. Queued/running records use the
  `abandoned_legacy_job` mode. No legacy job creates, claims, or executes a
  `durable_job`.
- The Notion adapter never imports or maps the retained external database. It
  copies the exact reviewed main/WAL/SHM/journal component set to
  migration-owned scratch, then recomputes quick/FK checks, the exact anchor
  schema, user version, schema/table counts and hashes, every raw row hash, and
  every logical child hash. Only same-owner resolved session-page links create
  canonical live bindings plus immutable record and relationship checkpoints.
- Source reads, JSON parsing, blob staging, and SQLite snapshot verification
  happen outside canonical write transactions. Each bounded service-owned
  transaction revalidates account/personal-space and target state, then commits
  effect, checkpoint, audit, and outbox together. Exact replay creates no new
  effect; failpoints leave no partial binding, mapping, audit, outbox, or scratch
  copy.
- The public `migrate apply --resume` boundary reports explicit P2.5 batch and
  aggregate counts without emitting raw session/job content. Unsupported P2.5
  records or relationships fail before execution.
