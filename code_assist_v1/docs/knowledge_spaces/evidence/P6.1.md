## Frozen deterministic policy

- The rule and LF-only normalizer are exact public constants:
  `p6.1-deterministic-ingest-v1` and `markdown_lf_v1`.
- A fingerprint binds target space, source-identity SHA, exact UTF-8 content
  SHA/size, LF-normalized SHA, normalizer, and optional canonical item/revision
  IDs. Evidence and metrics contain hashes/IDs/counts only, never Markdown.
- Same source identity plus exact bytes is `no_op`. Same source identity with
  changed bytes is `source_update_candidate`; it is not overwritten or
  deduplicated.
- A different source with the exact tuple in the same concrete space is
  `exact_repeat` and may add provenance only. Multiple current exact/source
  matches fail closed as corpus corruption rather than choosing a winner.
- LF-normalized-only equality is `normalized_candidate`, with no automatic
  effect. Exact bytes found only in another space remain `new` for the target
  and are merely recorded as cross-space candidate evidence. Automatic merge
  count is structurally fixed to zero.
- Production publication remains the effect boundary: same-space exact bodies
  add an `item_source` provenance row without generation/revision duplication;
  normalized-only inputs create distinct items; personal+part exact content
  remains two independent item/revision histories.
- Publication previews/audit and created/update/aggregate outbox evidence bind
  the deterministic rule version. A pending preview from an older rule is not
  silently reinterpreted; it must be re-previewed under the current version.
- The original blockers/errors remain: empty Markdown, unsafe controls,
  unterminated leading front matter, and unterminated code fences. P6.1 adds
  bounded warning-only first-occurrence evidence for duplicate H1, heading
  level jumps, and lines longer than 4,096 characters. Headings inside leading
  YAML or fenced code are ignored.
- Dedup and lint corpus metrics are order-independent, exact-keyed, body-free,
  and hash-sealed. Public decision DTOs are independently revalidated; a forged
  effect, target, candidate set, rule version, or evidence hash is rejected.
