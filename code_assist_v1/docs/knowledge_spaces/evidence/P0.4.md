## Gate behavior proved

- The CLI requires explicit existing paths, imports no application config/store,
  creates no database/schema/directory, emits one canonical JSON line, and
  sanitizes malformed and unexpected failures.
- Production accepts only SQLite 3.53.4 plus the exact source ID in
  `SCHEMA_V1.md`. Compile-option and executable FTS5 checks, JSON execution,
  required connection pragmas, WAL, database identity, `quick_check`, and
  foreign-key integrity are separately gated.
- Current SQLite 3.50.4 produces exactly two warnings and exit 0 in development;
  the same facts produce exit 2 in production.
- Explicit UNC paths are rejected before any filesystem/SMB access. Final Win32
  targets must be fixed local NTFS. Reparse components remain visible, and
  mapped remote, removable, ReFS, FAT, incomplete, and unavailable probes fail.
- Final resolved targets drive layout checks. A directory equal to its volume
  root, a DB under blob/projection, or overlapping blob/projection roots fails
  before any write or SQLite probe, including junction aliases.
- The directory probe creates one unpredictable exclusive file, flushes it,
  removes it, and checks only its own residue so concurrent legitimate files do
  not cause false failure.
- Runtime-lock pins are hashed and compared canonically; missing, mismatched, or
  ambiguous duplicate installed distributions cannot pass production.
- All seven rollout flags default to zero and accept only `0`/`1`. Higher spaces
  remain disabled. `KNOWLEDGE_CORE_PART_WRITES=1` is always refused in P0.4,
  even when a record file exists, because the P1–P7 evidence verifier does not
  yet exist. Failpoint names cause failure without exposing values.
- Node is a reported verified-baseline fact, not an invented production runtime
  pin. Unicode paths are JSON escaped so redirected Windows code pages cannot
  break the one-line output contract.
- The PowerShell adapter changes to the trusted workspace, invokes the exact venv
  interpreter with `-E`, forwards every explicit argument, and propagates the
  child exit code. An injected `PYTHONPATH` test cannot hijack module resolution.

## Current-host PowerShell limitation

During preflight development, Windows Application Event ID 1000 attributed
intermittent host exits `0xc0000409` to the endpoint-injected module
`C:\Windows\Teruten\TCube\TModule64.dll` 1.0.0.5 in `powershell.exe`; no
`python.exe` fault was recorded. Direct Python/Win32 stress remained clean.

A preliminary wrapper batch on this workstation is deliberately not accepted as
gate evidence: 60 attempts produced 46 expected results, five shorter failure
reports whose exact reason arrays were not retained, and nine native PowerShell
host crashes. A Start-Process/redirection variant still crashed 5/20, confirming
that retry or output-pipeline changes would only hide the host defect. The code
therefore has no retry/skip workaround. P7 must repeat the checked wrapper and
production service preflight on the target GPU server before deployment.
