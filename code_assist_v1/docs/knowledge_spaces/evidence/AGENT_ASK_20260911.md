## Failure and repair

The canonical executor returns answer text in `assistant_content.text` and
citation/model metadata in `final_response`. The previous integration adapter
returned only `final_response`, on both initial completion and replay. A
`state=completed` result therefore did not deliver the generated answer to Hermes.
Earlier integration checks asserted status and replay equality without checking
the answer body; their success was insufficient evidence for Ask delivery.

Adding `assert answer["answer"] == "Fixture answer"` to AIK-015 reproduced the
defect before the repair: **1 failed in 4.39s**, `KeyError: 'answer'`. The same
focused canonical test passed after the repair: **1 passed in 4.58s**.

The adapter now returns top-level `answer` from the committed turn's exact
assistant message, read through existing authorized conversation services.
`response` preserves canonical metadata. Both first delivery and replay use the
same stored result, including pre-fix completed turns with no answer in metadata.
Later messages in the same conversation cannot substitute for the original.
No canonical or ledger schema change, migration or historical-message rewrite
is required.

Failed/cancelled turns have a null answer, with the original error when present.
A completed record whose body cannot be read returns `503 ANSWER_UNAVAILABLE`;
delivery failure does not terminate or overwrite a committed successful turn.
Grant and selected-Wiki authorization are rechecked before delivering text.
