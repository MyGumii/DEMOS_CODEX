# P1.8 administrator organization UI evidence

Date: 2026-08-13 (Asia/Seoul)

## Result

P1.8 passes its isolated administrator UI boundary. The existing account-
administration entry now renders the canonical 담당→team→part tree and the
canonical users read model, builds every organization/account mutation from
server-issued snapshot or preview fences, and fails closed when the explicitly
injected P1.5 adapter is unavailable or its response violates the contract.

This evidence does not claim live-host route registration, canonical traffic
cutover, a live migration, team/responsibility publishing, personal/part read
rollout, or personal/part writes.

## Implemented UI contract

- `GET /api/admin/v1/org/tree` supplies one DEFERRED-snapshot hierarchy and an
  ID-sorted canonical user list. The browser accepts only the documented fields
  and cross-checks active leaders against the canonical user/part mirror.
- Create team/part, rename, move, inactivate, membership assign/move/unassign,
  leader replacement, and reasoned account disable/re-enable use exactly the
  nine P1.5 routes. No purge or team/responsibility publication control exists.
- Move is preview→impact display→three explicit retain acknowledgements→apply.
  Inactivation requires an explicit destination or explicit unassignment for
  every member and uses only the preview's user-version, leader-assignment, and
  space-version fences.
- Each mutation sends the same canonical UUID in body `operation_id` and
  `Idempotency-Key`. A response-less or explicitly retryable failure preserves
  the exact original body, transport, and operation ID. The UI exposes a
  recovery action and never invents a replacement operation for an unknown
  outcome. A validated success clears it and fully refreshes the canonical
  tree; every 409 also refreshes before the next intent.
- A 2xx body is accepted only when its request/operation correlation and exact
  MutationResponse fields are valid. Malformed, torn, injected, oversized, or
  mismatched tree/preview/result data fails closed.
- If the canonical adapter or snapshot is unavailable, all organization,
  membership, leader, account-status, and pending canonical mutation buttons
  are disabled. Retained login-data utilities are inline and isolated: no
  legacy status/role/delete fallback exists, and compatibility account creation
  is forced to `role=user`.
- Personal credentials and credential-policy fields are never rendered. All
  server/user strings are escaped, and the new surface contains no hard delete
  or publication action.

## Deliberate non-cutover boundary

- `register_admin_routes` remains explicitly injectable and absent from all
  default/live host composition. The UI therefore shows its fail-closed state
  until a later reviewed cutover provides that adapter.
- No canonical or legacy data was created, migrated, or mutated. No production
  service was started, and no feature flag or rollout setting changed.
- Higher spaces remain future-only. Personal/part writes and Agent traffic
  remain disabled; P1.9 owns only the minimal durable work kernel.
