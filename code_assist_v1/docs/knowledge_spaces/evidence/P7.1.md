# P7.1 durable job/claim service evidence

Date: 2026-08-15 (Asia/Seoul)

## Result

P7.1 passes its P0.2-isolated, disabled-worker/traffic implementation boundary.
The P1.9 durable repository and exact-version kernel remain the sole canonical
job authority; P7.1 adds the missing actor-authorized generic status and
idempotent cancellation service, strict route composition, and browser
transport. No worker loop, model process, projection materializer, feature
flag, route traffic, or service process was started.

This is not the aggregate P7 or `G-10` gate. P7.2 still owns central worker
polling/heartbeat, GPU concurrency/fairness, and removal of production
web-process model ownership. P7.3-P7.9 retain projections, backup/preflight,
Windows service packaging, health, randomized faults, target-class performance,
and restore.

## Durable authority retained from P1.9

- `JobRepository` persists only durable input references and hashes, captured
  authorization/expected-state facts, exact `(job_type, handler_version)`,
  stable effect key, claim lease/owner, attempt fence, and terminal result/error.
  It accepts writes only inside a managed transaction.
- `HandlerRegistry` is immutable and exact-versioned. Its callables implement a
  reviewed handler version; they are not queued process-memory authority.
- Every worker mutation repeats the live claim owner, attempt count, expiry,
  state, and cancellation fence. Expired claimed/running work recovers through
  retry/dead or cooperative cancellation without ABA reuse.
- Handler preparation remains outside the write transaction. Immediately before
  the effect, the kernel revalidates current actor/scope/capability and the
  handler's expected canonical state. The domain effect and stable `succeeded`
  result commit in one transaction; response loss returns the same result.
- Permanent fresh-process tests retain the authoritative `JOB-001..006` owners:
  enqueue hard-exit durability, expired claim recovery, stale-fence rejection,
  effect/ack crash replay, same-row multiprocess claim competition, account
  disable and membership-move rejection, and cancellation convergence.

## Public actor service

- `DurableJobService.read` opens a read-only transaction, requires a current
  active `SessionPrincipal`, validates the stored row through `JobRepository`,
  and returns only a user job whose canonical actor is the current user.
  Foreign, system, and missing rows all return nondisclosing `NOT_FOUND`.
- `cancel` owns one transaction and binds the actor, captured epoch, exact job,
  operation type, and caller operation ID into the dedup request hash. Reuse
  with changed input fails `IDEMPOTENCY_CONFLICT`; exact committed replay
  returns the prior resource/status with the current request ID.
- Queued/retry jobs become terminal `cancelled`. Claimed/running jobs set the
  cooperative `cancel_requested` fence and remain for the current worker to
  acknowledge. Non-cancellable jobs fail `STATE_CONFLICT` without a durable
  dedup/audit row.
- Job state, one sanitized audit event, and the operation result commit or roll
  back together. Failpoints after state change, audit, and operation-result
  commit each prove zero partial effect. Audit request metadata uses a closed
  allowlist and drops token/authorization/secret-bearing values.

## Route and browser boundary

- `ServiceRegistry.jobs` is optional. Generic job routes do not exist until an
  explicit service is injected. GET may then be registered under the disabled
  read-capable composition; POST cancel additionally requires a write-capable
  disabled rollout. Hosts with existing writes but no job service retain their
  prior route groups.
- `GET /api/knowledge/v1/jobs/{job_id}` derives actor identity and epoch only
  from the server principal, emits the exact `JobResponse` shape, and exposes no
  durable input, effect key, authorization snapshot, claim owner, or actor ID.
- `POST .../{job_id}/cancel` accepts exactly `operation_id`, binds an optional
  identical `Idempotency-Key`, and maps only the frozen public error vocabulary.
- `knowledge_core_transport.js` validates exact keys, identity/status URL,
  job-state vocabulary, attempt/progress domains, terminal/nonterminal null
  shape, result/error shape, and cancel operation/resource binding. It supplies
  CSRF/idempotency headers and never supplies actor identity.

## Safety and deliberate limits

- No live `.runtime`, `knowledge`, `user_data`, Notion DB, projection, feature
  flag, route traffic, service process, migration state, or worker was read or
  changed. Tests used only P0.2-isolated roots under `D:\CodexTestTemp`.
- System jobs are intentionally absent from the user API. Internal operational
  observation remains P7.6/admin authority, not a user ownership bypass.
- P7.1 introduces no scheduler loop, claim heartbeat thread, model execution,
  cross-job GPU serialization/fairness, queue SLO, or production deployment.
- The existing local PowerShell host can terminate with `0xc0000409` or an
  invalid stdout handle when running larger buffered pytest selections. Only
  independently captured exit-0 runs are evidence; host failures are not
  counted as passing or failing tests and remain a target-server P7.5/P7.7 gate.
