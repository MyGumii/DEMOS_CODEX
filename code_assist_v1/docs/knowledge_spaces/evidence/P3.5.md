# P3.5 read-only legacy response compatibility evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P3.5 passes its disabled read-compatibility implementation boundary. Existing
knowledge and Second Brain read shapes can be produced from canonical SQLite
state without opening a legacy store, refreshing a projection, or accepting a
legacy `uid` as authority.

This evidence does **not** register or change an HTTP route, change a feature
flag, start a worker, access live data, or claim the P3/G-07 gate. Existing
Flask routes remain authoritative until the P3.7 route/canary/traffic gate.

## Frozen behavior

- Each operation opens one read-only `DEFERRED` snapshot and resolves the
  authenticated actor's current personal space through `ScopeResolver`. A
  current scope epoch and personal-read capability are mandatory.
- `legacy_user_id` is control-free bounded compatibility text only. It is not
  normalized, compared with the actor, interpolated into SQL, or used to select
  a directory, database, store, space, item, graph, or finding.
- Legacy list/view/search and thought response keys are preserved while
  canonical UUID item IDs act as opaque filenames. Active published,
  provisional, and quarantined items are visible to management compatibility
  reads; the Agent path remains the separate published-only P3.3 service.
- Current item/revision/body identity, SHA-256, byte size, inline/blob storage,
  optional search-document identity, title, and body are exact checked. A
  blob-backed body without its canonical search document and any stale or
  forged search evidence fail closed.
- FTS text is NFKC-normalized, bounded, and compiled as literal terms. Every
  query is restricted to the resolved personal `space_id`; FTS operators and a
  forged legacy UID cannot reveal another personal or part-space canary.
- Graph nodes are current active items in the same personal space. Returned
  edges are active, same-space, have active endpoints, and use the frozen edge
  vocabulary. Focus/depth/filter evaluation occurs only over this bounded
  canonical set.
- Candidate/inbox responses read `curation_finding` and immutable revision
  joins. They do not read `pending_diffs` or legacy files. Evidence and proposed
  action remain canonical JSON, while raw content fields remain empty.
- Generated `index.md` and `log.md` compatibility documents are bounded
  database views. They never create, open, invalidate, or refresh a projection
  file. The module contains no write SQL.
- Caller result limits truncate within independent hard ceilings of 500 items,
  2,000 edges, 500 findings, 20 FTS results, 32 KiB returned content, 500 query
  characters, and 32 query terms. Invalid types, controls, stale scope,
  disabled reads, malformed metadata, and oversized canonical sets fail closed.

change creates a new immutable conversation. P3.7 owns route integration,
end-to-end API/Agent canaries, reconnect/session regression, and actual
