# P1.2 connection factory and single migrator evidence

Date: 2026-08-12 (Asia/Seoul)

## Result

P1.2 passes. Knowledge Core now has an explicit-path SQLite connection factory,
opaque managed connection boundary, transaction owner, immutable migration
catalog, reviewed physical-schema fingerprint contract, and one deployment-only
migrator. This evidence validates infrastructure against synthetic fixture
schemas only. It does not claim the physical v1 schema, a live migration,
repository behavior, canonical routes, workers, projections, or traffic cutover.

## Implemented boundary

- SQLite 3.53.4 and its exact source ID are the single production allowlist
  shared with runtime preflight. The current workstation's SQLite 3.50.4 stays
  blocked for production.
- Every managed connection verifies foreign keys, 10-second busy timeout,
  synchronous FULL, trusted schema off, recursive triggers, memory temp store,
  WAL mode, zero automatic checkpointing, and
  `SQLITE_DBCONFIG_NO_CKPT_ON_CLOSE=1`.
- `ManagedConnection` and `ManagedCursor` expose no raw connection through the
  public API. Commit, rollback, manual transaction SQL, replacement authorizer,
  writable blobs, backup destination, deserialize, extension loading, and
  mutable DB config fail closed.
- Public DML is authorized only inside the owner `BEGIN IMMEDIATE` transaction;
  the migrator alone uses `BEGIN EXCLUSIVE`. Statement caching is disabled so
  prepared authorization cannot cross a state boundary. Failed `execute` and
  `executemany` calls reconcile SQLite-initiated rollback before any caller can
  continue, and every context exit clears authority while preserving the
  original exception.
- Ordinary opens require an existing absolute canonical file, reject aliases
  and hard links, recheck device/file identity before commit, never create or
  migrate, and validate the complete ledger prefix plus physical schema hash.
- Migration catalogs are immutable, contiguous, normalized, and checksummed.
  Every version carries a precomputed cumulative `sqlite_schema` SHA-256; an
  ordinary open compares it without replaying migrations or running a shadow
  schema.
- The single migrator preflights runtime/JSON/FTS before target creation,
  establishes WAL, applies all pending versions atomically, protects immutable
  ledger history, executes read-only postconditions, sets `user_version`, checks
  foreign keys/integrity, commits, and proves an ordinary reopen. A repeat run
  applies zero versions.
- P0.4's SQLite observer now uses `mode=ro`, enables no-checkpoint-on-close before
  probing, and proves the live WAL bytes remain unchanged.

## Trust and phase boundary

The public connection/repository/HTTP boundary is the enforcement boundary.
Application DB and migration modules are trusted in-process code; Python
private-name reflection is not treated as a sandbox or hostile plugin boundary.
No Knowledge Core route is registered yet, so neither users nor HTTP requests
can invoke the factory or migrator.

The test-runtime path is not a production switch. It is revalidated on every
open, requires exact `CODE_ASSIST_TEST_MODE=1`, imports the P0.2 path guard, and
accepts only the current per-process isolated test root. Tests used a small
parent/child fixture schema, not `SCHEMA_V1.md`; P1.3 owns every physical
`SCHEMA-001..008` claim and the production fingerprint generated on the exact
approved runtime.
