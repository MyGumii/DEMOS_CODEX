# P5.4 activity and version UI evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P5.4 passes its tested activity/version read and browser-UI implementation gate
behind disabled canonical traffic. One authorized space now exposes current
item detail, immutable revision list/detail, bounded deterministic comparison,
and sanitized audit projection. The browser renders the required state, ages,
editor, reason, inactive context, impacts, history, and diff through canonical
transport only.

This is not a rollout. No edit/deactivate/restore route was added, no feature
flag was enabled, no live database/blob root/source tree was opened, no worker
or web process was started, and no personal/part write traffic was authorized.
P2.8 remains separately dependent on operator-approved rehearsal inputs.

## Frozen read and UI contract

- `ItemHistoryRepository` requires an active caller-owned read transaction and
  exact space/item binding. It returns the current revision, or the latest
  metadata anchor for a purged tombstone, and rejects cross-space/malformed or
  incoherent lifecycle/revision/body rows.
- Detail includes item lifecycle/curation/current revision/row version, current
  title and retained Markdown, item-specific capabilities, token-free live
  lease holder display/ID/heartbeat/expiry/fence, active/inactive edge and
  deterministic-reference counts, conversation pins, and the latest human
  review time.
- An inactive detail requires one open latest episode and its exact immutable
  deactivation audit projection. It exposes actor ID/display snapshot, reason,
  time, elapsed inactive duration, and exact manual-purge eligibility. Content
  age, review age, and inactive duration remain separate values.
- Revision list ordering and cursors bind `(revision_no DESC, revision_id
  DESC)`. List rows contain metadata only. Detail binds item, parent/base,
  title, change kind/reason, editor ID/display, raw and normalized hashes,
  normalizer, size, body presence, and creation time.
- Inline Markdown is byte-size/SHA-256 verified in the snapshot. Blob-backed
  bytes are loaded through an injected provider outside the transaction,
  checked as strict UTF-8 with exact size/SHA-256, then scope and immutable DB
  evidence are re-read. No live blob provider is configured by P5.4.
- Compare accepts exact same-item UUID endpoints, caps each body at 2,000,000
  characters and 20,000 lines and output at 2,000,000 characters, and returns
  deterministic `unified-v1` structured hunks plus canonical SHA-256. It emits
  no HTML.
- Activity exposes only actor snapshot, action/outcome, item/revision IDs,
  time, reason, and space. Raw audit details, request metadata, credentials,
  and tokens are neither queried into the DTO nor serialized.
- The canonical route group is now 21 routes. The four P5.4 GET routes reject
  duplicate/extra query fields, malformed UUIDs, wrong cursor kinds, and
  cross-space items. Server principal and current scope remain authoritative.
- Browser transport exposes `getItem`, `listRevisions`, `getRevision`, and
  `compareRevisions`. UI uses `textContent` only, binds item clicks to the
  exact space/item, shows all P5.4 fields, and renders historical body/diff
  without `innerHTML` or legacy fallback.
