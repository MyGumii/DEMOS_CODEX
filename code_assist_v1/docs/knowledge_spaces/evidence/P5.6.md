# P5.6 administrator purge and blob-GC evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P5.6 passes its administrator-only purge and asynchronous blob-GC
implementation gate behind disabled canonical traffic. The implementation
provides exact manual preview/command and purge-eligible queue boundaries,
retains tombstone/hash/provenance/audit metadata, removes only eligible body
links and FTS state atomically, and quarantines only blobs with zero remaining
canonical references. Forward schema v7 closes reference and active-backup
races around physical deletion.

This is not a rollout. No feature flag, live database/root, production HMAC
key, scheduler, worker, backup, service, personal write, part write, or traffic
was enabled. P5.7 still owns real two-web-process/40-client lifecycle load and
the aggregate P5 gate; P7 owns worker scheduling and production backup/recovery.

## Frozen behavior

- Preview and execution read the canonical active administrator and captured
  scope epoch; no client role or authority assertion is accepted.
- Preview uses SQLite time and the latest open deactivation episode. It binds
  item/space/row version, exact state hash, eligibility, actor epoch, expiry,
  and literal `PURGE <item_id>` confirmation into a short-lived HMAC token.
- Execution requires that token, the exact confirmation, expected row version,
  and caller operation ID. It repeats authorization, DB-time eligibility,
  references, and state-hash checks inside one owned `IMMEDIATE` transaction.
- A successful purge retains item/revision/source/lineage/hash/provenance/audit
  metadata, changes the item to `purged_tombstone`, closes the episode, removes
  FTS and every revision body, and removes artifact/extraction bodies only when
  no surviving item, ready preview, context binding, proposal, or backup hold
  needs them. Audit, outbox, generation, and blob candidates commit together.
- The administrator queue is bounded to 100 rows, uses a signed endpoint-domain
  keyset cursor over `(purge_eligible_at,item_id)`, includes blocked time-eligible
  items and exact blocker counts, and is absent unless explicitly registered.
- No automatic purge exists. Newly unreferenced verified blobs enter a further
  24-hour quarantined candidate state. `BlobGcService.run_once` claims one row
  in a short transaction, performs I/O outside SQLite, then finalizes briefly.
- The Windows storage provider revalidates the approved local storage layout,
  pins the CAS directory chain, opens without following a reparse point,
  requires the exact canonical path, byte size, streamed SHA-256, and one hard
  link, and deletes through the verified handle. It never uses path unlink.
- Schema v7 adds four body/proposal insertion fences, candidate-insert and
  claim/finalize guards, and a backup-start fence. A new canonical reference or
  active preparing/copying backup makes deletion fail closed.
- Purge remains possible for an otherwise valid inactive item in a frozen
  space; freezing writes cannot make retained data permanently unpurgeable.
  Stored edge rows remain unchanged and purged tombstones cannot be restored.
