# P4.1 artifact/blob/extraction boundary evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P4.1 passes its disabled implementation boundary. Non-legacy upload, Notion,
chat, and manual sources can now preserve raw content-addressed blob evidence
and exactly one immutable ready or failed extraction snapshot without creating
knowledge. Raw source bytes, extracted Markdown, normalized evidence, lint, and
the later editable revision remain distinct facts.

This evidence does **not** expose a publication route, create a preview/job,
authorize a target, create an item/revision, enable part writes, start a worker,
change a feature flag, access live data, or claim any `PUB-*` scenario.

## Frozen preparation contract

- `prepare_publication_artifact()` is a pure pre-transaction function. It takes
  exact raw bytes and already completed extractor output; it has no database,
  filesystem, network, application-config, or model access.
- Exactly one ready Markdown result or stable failure code is required. Ready
  evidence includes exact UTF-8 size/SHA-256 and the separately computed
  `markdown_lf_v1` SHA-256. Failed evidence contains no body, extracted hash,
  size, normalized hash, or normalizer claim.
- The closed P4.1 T0 lint reports only empty Markdown, unsafe ASCII controls,
  unterminated leading front matter, and unterminated fenced code. It is
  deterministic, body-free, and makes no semantic duplicate/conflict claim.
- Warnings are sorted unique safe codes. A canonical preparation SHA binds
  raw size/hash, extraction status/version/hashes/body reference, warnings, and
  lint evidence without copying raw content into metadata.
- The bundle builder accepts a staged raw observation only when its hash/size
  equal the prepared raw bytes and emits exact publisher and source-evidence
  metadata shapes.

## Frozen repository contract

- `ArtifactRepository.put_source_bundle()` requires an existing managed write
  transaction and accepts only `upload|notion|chat|manual`.
- It inserts or exactly verifies one `blob_object`, `source_artifact`, raw
  `artifact_blob`/body, and one `extraction_snapshot`; only a ready snapshot has
  an extraction body. It writes no `knowledge_item` or `knowledge_revision`.
- Before the first write it validates the publisher, canonical UUIDs and CAS
  path, metadata/owner exact key sets, warning vocabulary, ready/failed shape,
  inline exact bytes/hash/size, LF-normalized hash, publishability, and the full
  preparation hash.
- Existing CAS bytes may deduplicate by exact hash/size/path. Partial rows,
  identity collisions, changed source/extraction evidence, body/hash forgery,
  arbitrary nested metadata, unsafe warning text, or missing publisher fail
  closed. Exact replay is read-equivalent and adds no row.
- The repository performs no filesystem I/O and does not own commit/rollback.
  P4.2 must invoke it only inside its service-owned transaction after physical
  staging/verification and must let unexpected storage failures roll back.
