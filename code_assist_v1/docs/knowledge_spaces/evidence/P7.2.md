# P7.2 central inference coordination evidence

Date: 2026-08-15 (Asia/Seoul)

## Result

P7.2 passes its P0.2-isolated, disabled-worker/traffic implementation boundary.
Canonical web producers persist durable input references, while an explicit
central service owns recovery, polling, heartbeat, one-job execution, and
handler/actor fairness. Production web processes cannot own local GGUF or the
historical in-process background-job scheduler. No worker, model, route traffic,
feature flag, service process, live root, or live database was started, enabled,
or accessed.

This is not the aggregate P7, `G-10`, `G-11`, performance, or deployment gate.
P7.3 still owns outbox projection materialization; P7.4-P7.9 retain backup,
production packaging, health, randomized faults, target-class load, and restore.

## Central worker contract

- `DurableInferenceWorker` starts nothing at import or construction. Explicit
  `run_once()` executes at most one row; explicit `serve(stop)` holds ownership
  for the service lifetime and applies bounded stop-aware exponential idle
  backoff.
- Startup verifies the immutable exact-version handler registry against every
  nonterminal row. Each iteration recovers expired claimed/running work before
  claiming again. The P1.9 owner/attempt/expiry/cancel fence and atomic canonical
  effect/result commit remain authoritative.
- Claim ordering first rotates exact `(job_type, handler_version)` lanes and then
  actor lanes using durable rows with prior attempts. Permanent tests reconstruct
  the worker object between every claim and retain `A, B, A` ordering; no
  in-memory fairness cursor is required.
- A non-daemon heartbeat renews long preparation below one third of the lease.
  Terminal commit still requires the live database fence, so heartbeat failure
  cannot authorize a stale effect. Polling, heartbeat, and handler execution are
  serialized to one claimed job in this service.

## Machine-wide model ownership

- Production roles are exact: `development`, `web`, or `worker`. The historical
  default is `development` for compatibility; invalid spellings and whitespace
  fail closed. A worker role cannot compose Flask hosts.
- Local inference in `worker` requires an active machine-wide Windows mutex named
  `Global\\CodeAssistV1InferenceOwnerV1`. The database path is still required to
  be absolute, but it deliberately does not scope the mutex: a second deployment
  using another DB path is not another GPU lane.
- Acquisition uses `CreateMutexW` plus zero-time `WaitForSingleObject`. A live
  owner yields `InferenceOwnerBusyError`; a killed owner leaves an abandoned or
  released kernel object that a restarted process can acquire. No file lock,
  PID file, or mutable in-process queue is ownership authority.
- A two-process `JOB-005` proof shows that both production web processes are
  denied local inference. A separate process holds the global owner while the
  parent, using a different DB path, is denied; after forced child termination,
  the parent takes ownership.

## Web and development boundary

- Production `web` returns before GGUF catalog refresh/autoload, omits GGUF from
  the model list/default priority, and fails before local file discovery, path
  resolution, load, or execution. Guards exist at app composition, loader,
  internal-LLM, chat-stream, and process-local semaphore boundaries.
- The historical callable `JobManager.submit/create_job` and Outlook scheduler
  are development-only. Production web/worker roles fail before creating a JSON
  job or invoking a callable. This prevents the eight retained compatibility
  submit call sites from becoming production process authority while preserving
  their explicit development behavior.
- Canonical publication preview remains the concrete web-producer proof: source,
  preview, durable job, operation, audit, and outbox commit atomically; the exact
  handler can be reconstructed in a separate worker process and commits the
  ready/failed result without duplicate knowledge effects.
- Remote API/Codex compatibility is not a local-GPU owner. Actual Windows service
  wrapping and startup order remain P7.5 rather than being hidden in imports.

## Safety and deliberate limits

- No model file was opened and no inference was run. Tests used fake exact
  handlers and OS ownership primitives only.
- No production worker loop, WSGI host, Outlook scheduler, feature flag, route
  traffic, live data root, canonical live DB, or external service was started.
- The global mutex is the single-machine GPU boundary. P7.5 still must freeze the
  service account/ACL and service wrapper; P7.7 must rerun crash/fault profiles on
  the target; P7.8 must prove forty-client latency/saturation.
- Legacy submit call sites remain only for explicit development compatibility.
  Production roles reject them; canonical durable producer/handler conversion is
  the production authority and later projection/operations handlers remain their
  owning P7 tasks.
