# P3.6 scope selector and new-conversation UX evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P3.6 passes its disabled implementation boundary. Canonical server state now
produces a bounded personal/current-part selector and an independent immutable
conversation badge. The browser component implements immediate management
reload and explicit new-conversation chat switching without mutating the old
conversation.

This evidence does **not** register an HTTP/SSE route, enable the component,
change a feature flag, start a worker, access live data, disable legacy reads,
or claim the P3/G-07 gate. The component is hidden until P3.7 binds trusted
canonical route adapters and passes the end-to-end canary/session gate.

## Frozen server behavior

- `ScopeSelectionService.read()` accepts only a canonical actor ID, positive
  captured scope epoch, optional canonical selected-space UUID, and optional
  canonical conversation UUID.
- One read-only `DEFERRED` transaction resolves `SessionPrincipal` and returns
  exactly the actor's personal space plus at most the current part space.
  Team/responsibility/foreign/stale selections are absent and rejected.
- An optional conversation is loaded through owner-bound repository access.
  Its immutable `space_id`, kind, label/path, row version, lifecycle status,
  and current accessibility remain a separate badge; selecting a management
  space never changes this badge or the canonical conversation.
- After a part move, the old conversation still reports its original part
  badge and `stale_part_scope`, while that part is no longer selectable. A stale
  actor epoch, foreign conversation, missing space, or inconsistent hierarchy
  fails closed.
- The service opens only `read_only=True`, imports no mutation service, contains
  no write SQL, and leaves conversation/audit/outbox row counts unchanged.

## Frozen browser behavior

- `static/knowledge_scope.js` is a dependency-injected controller. It has no
  `fetch`, XHR, legacy session URL, user/actor selector, or conversation-update
  function. P3.7 must inject the authenticated canonical snapshot and create
  adapters.
- Snapshot validation permits exactly one personal and at most one part option,
  exactly one selected option, and only immutable personal/part conversation
  badges. Forged higher spaces, duplicate/unknown options, inconsistent
  selection, malformed access data, or a mismatched create result fail closed.
- Management selection first obtains a validated server snapshot, then reloads
  `list`, `search`, `graph`, `index_log`, `activity`, `candidates`, and `pins`.
  It never invokes the conversation creator.
- Chat selection preserves the current badge/history and exposes the sole
  primary action `새 지식공간으로 새 대화 시작`. The controller creates a
  stable operation ID per pending target, coalesces simultaneous clicks, and
  accepts the transition only after a distinct returned conversation and a
  matching immutable server badge are observed.
- The semantic top-bar markup, selector, badge, action, and cancel control are
  shipped `hidden`; adding the canonical adapter and enabling traffic belongs
  to P3.7, so current legacy UI behavior is unchanged.
