# P5.2 immutable item edit service evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P5.2 passes the tested immutable-save implementation gate behind disabled
canonical traffic. One service-owned SQLite transaction revalidates the P5.1
scope/token/fence/base proof and commits the immutable content revision,
curation rescan state, item compare-and-swap, stale-evidence invalidation,
lease release, audit, outbox, and exact operation results together.

This is not a feature rollout. No route, UI, feature flag, live database,
source tree, worker, or production traffic was accessed or enabled. P2.8
remains separately blocked on operator-approved frozen rehearsal inputs.

## Frozen save contract

- `SaveItemCommand` requires the authenticated principal and captured scope
  epoch, exact space/item/editor session/lease IDs, positive fence, exact item
  row version/current revision, caller UUID operation/request IDs, 1..2,000,000
  non-NUL Markdown characters, a bounded non-blank reason, and a strict
  32-byte lease token encoded as unpadded base64url.
- The edit operation request hash binds token HMAC/key ID, fence, lease/session,
  expected row/revision, raw and LF-normalized content hashes, UTF-8 byte size,
  normalizer version, and normalized reason. Exact replay returns the stored
  effect; the same operation ID with changed content, base, or reason fails.
- Commit-time EDIT resolution and `validate_edit_fence_in_transaction` prove
  current actor scope, current item/base, holder/session/token/generation, and
  non-expiry inside the same `BEGIN IMMEDIATE` transaction.
- Success enqueues exactly one queued `curation.rescan` v1 job with fixed input,
  expected content evidence, and current authorization snapshot. It inserts one
  immutable revision/body and one `revision_rescan` transition, then CASes the
  active item to that revision, provisional curation state, and row version +1.
- Pending/approved findings fixed to the replaced revision become obsolete;
  their pending/approved update proposals become obsolete. Affected semantic
  edges become inactive with `needs_revalidation=1`. The current search/FTS
  source row is removed and target-space generation advances once.
- The exact lease is released without reusing its generation. One
  `knowledge_item.edit` audit and one `knowledge_item.edited` outbox event bind
  base/new revision, transition, rescan job, fence/lease, invalidation counts,
  result row version, and space generation. The edit and job dedup rows commit
  last in the same transaction.
- Rejected stale, expired, force-released, or moved-scope saves add no revision,
  job, audit, outbox, generation, or lease-release effect. Revision conflicts
  return current revision/row metadata plus preserve/copy/reacquire recovery and
  never permit force overwrite.
- Raw lease tokens and Markdown are excluded from command reprs. Raw tokens are
  absent from the response, SQLite database, WAL, and SHM bytes; only the P5.1
  HMAC evidence is persisted.

## Acceptance ownership

| `LEASE-001` | Acquire then save atomically writes the revision and releases the exact lease while preserving its generation. |
| `LEASE-003` | An expired lease cannot save. |

P5.7 still owns real web-process save races, 40-client lifecycle load, and the

## Atomicity and failure proof

Permanent named boundaries cover:

```text
edit.after_rescan_enqueue
edit.after_revision_insert
edit.after_current_pointer_update
edit.after_item_effect
edit.after_lease_release
edit.after_audit
edit.after_outbox
edit.before_commit
```

Each named boundary raises inside the service-owned transaction and restores
the exact held-lease baseline. A second dynamic test observes every mutating
application SQL statement, discovers 16 DML boundaries through the terminal
edit-dedup commit, and raises immediately after each boundary in a fresh retry.
Every run restores exact item/revision/body/transition/job/dedup/audit/outbox,
finding/proposal/edge/search, space-generation, and lease rows and passes every
canonical migration postcondition.

The successful published-item path additionally proves search-document removal
and published-to-provisional transition. Fixed semantic-edge and update-proposal
fixtures prove bidirectional stale-evidence closure and exact audit counters.
