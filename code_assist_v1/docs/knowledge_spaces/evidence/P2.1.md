## Frozen report contract

- The report contains all 41 fixed categories even when their count is zero.
  Its only record kinds are `physical_file`, `logical_record`, and
  `unavailable`.
- Every record has a stable source identity, owner claim, parent policy,
  proposed class from `imported | rebuilt | retained_external | quarantined |
  unavailable`, and authority `scanner | planner_required`.
- `inventory_contract_errors()` independently recalculates record and
  relationship identity/endpoint closure, parent/child counts, category
  action/authority/owner/parse/kind/terminal aggregates, aggregate hashes,
  reconciliation totals, and the overall manifest hash. A mismatch is a hard
  `RECONCILIATION_INCOMPLETE` result.
- `proposed_terminal_classification="imported"` means only that a later reviewed
  plan may import the record. It is not an observed migration outcome. P2.2
  owns the final plan and P2.6 owns observed one-of-five reconciliation.
- Strict mode fails on corrupt, unreadable, ambiguous, missing-reference, or
  unknown input. `--allow-partial` may serialize record-level data-quality
  failures but never relaxes root/reparse, source-drift, code-ledger, SQLite
  snapshot, or report-closure gates.

## Source and semantic closure

- Registry rows validate canonical IDs, key/ID equality, password-hash
  presence without exposing it, exact role/status vocabulary, legacy disabled
  state, and NFKC/casefold collisions. Owners are summarized by canonical user
  with all claims and source paths.
- Graph nodes resolve to actual same-owner wiki source/page records; edges use
  an exact producer relation vocabulary and mutually exclusive valid,
  duplicate, orphan, or legacy-auto dispositions. Candidates bind structural
  source/target evidence, and hidden pages record exact-content duplicates.
- Known-producer inline Markdown asset references resolve to physical records;
  missing targets become synthetic unavailable records. Browser pins also
  produce an explicit unavailable record.
- Session core metadata and every message/metadata/summary/upload/binding
  collection receive hash-only logical children. Legacy job identity, owner,
  kind, and state are validated, and queued/running jobs remain non-runnable
  abandoned legacy input.
- Notion SQLite is copied with its WAL/SHM/journal bytes into scanner scratch
  before the copy is opened read-only. The scanner validates integrity,
  foreign keys, required/unknown tables, schema and per-table row hashes, link
  owner/page/session identity, and keeps the live DB/files external.
- Raw document bodies, password hashes, cookies, tokens, secret enum values,
  unknown SQLite table names, and raw Notion BLOB values are not emitted.

## Snapshot and filesystem boundary

All source roles (`legacy`, `knowledge`, `runtime`, `user_data`, `sessions`,
and `workspace`) must be declared or safely discovered and are recorded with
requested/configured/final resolved paths, volume facts, and reparse facts.
Sources and scratch must be absolute, local, fixed NTFS, reparse-free, and
non-overlapping. File opens use no-follow/identity checks; roots, code coverage,
scratch, and source high-water hashes are rechecked after all reads. Output is
an atomic create-if-absent operation unless explicit replacement is requested,
including the validate/write winner race.

On Windows, the scanner holds the approved scratch and output directories open
and creates children relative to those directory handles. Each scratch-copy or
output temporary file is made delete-pending before bytes are written, flushed
through that same handle, and only then made linkable for its handle-relative
final rename. Permanent adversarial tests prove that the pinned directories and
scratch child cannot be renamed during use, that a temporary scratch/output
file cannot be renamed or hard-linked into a source while it is writable, and
that a late output winner is preserved rather than clobbered.

`source_snapshot.attestation_sha256` is an external value supplied by the
operator or snapshot procedure. The scanner validates its format and time,
binds it to the declared final roots through `root_binding_sha256`, and checks
scan-time drift. It does not authenticate that value, create the snapshot,
prove writer quiescence, or independently prove application-level consistency.
