## Reviewed authority and evidence boundary

- Only the frozen P6.3 tuple `semantic_edge/info/T2/human/space_editor/none/
  relation` is applicable. The finding must already be `approved`, have the
  caller as its explicit reviewer, and match the expected row version.
- The authenticated `SessionPrincipal` and current scope epoch are resolved
  again inside the application transaction for effective `CURATE`. Foreign
  personal-space access is intentionally returned as undisclosed not-found.
- The request fixes source and target evidence revisions plus the SHA-256 of
  the exact canonical P6.3 evidence object. Any changed version, revision, or
  evidence fails before a domain effect.
- The repository parses an exact immutable action object and derives the edge
  type from `related|supports|contradicts|depends_on|extends|example_of`.
  A client/model cannot supply or change the committed relation type.
- Source and target must remain different, current, active, published, and in
  the same active writable concrete space. Endpoint drift transitions the
  approved finding to `obsolete` and creates no edge or generation change.
- Active `(space,source,target,type)` collision and deterministic edge-ID
  collision fail closed. Deterministic fork/promotion/exact provenance remains
  in immutable/versioned `item_relation`, never `knowledge_edge`.

## Transaction, replay, and confidentiality boundary

- The service owns one short write transaction. It reserves the actor-scoped
  `semantic_edge` operation before the repository may change state.
- Success writes the applied finding proof, one active `semantic_approved`
  edge with exact evidence revisions, one space-generation increment, one user
  audit, one outbox event, and one committed operation result atomically.
- The stale branch writes only the `obsolete` finding plus audit/outbox/result.
  It creates no edge and leaves space generation unchanged.
- Exact operation/input replay returns the stable stored result without another
  mutation. Reusing an operation ID with any changed reason or bound evidence
  fails as an idempotency conflict.
- Failpoints after obsoletion, finding application, edge insertion, domain
  effect, audit, outbox, and immediately before commit prove full rollback of
  finding, edge, generation, audit, outbox, and operation state.
- Persisted edge evidence contains the body-free P6.3 evidence object, hashes,
  UUIDs, versions, and rule identity only. Source/target Markdown and sensitive
  request metadata are absent from edge, audit, outbox, and operation rows.
