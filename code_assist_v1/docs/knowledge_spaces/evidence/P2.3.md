# P2.3 users, personal items, and assets importer evidence

Date: 2026-08-13 (Asia/Seoul)

## Result

P2.3 passes its isolated, reviewed-plan-bound importer boundary. The production
code consumes only an exact `reviewed_migration_plan`, imports the P2.3 identity
and personal-content subset, and persists every committed source or
`asset_reference` effect in immutable migration ledgers.

This evidence does **not** claim that a production snapshot was migrated. It
does not claim P2.4 graph/history, P2.5 conversation/operational state, P2.6
observed verification/rebuild, P2.7 fault/large migration scenarios, P2.8
rehearsal, any `MIG-001..008` completion, traffic cutover, worker startup, or
enabled part writes.

## Frozen apply boundary

- `migrate apply` requires the exact reviewed-plan document SHA, the exact
  approved data/database/blob/projection layout, an already-current canonical
  schema, `--resume`, and a batch size from 1 through 100. It never discovers a
  plan, organization mapping, source root, or schema upgrade implicitly.
- The source reader reconstructs the reviewed P2.1 inventory, validates every
  root binding, opens every directory and file component handle-relative with
  reparse-point protections, verifies final paths/file identity/size/mtime/SHA,
  and retains the source handles through the owning database transaction.
  Snapshot high-water state is checked before identity, before every content
  batch, and at the final boundary.
- Identity bootstrap verifies the exact bound registry bytes outside SQLite,
  then imports reviewed users, organization membership/leader assertions,
  personal spaces, immutable child mappings, the dependency-closed registry
  container, audit, and outbox in one service-owned transaction. The batch is
  limited to 100 imported accounts.
- Assets are staged and streamed to content-addressed storage before SQLite is
  opened. The retained blob handle binds the verified bytes through commit.
  CAS rows use `application/octet-stream` as their deterministic storage media;
  source artifacts and manifests retain each reviewed source media type. Thus
  identical bytes from different legacy extensions share one CAS object while
  preserving both source identities and formats.
- Personal Markdown and the frozen legacy Markdown/text/JSON adapter set create
  exact source artifact/raw manifest, ready extraction, body, personal item,
  revision, and migrated provenance effects. Same-owner exact-body duplicates
  add provenance to one item; cross-owner content never deduplicates. Invalid
  UTF-8, malformed structured input, unsupported extensions, missing assets,
  owner mismatch, or source/storage drift fail closed or remain reviewed
  quarantine decisions.
- Valid same-owner `asset_reference` rows create one embedded-asset manifest
  and one immutable relationship checkpoint only after both endpoint mappings
  and physical blob observations verify. Records and relationships are replayed
  in deterministic plan order; a committed prefix resumes without duplicate
  items, revisions, artifacts, mappings, audit, or outbox rows.
