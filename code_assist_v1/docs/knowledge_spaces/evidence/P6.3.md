# P6.3 versioned finding service evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P6.3 passes its isolated versioned-finding task behind disabled canonical
traffic. Finding policy is server-derived, evidence is versioned and body-free,
candidate-backed conclusions are rebound to the complete P6.2 snapshot, and a
human review transition commits with idempotency, audit, and outbox in one
service-owned transaction.

This is not the aggregate P6 gate. Approval records only a reviewed finding
state; this slice cannot apply a semantic edge, merge, replacement, update,
publication, quarantine, deactivation, or purge. P6.4-P6.8 own those effects,
UI/shadow evidence, and aggregate acceptance.

## Frozen policy and evidence boundary

- `p6.3-finding-policy-v1` contains the exact 18 v1 tuples from
  `SCHEMA_V1.md` for kind, severity, T0–T3 tier, decision mode, reviewer,
  visibility, and proposed action. Callers cannot supply or lower those fields.
- Severity remains distinct from risk tier. No T2/T3 tuple is automatic.
  `weak_complementary` is T2/human/published badge/no-action;
  `near_duplicate` and `potential_conflict` are T2/human/Agent-hidden review;
  `deactivate` and `purge` are T3 review records only.
- Source/target IDs form the frozen pair shape, are different, current, active,
  and in one concrete space. Candidate targets remain published; strong risky
  sources remain provisional; weak-complementary sources remain published.
- Persisted evidence contains only UUIDs, versions, finite confidence, sorted
  codes, hashes, sizes, and 1-based/end-exclusive span coordinates. It never
  stores Markdown, titles, prompt bodies, model output, credentials, tokens, or
  arbitrary request metadata.
- Transient Markdown is UTF-8 bounded to 2,000,000 bytes, rebound to exact raw
  and `markdown_lf_v1` normalized hashes/size, and discarded after each span's
  exact normalized excerpt SHA is verified.
- Candidate-backed weak/near/conflict/semantic/replace/merge findings require
  the full `IncrementalCandidateSnapshot`. The P6.2 validator must pass and its
  evidence hash, concrete source IDs/hashes/size, selected target IDs/title/
  content hashes/size, and same-space binding must match canonical rows.
- Exact-repeat automation requires exact raw+normalized hash and size equality;
  normalized-only matches cannot enter that path. T0/T1 model metadata is
  rejected. Model and prompt versions are an all-or-none pair elsewhere.
- The deterministic finding UUID binds policy, endpoints, evidence hashes and
  spans, detector/rule/model/prompt versions, confidence, and relation proposal.
  An ignored row suppresses only that exact identity; a rule/model/revision/
  evidence change creates a different identity.

## Review and transaction boundary

- System detection opens one short write transaction. New finding, system audit,
  and outbox rows commit together; exact existing input performs no duplicate
  write. Failures after finding/audit/outbox all roll back.
- Human review requires an authenticated `SessionPrincipal`, current scope
  epoch, effective `CURATE`, expected finding row version, and the database-
  derived reviewer class. `purge` additionally requires an active administrator.
- Endpoint current revision, active lifecycle, and kind-specific curation state
  are rechecked immediately before review. Drift transitions pending to
  `obsolete` without fabricating a review triple.
- Approve/reject/ignore or obsolete state, one actor-scoped operation result,
  one audit, and one outbox commit together. Same operation/input replays the
  stable prior result; changed input under the same operation ID fails closed.
- T3 approval does not execute its proposed lifecycle/purge action. The service
  imports no model, HTTP, subprocess, graph, proposal, lifecycle, merge, or
  purge executor and exposes no such dependency.
- Existing immutable edit service coverage proves a real revision save marks
  fixed-revision pending/approved findings obsolete in the same edit
  transaction. P6.3 also directly verifies the repository's pre-review stale
  endpoint branch.
