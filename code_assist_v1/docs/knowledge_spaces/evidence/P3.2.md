# P3.2 server-persisted pins and explicit-context evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P3.2 passes its inert canonical pin and explicit-context storage/service
boundary. Pins cannot cross spaces and always identify one fixed current
active/published revision. Explicit workspace, project, Notion, and canonical
source context is resolved by a trusted injected server boundary rather than
browser-supplied artifact identifiers or hashes.

This evidence closes only the P3.2 implementation task and the storage portion
of `CONV-013`. It does **not** register HTTP/SSE routes, execute retrieval,
change legacy chat/session traffic, enable Knowledge Core feature flags, enable
part writes, or claim the P3/G-07 gate. P3.3-P3.6 retain those responsibilities.

## Frozen behavior

- A pin requires an active accessible conversation, an active/published item in
  the same exact space, and the item's current revision. A stale revision or
  cross-space item is rejected before mutation.
- Natural duplicate pin insertion is a no-op. Remove and exact operation replay
  are deterministic and preserve the original result.
- Context commands contain only the binding type, binding mode, and external
  resource key. They do not accept a source artifact ID, snapshot hash, owner,
  or target space from the caller.
- A trusted injected resolver runs before the write transaction and must return
  the exact requested type/mode/key and the conversation's exact space. For a
  snapshot it also returns canonical source-artifact/hash evidence; the
  transaction revalidates that evidence against the database.
- A committed add-context replay does not contact the external resolver again,
  but it rechecks the current active actor and conversation access. A live
  resolver outage therefore cannot invalidate an already archived exact replay.
- Detach is immutable history. Repeating detach is a no-op, while a later
  explicit re-attach creates a new binding identity.
- Personal and part-space fixtures prove same-space pin behavior, direct
  cross-space rejection, and zero implicit personal context for a new part
  conversation.
- Every mutation owns one short transaction containing the domain effect,
  operation-dedup result, audit event, and outbox event. Injected audit failure
  leaves all four surfaces unchanged.
