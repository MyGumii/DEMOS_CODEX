## Frozen verification boundary

- `migrate verify` requires the exact reviewed plan SHA, explicit canonical
  database/blob/projection roots, the current schema catalog, and a safe local
  storage binding. It does not scan a live legacy source or reinterpret planner
  policy.
- Exactly one phase-specific immutable checkpoint is required for each reviewed
  imported record and relationship. Every checkpoint is rebound to the plan,
  inventory manifest, root binding, normalized source identity, and canonical
  target. Unplanned or duplicate checkpoints fail closed.
- P2.3 user/content/asset/asset-reference effects, P2.4 graph/finding/container/
  labelled-history effects, and P2.5 conversation/message/summary/metadata/
  Notion-link/job-history effects are replayed through their independent target
  integrity contracts. Schema, quick/FK, space, owner, endpoint, and evidence
  drift cannot be hidden by a resealed report.
- Every imported CAS object is reopened through a no-follow, fixed-layout,
  one-link handle and its bytes, size, media type, raw digest, and Markdown LF
  normalized digest are reverified outside SQLite transactions.
- `search_document` and FTS are rebuilt transactionally from current
  active/published revisions only. Two-personal-space canaries prove same-space
  results and zero cross-space matches.
- The full file rebuild captures one read-consistent canonical snapshot per
  database and emits one immutable generation per space:
  `sources/<item-id>.md`, `index.md`, `log.md`, `graph/graph.json`, and
  `graph/backlinks.json`. Old legacy index/backlink files are never inputs.
- Source filenames use immutable item IDs. Graph/backlinks include only stored
  active edges whose two endpoints are current active/published items in the
  same space. Audit projection is labelled and body-free.
- Windows directory handles pin all output parents. New files remain
  delete-pending while written, each complete generation is checksum-verified
  before same-directory handle rename, and every verified generation file
  remains handle-pinned against write/delete through per-space manifest
  publication and the `projection_state` commit. Only the small per-space
  `manifest.json` is atomically replaced. Reparse/multiply-linked files are
  rejected.
- Canonical state is captured again after staging and inside the short
  `projection_state` transaction. Drift prevents manifest publication or state
  advancement. A manifest-write failure preserves the previous pointer; a
  staged orphan generation is immutable, safe, and reusable on exact retry.
- Exact replay is byte-identical, creates no extra generation, and leaves
  `projection_state.row_version` unchanged when already exact.
