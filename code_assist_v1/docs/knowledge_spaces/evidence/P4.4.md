# P4.4 stable Notion provenance evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P4.4 passes its disabled canonical-traffic implementation boundary. A ready
authorized Notion source now carries exact body-free owner, page, revision,
source snapshot, asset manifest, publisher, and captured-part evidence. An
unchanged stable source remains `no_op`; a changed stable source preserves the
current item/revision and creates one fixed human-reviewed update proposal.

This evidence does **not** register or enable the canonical publication route,
change a feature flag, start a worker, touch a live database, enable part
traffic, or claim a completed `PUB-*` or `PROP-*` scenario. The two existing
legacy wrappers are proven to share one legacy immutable snapshot/write
delegate; P4.5 still owns the canonical API/UI cutover. P4.6 owns exhaustive
SQL failpoints, process/restart races, 1,000 retries, and the complete
`PUB-001..013` acceptance gate.

## Frozen Notion provenance contract

- `build_source_artifact_bundle` accepts an authorized Notion snapshot only
  for `origin_type='notion'`. It binds actor/publisher, owner, page, stable
  origin key, page revision, source-snapshot SHA, asset-manifest SHA, exact
  Markdown content SHA/body, and captured part before persistence.
- A ready Notion source artifact stores a strict `notion_provenance` envelope
  containing only hashes and safe identifiers. The artifact repository
  independently validates the exact key set, scalar types, owner/page origin,
  and source-snapshot revision binding. Missing, extra, or drifted provenance
  fails before source-artifact insertion.
- Manual, upload, and chat sources reject a Notion snapshot and retain their
  pre-existing exact metadata contracts. No raw Notion body or credential is
  written to metadata, audit, outbox, or proposal evidence.

## Frozen changed-source proposal contract

- An unchanged stable origin revision remains `no_op`; a different-origin
  exact body retains the existing provenance behavior.
- A changed stable Notion origin resolves one unambiguous current target
  item/revision and inserts one deterministic T2 `curation_finding` with
  `decision_kind='human'`, `reviewer_scope='space_editor'`, pending status,
  and Agent-hidden visibility.
- The paired deterministic `change_proposal` has kind
  `stable_source_update`, version 1, `pending_review` state, fixed source
  artifact/extraction, fixed base item/revision, fixed target space, fixed
  finding row version, exact proposed Markdown body reference/hash/size, and a
  canonical preview SHA. The current item and revision are not overwritten.
- The same immediate transaction inserts the `update_proposed` publication
  target, consumes the preview, writes target audit, finding-queue outbox, and
  publication-operation outbox, and commits the actor-scoped idempotent result.
  No target generation changes because no visible item/revision changes.
- Exact operation replay returns the first stored result after independently
  validating the immutable finding/proposal/source/target bindings. Later
  review-state evolution is allowed, but the fixed proposal inputs may not
  drift. A late failure rolls back every new finding, proposal, publication,
  audit/outbox, dedup, and preview-consumption effect.

## Independence and existing-route contract

- Personal and current-part changes create separate proposals against their
  separate current items. A repeated `both` publication creates two independent
  proposals and does not synchronize, replace, or re-lineage the items.
- The existing Notion workspace and code-bridge route wrappers are permanently
  tested to delegate the same actor, page, source store, target store, write
  lock, and approved snapshot to
  `publish_page_to_legacy_second_brain`. This proves there is one legacy
  wrapper-side mutation boundary; it does not enable the P4.5 canonical route.
- Publication creates no semantic relation and invokes no model/LLM path. P6
  may later enrich or review the fixed finding/proposal without changing its
  P4.4 source/base/target evidence.
