# P3.4 canonical turn-context composition evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P3.4 passes its disabled canonical Agent turn-context implementation boundary.
One accepted canonical turn determines its immutable knowledge space and search
text. The service then performs exactly one canonical FTS retrieval and returns
only current pin results and explicitly attached, labelled context references.

This evidence does **not** enable or register an HTTP/SSE route, change a
feature flag, start a worker, access live data, or claim the P3/G-07 gate. The
legacy Flask chat route remains authoritative until the P3.7 API/Agent canary
and traffic-disablement gate.

## Frozen behavior

- The public service request contains no `space_id`, query override, browser pin
  state, private-memory selector, or project/workspace/Notion default. Actor,
  current scope epoch, conversation, and accepted turn are the only authority
  inputs; retrieval text comes from the immutable canonical user message.
- The first read snapshot requires an active actor, current scope epoch, owned
  active conversation, current read capability, accepted/running turn, exact
  accepted event, exact user message, and no more than 20 attached bindings.
- Explicit live/snapshot materialization runs outside SQLite. Before returning
  any result, a second transaction revalidates all authority facts and compares
  the complete turn and attached-binding tuple. Concurrent detach, scope move,
  archive, or terminal turn therefore fails closed.
- Exactly one `RetrievalRepository.retrieve` call uses the conversation-derived
  space. Pins are re-read each turn and become explicitly unavailable when the
  item is not active/published, the revision is no longer current, its body is
  unavailable, or its search document is unavailable.
- Live context is reauthorized every turn. An availability transition uses
  row-version CAS and commits the canonical row, audit event, and outbox event
  atomically. Exact replay emits no duplicate event; injected audit failure
  rolls the transition back.
- Immutable snapshots cannot degrade to a live/unavailable result and must
  reproduce their stored SHA-256. Resolver identity, scope, mode, external key,
  row version, content SHA, and evidence SHA are exact checked.
- Each context is bounded to 32 KiB and all contexts together to 128 KiB.
  Control characters are rejected. Pin/context Markdown is returned only in
  structured values labelled `untrusted_reference`.
- The canonical module contains no legacy KB, Second Brain, memory, project,
  workspace, Notion-store, pinned-thought, or browser-state dependency. It
  records `retrieval_call_count=1` and explicit false legacy/implicit-context
  facts in the result contract.
