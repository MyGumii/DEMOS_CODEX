# P7.5 production WSGI and Windows service packaging evidence

Date: 2026-08-15 (Asia/Seoul)

## Result

P7.5 passes its P0.2-isolated, disabled-service/traffic implementation
boundary. The production HTTP host, Windows service package, protected
configuration, service-account/ACL policy, startup/drain order, and sole
periodic checkpoint coordinator are explicit, versioned, and fail closed.

This is not an installed target-server or aggregate P7/`G-11` claim. No SCM
service or account was created, no target ACL was applied, no production port,
worker, or projector was started, and no live root/database, flag, model, or
traffic was accessed or enabled. P7.6-P7.9 retain deep health/metrics,
randomized restart/fault, target-class load, and signed target restore/service
authority.

## Exact server and deployment manifest

- `requirements-runtime.lock` pins Waitress `3.0.2`. The host rechecks the
  installed distribution immediately before listener construction and binds
  sixteen threads, 128 connections/backlog, 60-second channel timeout,
  30-second cleanup, untrusted-proxy clearing, hidden tracebacks, stable server
  identity, and a 30-second non-cancelling drain.
- The wrapper is WinSW `2.12.0`, asset `WinSW-x64.exe`, SHA-256
  `05b82d46ad331cc16bdc00de5c6332c1ef818df8ceefcd49c726553209b3a0da`.
  Package rendering verifies both the reviewed source and each active service
  copy. Existing exact files are replay-safe; reparse/hard-link/content drift
  fails before package output.
- The canonical deployment example has document SHA-256
  `a5078d94d2227f5c885f6e5bc4ed0a3661a426b5cc72b41f6e8d18ff0effca6e`
  and embedded config SHA-256
  `6e61a94e8a6ab743759620153124a6a02b2b501cadbedb174cdac018b8f96683`.
  It exactly owns WSGI/wrapper/checkpoint constants, ports, service rows,
  startup order, absolute paths, dedicated account, and ACL policy. Data,
  logs, backup, and immutable working tree cannot overlap.

## Protected environment, paths, and account

- The protected environment is canonical UTF-8 without BOM, LF-only, final
  LF, at most 1 MiB, duplicate-free, and non-interpolating. It rejects process
  role/path/browser-security authority, test mode/data roots, failpoints,
  unapproved namespaces, and controls. Direct mapping calls repeat the same
  validation, then remove unreviewed inherited application namespaces.
- Both manifest-bound `127.0.0.1` web origins are mandatory because the start
  script health-gates those exact endpoints. This fixed an observed real
  Waitress `403 request_origin_not_allowed` startup failure in the first
  process test; the canonical environment example now binds both health
  origins plus the reviewed external origin.
- Before package mutation, every immutable input and mutable root must be an
  existing fixed local NTFS, non-reparse, final-path-identical object with the
  reviewed kind; files are single-link. Runtime readiness repeats those facts
  and binds cwd, Python executable, current Windows account, source/active
  wrapper hashes, dependency lock, SQLite source/runtime, feature flags, and
  canonical storage.
- Only `CodeAssist-Migrator` may preflight an absent database. Its existing
  safe parent is checked, and `SingleMigrator` retains exact SQLite, storage,
  schema, and postcondition authority. The other services always require a
  complete production runtime preflight.

## Service split, ACL, and lifecycle

- Exact services/order are `CodeAssist-Migrator`, `CodeAssist-Web`,
  `CodeAssist-Notion`, `CodeAssist-DurableWorker`, and
  `CodeAssist-Projector`. The migrator is manual/one-shot; both web apps use
  only `ProductionWSGIHost`; worker and projector are explicit stop-aware
  loops. Development `app.run()` remains separate.
- Installation requires an administrator and a pre-provisioned dedicated
  account. It removes inherited ACLs; grants service read/execute on the
  immutable working tree, modify on data/log/backup, read on config/env, and
  preserves SYSTEM/Administrators full control. The password is never written
  to XML, command arguments, files, or stdout; the transient BSTR is zeroed.
  SCM credential failure reverses every installed service.
- Start waits for the migrator to stop successfully, then health-gates Web and
  Notion before worker/projector. Stop order is projector, worker, Notion, Web,
  with named manual-reset stop events and a wrapper hard bound longer than the
  application drain. WinSW logs roll at 10 MiB and retain eight files.
- The operator must provision the account and service-logon policy. This slice
  deliberately does not claim that target SCM/account/ACL state was observed.

## Checkpoint and real-process proof

- `CodeAssist-Projector` alone owns the machine-wide
  `Global\CodeAssistV1CheckpointCoordinatorV1` mutex. It uses the narrow DB
  capability `PRAGMA wal_checkpoint(PASSIVE)` every 300 seconds; ordinary
  connections cannot execute effectful pragmas. `TRUNCATE` remains limited to
  the existing isolated, drained restore activation.
- Two independent child processes create the actual `app_code` and
  `app_notion` Flask applications and serve them with the installed Waitress.
  `/healthz` returns production mode, the `Server` header contains
  `code-assist-v1` and not Werkzeug, named stop exits cleanly, and an already
  running request completes before process exit.
- A separate child owns the checkpoint mutex while the parent is rejected;
  after release the parent acquires it. Absent service stop events fail closed.

## Safety and deliberate limits

- The permanent process tests use random loopback ports and only the isolated
  `D:\CodexTestTemp` fixture. They do not invoke WinSW/SCM or the install/start
  wrappers and do not inspect the repository's live-looking compatibility
  roots.
- P7.5 proves an exact deployment package and real production WSGI/process
  behavior, not target account rights, installed ACLs, reverse proxy/TLS,
  monitoring, fault endurance, capacity, or restore readiness.
- The durable worker currently registers the reviewed publication-preview
  handler. Feature flags and traffic remain off; later handler coverage and
  kill/restart convergence remain P7.7 authority.
- No password/token/body is included in the manifest, XML, preflight report,
  test output, or this evidence.
