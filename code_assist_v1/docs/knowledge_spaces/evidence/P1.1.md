## Implemented boundary

- `knowledge_core` now declares the complete architecture module tree:
  connection/migration, domain/error/scope/route/worker, twelve repositories,
  eight services, four projection components, and three legacy adapters.
- All repository, service, projection, migration, and legacy modules are inert
  boundaries in P1.1. Importing the package opens no SQLite connection, reads no
  application config/store, starts no thread, and writes no file.
- One composition contract defines stable host profiles for `app_code`,
  `app_notion`, and Blueprint. Host registration is idempotent and rejects a
  conflicting host, flags, target, or foreign extension value.
- The container exposed by the host is the exact same object presented to route
  adapters, preventing later route closures from capturing a provisional copy.
- Every service slot is explicitly unbound and fails with a stable non-secret
  error until its owning phase supplies an implementation.
- Registration in P1.1 adds zero URL rules and returns an empty route-group
  manifest.

## Rollout safety

The seven flag names remain exactly aligned with the P0.4 runtime preflight.
Values accept only the literal strings `0` and `1`.

- All flags omitted: inert and accepted.
- Only `KNOWLEDGE_CORE_ENABLED=1`: inert scaffold composition is accepted.
- Any traffic, mutation, projection, higher-space, or part-write flag without
  core enabled: configuration failure.
- Any downstream flag with core enabled in P1.1: phase-not-ready failure.
- `KNOWLEDGE_CORE_PART_WRITES=1` and
  `KNOWLEDGE_CORE_HIGHER_SPACES=1` therefore cannot start either web host.

Executable isolated host tests prove unsafe traffic flags fail before auth or
legacy route registration. No UI, environment transition, or runtime command
enabled a flag during this task.
