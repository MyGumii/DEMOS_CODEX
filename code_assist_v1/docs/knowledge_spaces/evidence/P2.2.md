# P2.2 explicit migration planner evidence

Date: 2026-08-13 (Asia/Seoul)

## Result

P2.2 passes its P0.2-isolated offline planning boundary. It converts one exact
schema-v2 inventory and explicit organization mapping into a deterministic
`migration_plan_draft`, then requires a separate hash-bound review operation to
produce a `reviewed_migration_plan`.

This evidence does **not** claim a production inventory or plan, migration
apply, canonical database mutation, observed reconciliation, rerun checksum,
`MIG-001..008`, traffic cutover, worker startup, or enabled personal/part
reads or writes.

## Frozen planning contract

- The exact CSV header/version, UTF-8/RFC4180 shape, selectors, NFKC/casefold
  uniqueness, canonical user/role/status, UUID hierarchy assertions, active
  administrator requirement, and at-most-one represented part leader are
  fail-closed. Every required unowned/global disposition is explicit.
- The planner covers all 41 inventory categories with a frozen action, phase,
  and import-mode table. Scanner-fixed rebuild/retain/unavailable/corruption
  decisions cannot be promoted, and no legacy record targets a part/team/
  responsibility knowledge space.
- P2.1 metadata and original ledger order are retained. Planned rows copy the
  exact sanitized source records and relationships. The independent contract
  reconstructs the full P2.1 report, runs `inventory_contract_errors()`, binds
  its exact canonical-JSON-plus-LF document SHA, manifest/root/attestation/tool
  facts, and then recalculates organization,
  record, relationship, classification, phase, mode, and reconciliation hashes.
- A draft technical hash covers every technical field. Review confirmation
  requires the exact draft document hash, matching technical hash, a real
  canonical UTC timestamp, reviewer ID, and external review-attestation hash;
  the final plan hash covers the draft and review wrapper.
- The external review attestation is supplied and hash-bound but is not
  authenticated by the planner.

## Safety and concurrency boundary

- Planning is a pure in-memory transform after the two input artifacts are
  safely read. It opens no source, canonical database, application config,
  route, worker, or network service and mutates neither parsed input.
- Frozen source paths are contract-validated declarations used only for lexical
  output containment. A missing or moved source root cannot make containment
  fail open, and the planner does not probe it.
- Output is create-if-absent under the P2.1 Windows directory-handle writer.
  Byte-identical late/concurrent winners are idempotent success; different
  winners are `PLAN_DRIFT` and remain unchanged. Read-only directory anchors
  allow concurrent bound readers while still denying write/delete/reparse
  opens.

## Deliberate P2.3-P2.8 boundary

- P2.2 itself still creates no canonical effect. A later bounded P2.3
  `migrate apply` implementation now consumes the reviewed artifact;
  `migrate verify` remains unimplemented until P2.6.
- No user, space, item, revision, artifact, edge, conversation, audit, outbox,
  or legacy mapping row is created by P2.2.
- P2.3-P2.5 own bounded canonical imports. P2.6 owns observed one-of-five
  equality and rerun checksums. P2.7-P2.8 own dirty/large faults and an approved
  rehearsal. No `MIG-*` scenario passes at P2.2.
