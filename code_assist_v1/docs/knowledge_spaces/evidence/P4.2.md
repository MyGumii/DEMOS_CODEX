# P4.2 durable publication preview evidence

Date: 2026-08-14 (Asia/Seoul)

## Result

P4.2 passes its disabled implementation boundary. Upload, manual Markdown,
canonical chat promotion, and authorized Notion page snapshots now converge on
one durable preview model without creating knowledge. Synchronous and
asynchronous ready results preserve immutable source/finding evidence, while
status, cancellation, expiry, failure, and orphan-body cleanup remain durable
and independently auditable.

This evidence does **not** register or cut over a publication route, enable a
feature flag, start a worker, consume a preview, create an item/revision, enable
part publication, access live data, or claim a completed `PUB-*` scenario.
P4.3-P4.6 still own actual single/dual publication, stable Notion update
proposals, API/UI activation, exhaustive failpoints, 1,000 retries, and the
complete `PUB-001..013` gate.

## Frozen source and authorization contract

- Manual Markdown is encoded and prepared deterministically. Chat promotion
  reads one actor-owned, currently accessible, active canonical conversation
  and an exact inclusive contiguous range of at most 100 canonical messages;
  browser-supplied message bodies are never authority. The range, message IDs,
  roles, sequence numbers, canonical content hashes, conversation space, and
  row version form one body-free source identity and are revalidated inside the
  final write transaction.
- The Notion provider returns an already authorized owner/page snapshot. The
  service checks actor, owner, page, safe title, nullable revision/time,
  Markdown content hash, asset-manifest hash, and the exact composite source
  identity compatible with the existing Notion snapshot boundary. Provider
  failure, access denial, caller-expected hash drift, or inconsistent evidence
  fails before a database effect. P4.4 owns the concrete legacy-route adapter
  and changed-source proposal behavior.
- Every create first revalidates the active canonical actor, captured scope
  epoch, personal publish capability, and optional writable current-part
  capability. It freezes `personal`, or `personal|part|both`, with the current
  part and epoch. Exact operation replay returns the original result without
  restaging or rereading chat/Notion; an operation ID reused with changed input
  fails closed.
- Raw staging and extraction/network work happen outside the write transaction.
  A physical staging lease remains held through the canonical commit and is
  closed on every success or failure path.

## Frozen durable lifecycle contract

- Manual/chat/Notion create one ready preview transaction containing artifact,
  extraction, preview, operation result, audit, and outbox. Upload creates one
  raw artifact, queued preview, exact-version durable job, producer operation,
  audit, and outbox transaction; no path creates a knowledge item/revision.
- The P1.9 handler loads and verifies the frozen raw source outside SQL,
  revalidates actor/scope/capability and every expected artifact fact at
  commit, and atomically stores the extraction plus ready/failed preview and
  successful job result. Invalid extraction output, permanent failure, retry
  exhaustion, cooperative/concurrent cancellation, authorization drift, and
  expired-claim recovery converge terminal job and preview state in the same
  transaction. A post-commit worker restart finds no repeatable effect.
- Actor-authorized polling requires an active canonical actor and current epoch
  but not a still-enabled publication-write rollout flag. It reconstructs exact
  queued/extracting/failed/pre-ready-cancelled response shapes from the frozen
  producer operation and returns the immutable ready-result payload with only
  current lifecycle status/timestamps overlaid. Foreign/missing chat sources
  are concealed as authorization failures.
- Repository and schema checks bind state shape, source snapshot, target modes,
  rule version, deterministic finding vocabulary/evidence, ready-result schema,
  expiry, completion time, and legal transitions. SQLite time drives expiry;
  exact maintenance replay emits no duplicate audit or outbox effect.

## Frozen cleanup contract

- Only a terminal, never-published source at or after its fixed 30-day
  `orphan_cleanup_eligible_at` may be cleaned. Any queued/extracting/ready
  preview, item source, lineage, active snapshot binding, unapplied proposal,
  or active backup blocks cleanup.
- One service-owned transaction removes only `artifact_blob_body` and
  `extraction_snapshot_body` links, marks retained artifact/blob/extraction
  metadata `purged` with the stable orphan reason, and appends system audit and
  outbox evidence. Artifact IDs, blob/extraction rows, hashes, sizes, source
  metadata, preview history, and the CAS object row remain. Physical blob GC is
  a separate later idempotent operation.
- An ineligible source, partial stored state, trigger rejection, or injected
  failure changes nothing. Exact replay is a no-op.

## Residual ownership

personal, part, or both into exact target outcomes with all-or-none audit,
outbox, generation, provenance, and lineage. P4.4 owns the concrete Notion
route consolidation and stable-origin changed-source proposal. P4.5 owns the
browser/API cutover, and P4.6 owns the full `PUB-001..013`, failpoint, restart,
and 1,000-retry acceptance gate. P2.8 remains separately blocked on
operator-supplied rehearsal inputs.
