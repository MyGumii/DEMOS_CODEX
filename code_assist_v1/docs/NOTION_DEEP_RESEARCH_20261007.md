# Notion 심층 리서치 구현 — 2026-10-07

## 작업 흐름

자료 리서치는 동기식 요약 요청 대신 서버에 보관되는 작업을 시작한다.
Qwen 모델과 자체 SearXNG를 유지하며 외부 유료 검색 API를 요구하지 않는다.

1. 질문의 전체 범위와 조사 항목·보고서 목차를 작성한다.
2. 허용된 내부 자료·DB와 공개 웹을 검색한다. 중복 검색은 재실행하지 않는다.
3. 검색 결과를 선별하고 HTML/PDF 원문을 확보한다. 확보한 문서가 실제 조사 범위에 속하는지 별도로 검토한다.
4. 원문을 구간으로 나누어 방법·실험 조건·비교 결과·한계·연대 근거를 추출한다.
5. 조사 항목의 부족한 근거를 항목별로 확인하고 최대 3차례 추가 검색·분석한다.
6. 각 장을 2–3개 세부 질문으로 나누어 작성한다. 세부 항목을 독립적으로 저장하고 문장·문단의 주장·수치·연대와 저자 귀속을 원문 문맥과 대조한 뒤 하나의 장으로 합친다.
7. 검토에 실패한 세부 항목은 두 차례 다시 작성한다. 계속 실패하면 해당 설명 대신 확인 가능한 원문 인용과 미확인 표시를 제공한다.
8. 각 장의 질문에 직접 답하는 근거가 있는지 먼저 판정한다. 부족한 장은 기초 설명으로 채우지 않고 미확인 항목을 짧게 표시한다.
9. 장마다 필요한 비교 표·연산도·비교도·연대표를 작성하고 원문과 대조한다. 검토를 통과한 시각 자료를 해당 장에 배치한다. 표와 그림은 따로 검토·재시도하여 유효한 그림이 잘못된 표 때문에 사라지지 않게 한다.
10. 검토를 통과한 세부 설명과 실제 인용 근거로 요약을 작성하고 상세 보고서·조사 범위·확인 한계·번호 인용을 함께 저장한다.

모델은 도구를 직접 실행하지 않는다. 호스트가 URL 검증, 검색, 원문 조회,
자료 권한, 인용 ID 및 원문 인용 일치를 관리한다. 각 모델 요청은 현재 단계만
수행하도록 별도의 사용자 지시를 포함한다. 문서 하나가 비교 질문 전체를
답하지 못한다는 이유로 원문을 제외하지 않도록 포함 여부와 근거 충족 여부를 구분한다.

## 장시간 실행과 복구

- 기존 계정별 `notion_ai/chats.db`의 operation payload를 재사용한다. 테이블 변경은 없다.
- 원문·근거·진행 상태는 기존 계정별 Fernet 키로 암호화하고 압축해서 저장한다.
- 상태는 queued → processing → completed이며 paused, cancelled, failed를 지원한다.
- 한 단계마다 실행권을 획득한다. 실행권은 180초이며 활동 중 20초 간격으로 갱신한다.
- 기존 일반 채팅의 600초 제한은 유지한다. 심층 리서치에는 그 고정 제한을 적용하지 않는다.
- 브라우저를 닫거나 새로고침해도 서버 작업은 계속된다. 서버 재시작 후 대기 작업과 만료된 실행권의 작업은 저장한 단계부터 이어간다.
- 작업 실행권의 토큰·상태·기한을 확인하므로 오래된 프로세스가 새 작업의 결과를 덮어쓸 수 없다.
- 기본 전체 시간 예산은 2시간이다. `CODE_ASSIST_RESEARCH_MAX_SECONDS`로 900–21600초 범위에서 설정한다. 초과하면 중간 결과를 저장하고 일시 중단하며, 사용자의 ‘이어 조사’는 새 시간 예산으로 계속한다.
- 연구 요청의 모델 응답 대기는 180초까지 허용한다. 이는 응답이 전혀 오지 않는 동안의 대기 한도이며, 연구 전체의 실행 시간이나 로그인 유효기간이 아니다. 다른 생성 모드는 기존 60초 대기를 유지한다.
- 계정 간에는 단계 단위로 순환한다. 한 서버 worker는 모델 호출 하나씩 처리한다. 다른 앱이 같은 로컬 모델을 사용하면 모델 대기가 발생할 수 있다.

## 권한과 웹 연결

현재 계정·대화 범위·페이지/Wiki/DB 접근 권한을 실행과 공개 조회 전에 확인한다.
다른 계정의 자료를 읽거나 외부 검색에 내부 발췌문·DB·대화 기록을 전달하지 않는다.
웹 후속 검색 계획은 사용자가 입력한 질문과 공개 웹 근거만 사용한다.

사용한 내부 본문 또는 Wiki revision이 변경되면 저장을 중단한다. 동일한 작업의
재개도 차단하여 변경된 내용과 이전 근거를 섞지 않는다. 사용하지 않은 개인
페이지의 추가만으로 진행 중인 조사를 중단하지 않는다. 권한을 잃은 참고 자료를
포함한 진행 작업도 대화 목록·본문에서 숨긴다.

웹 연결 스위치와 내 자료 검색 스위치는 기존 출처 메뉴에서 유지한다.
웹 검색을 끄면 외부 검색·원문 조회를 수행하지 않는다. 둘 다 끈 요청은 시작하지 않는다.
완료 보고서의 페이지 저장은 사용자의 명시적인 버튼 동작으로만 수행한다.

## 원문과 품질의 실제 한계

- 웹 문서 80개, 검색 36회, 저장 원문 10 MiB, 근거 6 MiB, 압축 전 checkpoint 32 MiB로 제한한다.
- 웹 원문과 허용된 내부 페이지는 문서당 최대 500 kB의 텍스트를 보관한다. PDF는 최대 200쪽, 응답 파일은 최대 16 MiB다.
- 48구간 이하인 문서는 모든 구간을 분석한다. 더 긴 문서는 우선 24구간을 분석하고 근거가 부족하면 조사 회차마다 12구간씩 확대한다. 전체 분석 여부를 출처별로 표시한다.
- Wiki는 현재 검색 계약이 제공한 발췌문을 참고한다. 첨부파일·동기화 원본·인접 페이지를 자동으로 읽지 않는다.
- PDF의 줄바꿈을 유지하는 연속 인용 구간으로 실험 조건이 숫자에서 분리되지 않도록 한다. 이미지 PDF나 일부 글자·수식 추출 실패는 표시한다.
- PDF 인용 위치는 실제 인용문이 걸치는 쪽 범위로 표시한다. 앞뒤 문맥 확장이 다음 쪽까지 이어지면 시작 쪽만으로 표기하지 않는다.
- 짧은 인용은 원문 앞뒤의 연속 문맥으로 확장하고 원래의 인용 조각을 함께 보관한다. 확장 인용도 원문에 존재하는 문자열이다.
- 검토 문단을 나눌 때 인용 ID를 자르지 않으며 표의 열 이름을 보존한다. 다음 표의 설명을 앞 표의 숫자에 잘못 붙이지 않도록 원문 문맥을 함께 확인한다.
- 작성·검토 단계에 원문의 제목·저자 부분도 전달한다. 원문이 인용한 선행 논문의 저자와 해당 원문의 저자를 구분하며, 긴 문단은 문장 경계에서 나누어 귀속 오류도 검토한다.
- 실제 Qwen 검증에서 발견한 문장 중단 후 빈 줄 반복과 설명 문장 속 내부 근거 별칭 노출은 서버가 먼저 거부한다. 모델 검토의 찬성과 관계없이 재작성하며, 실패한 초안에는 반복된 후행 공백을 제거해 전달한다.
- 일정 길이 이상의 응답은 마지막 문장의 종결도 확인한다. 근거 검토용 발췌문의 문장 경계와 응답 전체의 미완성 문장을 구분하며, 재작성은 기존 초안에 덧붙이지 않고 완결된 한 편으로 교체하도록 한다. 수식·표·코드로 끝나는 경우도 지원한다.
- 수식이 있는 세부 답변은 원문 검토 외에 수식과 설명의 일관성을 별도로 확인한다. 식 안쪽부터 바깥쪽으로 연산 순서를 읽어 입력 변환·비선형 활성화·최종 사영의 순서를 혼동한 설명을 재작성한다.
- 단순한 활성화 함수·벡터 투영 수식은 연산자 배치와 명시적인 ‘먼저·마지막’ 서술을 서버도 대조한다. 모델 검토가 잘못 찬성해도 이 모순을 통과시키지 않는다. 복수의 서로 다른 식이나 복잡한 수식은 기존 문맥 기반 수학 검토를 사용하며, 형식적인 수학 증명기는 아니다.
- 모델이 생성하는 세부 답변은 최대 1,200자, 요약은 최대 800자로 출력 한도를 정한다. 남은 문맥이 작으면 각 응답의 길이 제한을 더 줄이고 JSON을 닫을 여유를 확보한다. 하나의 장은 여러 세부 답변을 합치므로 보고서 전체에 이 길이 제한을 적용하는 것은 아니다. 검토 실패 시 보여 주는 원문 인용은 별도로 포함한다.
- 실제 작성 길이는 한도의 80%를 목표로 지시해 마지막 문장을 마칠 여유를 둔다. 수치의 순위가 고정된다는 주장과 수치 자체가 고정된다는 주장을 구분하도록 작성·검토한다.
- 불변·독립·보편·항상 등의 적용 범위 주장은 별도로 모아 원문의 도입부와 근거로 개념적 함의를 검토한다. 올바른 수식 설명이 함께 있다는 이유로 잘못된 일반화를 통과시키지 않도록 한다. 재작성에는 이전 초안과 검토 의견을 함께 제공한다.
- 개념 검토에서 주장과 증명의 대상을 따로 분류한다. 순위에서 수치의 불변성을 도출하거나 점수 함수의 성질을 전체 모델의 성질로 바꾸는 경우 서버도 거부한다. 수치의 불변성에 대한 미지원 판정은 후속 검토의 찬성만으로 번복하지 않는다. 이 보수적 처리로 완성하지 못한 설명은 일부 확인으로 남을 수 있다.
- 입력 조건도 쿼리·키·이웃 집합으로 따로 분류한다. 원문이 쿼리에 따른 순위를 설명하는데 답변이 이웃 집합 변화로 바꿔 설명하면 검토의 찬성만으로 통과시키지 않는다. 두 방법에 공통인 속성을 차이를 정의하는 근거로 사용하지 않도록 한다.
- 정적 어텐션 설명에서 순위와 수치를 구분하지 않고 어텐션 가중치가 고정되거나 재계산되지 못한다고 서술하면 서버가 명확한 재작성을 요구한다. LaTeX뿐 아니라 인라인 코드로 작성한 수식도 별도 수학 검토를 수행한다.
- 부정적인 검토 의견은 원문과 다시 대조한다. 검토기가 원문에 없는 조건을 주장하거나 원문과 일치한다고 인정한 내용을 오류로 처리하면 해당 의견을 제외한다. 실제 오류를 지적한 의견은 유지해 재작성한다.
- 모델이 묶어서 반환한 유효한 인용을 개별 인용으로 정규화한다. 인용 사용 목록은 본문에서 서버가 계산하며, 공급하지 않은 출처 ID는 차단한다.
- 세부 답변 작성 시 서버가 해당 요청에만 유효한 `E1`, `E2` 등의 짧은 별칭을 제공한다. 답변의 별칭은 서버가 원래 해시 근거 ID로 연결하고 최종 보고서에서 전체 번호로 변환한다. 별칭의 순서를 추측하지 않으며, 알려진 번호와 미지의 번호를 섞은 답변도 차단한다.
- 검색 발췌문·초록·확보한 본문·일부 원문을 구분한다. 초록과 검색 발췌문만으로 조사 항목을 충분히 확인했다고 처리하지 않는다.
- 완성한 장과 내부·웹 근거를 함께 확인해 최종 조사 범위를 다시 판정한다. 이 단계에서는 검색어를 생성하지 않아 내부 자료가 웹 검색으로 전송되지 않는다. 발췌문·초록만 확보한 항목은 모델의 판정과 관계없이 일부 확인으로 제한한다.
- 모델 문맥에는 단계별 필요한 근거만 넣는다. 확인한 로컬 Qwen의 모든 리서치 단계에서 `/apply-template`·`/tokenize`로 실제 입력 토큰을 확인한다. 실패하면 선언된 context_window를 기준으로 보수적인 입력 추정과 출력 여유를 사용하며 실제 토큰 한도는 모델 서버가 적용한다. 외부 서버에 토큰 계산을 요청하지 않는다.
- 확인한 로컬 Qwen 서버는 보고서 작성·근거 검토 요청에서만 추론을 켠다. 토큰 계산과 추론 활성화는 별개다. `CODE_ASSIST_RESEARCH_LOCAL_REASONING=1`과 loopback Qwen URL이 필요하며 일반 채팅에는 적용하지 않는다.
- 추론 내용은 저장·화면 출력하지 않는다. 해당 요청에서 받은 completion ID만 사용해 `/v1/chat/completions/control`의 `reasoning_end`를 호출하고 최종 JSON을 쓸 공간을 남긴다. 서버 전체 설정이나 다른 요청의 추론을 바꾸지 않는다. 이 기능은 실제 로컬 서버에서 검증했고, API 규격은 [llama.cpp 서버 문서](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)를 따른다.
- 근거 검토에는 해당 문단이 인용한 근거를 모두 전달한다. 작성 때 공급한 제한된 후보 중 일부를 검토에서 누락해 존재하는 인용을 잘못 거부하지 않는다.
- 작성에 필요한 근거를 고를 때 보관한 후보 전체의 설명과 원문 인용을 비교한다. 원문 뒤쪽의 관련 구간도 후보에 포함하고, 선택 후에 문맥 예산과 출처당 수량 제한을 적용한다.
- 추출 단계의 장 번호는 관련성 힌트로 사용한다. 같은 조사 범위의 다른 장에 분류된 근거도 재사용할 수 있다. 수식·연산 순서 질문에서는 실제 연산자와 수식이 있는 원문을 우선하며, 초기 조사 때의 ‘수식 미확보’ 설명을 작성 단계에 그대로 전달하지 않는다.
- 동일 모델의 근거 검토는 사실의 수학적 보증이 아니다. 불확실한 결과와 조사 누락을 보고서에 표시한다. 검색 접근성과 원문 추출 품질에 따라 결과는 달라진다.

## API와 UI

`POST /api/notion/ai-home/conversations/<id>/research`는 작업을 시작하거나
`operation_id`와 `action: pause|resume|cancel`로 제어한다.
`GET /api/notion/ai-home/conversations/<id>`는 안전하게 공개한 `research_job`을 포함한다.
기존 messages 및 messages/stream의 research 요청도 이 작업 방식으로 연결한다.
같은 operation ID와 동일 요청은 재실행하지 않으며 다른 요청으로 재사용하면 409다.

UI는 단계·경과 시간·검색/자료/근거 수, 중단·재개·취소와 검토 전 초안을 표시한다.
완료 후 요약, 접을 수 있는 전체 보고서, 목차, 번호 인용, 출처별 확인 범위,
Markdown 다운로드, 페이지 저장을 제공한다. 갱신 중 보고서의 펼친 상태와 스크롤을 유지한다.
다운로드와 저장한 페이지의 출처 목록도 본문의 인용 번호를 유지하며 원문 URL·위치·인용을 포함한다.

## admin 실패 복구와 보고서 시각 자료 — 추가 수정

운영 admin의 실패한 요청은 ‘graph attention network에 대해서 자세히 리서치하고
최근 동향과 함께 어떤식으로 발전해왔는지 자세히 기술하는 리포트를 만들어줘.’다.
읽기 전용 진단과 서버 로그에서 원문 분석 단계의
`research step context exceeds model capacity`가 동일 입력으로 3회 반복된 것을
확인했다. 긴 한국어 조사 질문과 원문, 원문에서 만든 인용 후보를 중복 전송했고,
추론을 끈 분석 요청은 실제 토큰 계산을 사용하지 않아 한도 추정이 과도했다.

분석 요청에는 원문을 중복해서 넣지 않고 연속 인용 후보와 짧은 `quote_id`를
전달한다. 모델이 반환한 ID는 서버가 원래 인용 문자열로 연결한다. 실제 토큰과
출력 여유가 부족하면 구간을 절반으로 나누고 자식 구간을 체크포인트에 저장한다.
어떤 문자도 버리지 않으며 PDF 위치도 다시 계산한다. 같은 과대 입력의 반복
실패 대신 다음 단계에서 작은 구간을 분석한다.

최신 10322 반영 후 운영 화면의 ‘이어 조사’를 실행했다. 기존 실패 자료가
분석을 통과했고, 자료 7개·근거 10개를 확보하여 보고서 작성·검토 단계로 진행했다.
최종 상태는 아직 `processing`이며 오류와 단계 실패 횟수는 각각 빈 값과 0이다.
운영 요청은 내 자료 검색 켜짐·웹 검색 꺼짐이다. 웹 검색 0회는 오류가 아니라
선택한 조사 범위이며, 최신 공개 동향을 충분히 조사했다고 간주하지 않는다.
운영 DB를 테스트 fixture로 쓰거나 직접 수정하지 않았다.

진행 표시의 카드 테두리·배경·둥근 프레임을 없애고 간결한 상태 문장과 수치,
중단·취소 동작으로 표시한다. 실제 운영 화면에서 테두리 `0px`, 배경 투명과
진행 갱신을 Computer Use로 확인했다.

첫 `visuals` 구현은 보고서 전체에서 비교 표·도식을 한 번 생성했다. 현재는
각 장에서 최대 6행 비교 표와 최대 3개 묶음·7개 노드의 도식을 생성한다.
모든 행·흐름에는 제공된 근거 ID가 필요하다. 없는 수치나 그래프를 만들지 않도록
지시하고 근거 검토를 거친다. 서버는 자료 확보 상태·분석 구간 수를 별도 표로
표시한다. 도식은 안전하게 이스케이프한 짧은 레이블과 기존 오프라인 수식
렌더러를 사용하며 모델의 HTML·SVG·실행 코드를 사용하지 않는다.

실제 Qwen의 첫 도식은 GAT의 내적·활성화 순서를 뒤집었고 모델 검토도 이를
놓쳤다. 명시적으로 이름이 붙은 단일 활성화·벡터 투영 수식에 대해 서버가
원문 연산자 순서와 화살표 순서를 대조하는 제한된 검사를 추가해 해당 후보를
거부했다. 임의의 수식이나 모든 도식에 대한 증명은 아니며, 다른 경우에는
문맥에 따른 모델 검토와 일부 확인 표시가 필요하다.

기존 격리 계정의 완료된 GAT/GATv2 보고서·근거에 새 시각 자료 단계를 실제
Qwen으로 실행한 뒤 올바른 비교 표와 두 흐름의 연산 순서도를 확인했다.
이는 새 요청의 전체 조사 시간을 재측정한 검증이 아니다. Computer Use로
최신 보고서의 표 2개, 도식 1개와 수식 22개 렌더링을 확인했다. Markdown
버튼으로 다운로드한 파일에도 표·도식·수식·번호 출처 23개·PDF 쪽 범위가
유지된다. 페이지 저장 후 열어 네이티브 표 2개, 수식 도식 1개와 출처 23번을
확인했다. 표 셀의 수식 원문도 보존되지만 네이티브 표 편집 셀에서는 원문
텍스트를 표시한다.

추가 검증 화면과 메타데이터는
`.dev/local-qwen/ui-evidence-20261007-deep-research-fix/`에 보관한다.
기존 완료 대화의 저장 본문을 다시 작성하지 않았으며, 테스트용 결과는
별도 OS Temp 저장소에 새 대화로 보관했다. 운영 계정의 인증 자료와
10521·8080·10324 프로세스는 변경되지 않았다.

## 섹션별 작성·시각 자료와 웹 재조사 — 추가 수정

운영 결과를 다시 읽어 다음 문제를 확인했다. 제목과 범위가 2017–2026년을
다룬다고 했지만 후속 연구의 근거가 없는 장에서도 원래 GAT 설명을 반복했다.
`over-smoothing`을 과적합으로 잘못 번역했고, 이전 그림은 독립적인 두 입력을
화살표로 연결하거나 그리지 않은 softmax·출력 단계를 설명에 포함했다.
웹 검색 꺼짐 외에도 근거 선택과 장별 작성·검토 문제가 함께 있었다.

현재 근거 선택은 질문과의 관련성을 문서 형식보다 먼저 적용한다. 관련 없는
오래된 PDF가 관련 있는 후속 연구의 학회 HTML 원문을 밀어내지 않는다.
장의 근거 적합성 판정은 직접 답변·일부 답변·미확보로 나누며, 같은 키워드가
있거나 원래 방법을 설명한다는 이유만으로 후속 개선·연대·실험의 근거로
인정하지 않도록 한다. 관련성이 확인된 출처의 다른 허용된 원문 구간은 세부
질문에 재사용할 수 있다. 이 판정은 의미 관련성 검사이며 접근 권한 검사를
대체하지 않는다.

미확보 장은 짧은 미확인 설명으로 남기고 기본 방법 설명을 반복하지 않는다.
검토 실패 시 보여 주는 인용도 2개·각 350자로 줄였다. 요약에는 설명 검토를
통과한 세부 항목의 근거만 제공한다. 보고서 기준일·요청한 조사 목표·실제 확인
범위를 구분하고, 미확인 항목이 있으면 제목에도 ‘추가 확인 필요’를 표시한다.
알려진 과적합(over-smoothing) 오표기는 모델 검토가 찬성해도 서버가 거부한다.
이는 모든 용어 오류를 자동으로 탐지한다는 의미는 아니다.

원문 확보 시 주요 학회 출판 페이지의 명시적인 `citation_pdf_url`을 따라 PDF를
읽는다. 임의의 참고문헌 링크는 따라가지 않는다. URL·DNS·TLS·리다이렉트 검증과
용량 한도·권한 재검사를 동일하게 적용한다. PDF 접근 실패 시 공개 HTML을
보존하고 제한을 표시한다. 공개 논문의 원문 접근 실패 시 제목으로 대체 원문을
검색하되 기존 검색 횟수·중복 제한을 유지하며 내부 발췌문이나 대화는 보내지 않는다.

시각 자료는 장별 체크포인트로 저장한다. 비교도는 독립적인 속성을 화살표 없이
표시하고, 과정도는 실제 순서를, 연대표는 확인한 발표 연도를 오름차순으로 표시한다.
모든 노드에 각각 근거 ID가 필요하고 해당 흐름의 근거에 포함돼야 한다.
모델이 새 요청에서 제공받는 짧은 별칭은 승인된 구성 요소를 저장할 때 원래
근거 ID로 변환한다. 재시도나 선택 순서 변경으로 승인된 그림의 인용이 다른
문서에 연결되지 않는다.

실제 Qwen 재검증에서 비교도라는 형식을 선택해도 `W`와 `aᵀ`의 위치를 혼동하고,
점수 함수의 근사 성질을 모델 전체의 성질처럼 표에 표시하는 오류가 발생했다.
명시적인 수식·모델 레이블에 대한 제한된 연산 순서 검사를 비교도에도 적용했고,
입력 변환과 출력 투영을 따로 대조한다. 보편 근사성 표에는 대상 함수와 조건을
명시하도록 요구한다. 캡션의 누락된 연산·독립 입력 간 화살표·불명확한 가중치
계산 전후 표현도 제한된 서버 검사로 거부한다. 여전히 일반적인 증명기는 아니다.

출처 스위치는 공통 버튼 최소 높이 28px 때문에 원이 위쪽으로 치우쳤다.
스위치 높이와 최소 높이를 18px로 맞췄고, 실제 브라우저에서 위·아래 여백 2px,
메뉴 행 높이 32px를 확인했다.

운영 admin의 기존 대화에서 웹 검색을 켜고 사용자가 요청한 연구사를 다시
조사하는 새 요청을 실제 UI로 전송했다. 기존 완료 보고서를 직접 다시 쓰지
않았다. 새 요청에는 내 자료 검색과 웹 검색이 모두 켜져 있다. 진행 상태는
`.dev/local-qwen/ui-evidence-20261007-deep-research-sections/`의 최종 검증 메타데이터에
별도로 기록한다. 기능 회귀 검증과 운영 재조사의 완료 여부를 구분한다.

시각 자료 검토는 표와 그림을 각각 수행한다. 표의 검토 실패 때문에 통과한
그림까지 버리지 않으며, 재시도에서는 이미 승인한 구성 요소를 유지한다.
그림을 안전하게 만들 수 없거나 장의 근거가 없으면 억지로 넣지 않고 그
한계를 표시한다. 작성·시각화 과정에서 모델 검토가 놓친 실제 오류를 확인해
검사 항목을 보강했으므로 모델의 자기 검토만으로 정확성을 보장하지 않는다.

기능 회귀 검사: 관련 Python 테스트 314개 통과(152.68초), 프런트엔드
Node 테스트 29개 통과(93.19ms). 검증은 섹션별 근거 적합성, 검토된 구성 요소
보존과 인용 ID 안정성, 수식 순서·번역 오류 거부, 원문 PDF 확보의 URL 보호를
포함한다. 이 숫자는 운영 보고서가 전체 연구사를 완성했다는 의미가 아니다.

그림과 표 생성도 각각 한 단계로 분리하고 로컬 Qwen의 제한된 reasoning을
사용한다. 일반 구성 요소 비교도에서는 제안된 레이블을 해당 노드의 인용에
실재하는 짧은 구절로 바꾼다. 연속으로 일치한 원문 단어만 사용하며 관사와
단·복수 차이만 맞춘다. 불일치 레이블은 제외하고, 그림의 수치·복잡도 표현도
해당 노드의 원문에 없으면 거부한다. 기존 모델의 비용·한계 문구를 새로운
모델의 특성으로 오해하지 않도록 구성 요소 그림에서는 제외한다. 수치 비교는
방법·조건을 함께 적은 표로 검토한다. 비교도 설명은 서버가 도식의 읽는 방식만
안내하며 모델의 별도 미검증 주장을 추가하지 않는다.

명시적인 `activation(aᵀ[W...])`와 `aᵀ activation(W...)` 점수 수식의 비교 질문은
서버가 원문의 이름·연산자와 인용 ID로 좁은 연산 도식을 구성한다. 새 연산,
정규화·집계·정리·성능 주장을 추가하지 않으며 복잡한 수식을 일반적으로 증명하는
기능은 아니다. 이 경로는 질문에 비교할 모델 이름과 연산 순서 또는 정적·동적
어텐션 비교가 명시된 경우만 적용해, 일반적인 수식·이론 질문이나 다른 장에
같은 GAT 도식을 반복하지 않는다. 실제 격리 검증에서 GAT/GATv2 그림은 이 경로, GraphGPS/Primphormer
그림은 Qwen 제안·원문 구절 선택·검토 경로로 확인했다. 승인된 두 그림과 실제
Qwen 비교 표를 재사용해 최종 화면·내보내기를 검증했다. 이 검증은 새 연구사를
처음부터 끝까지 생성한 시험이 아니다. Graph Transformer 표는 두 번의 시도에서
구성·복잡도·관계의 검토를 통과하지 못해 제외됐지만 승인된 그림은 유지된다.

원문 구절이 긴 레이블은 도식 안에서 줄바꿈하고 비교도 상자 사이에는 여백을
둔다. 표에서는 공통 `overflow-wrap:anywhere` 때문에 짧은 Method·GATv2까지
끊기던 현상을 셀의 `break-word`로 고쳤다. 실제 브라우저에서 첫 열 폭이
53.52px에서 67.80px로 늘고 단어가 유지되는 것을 확인했다. 마지막 도식 간격
수정 후 시각 자료 테스트 20개도 통과했다(1.62초).

Computer Use로 최종 검증 보고서의 장별 그림 2개·표 2개(연구 비교 1개,
자료 확보 상태 1개)를 확인했다. 다운로드한 Markdown에는 2열 도식 2개,
비교도 간격·번호 출처 10개·근거 미확보 장이 유지되며 원시 근거 ID는 없다.
페이지 저장 후에도 네이티브 표 2개·렌더링된 수식 도식 2개와 출처 10번을
확인했다. 네이티브 표 편집 셀은 수식 원문을 저장·표시한다는 기존 제한은 같다.

운영 재조사는 근거 273개를 확보한 뒤 긴 한글 후속 검색 질문에서 결과가
없고 일부 엔진이 요청 제한·CAPTCHA 상태라 중단됐다. 같은 시점에 간결한
영어 논문명 검색은 결과 20개를 반환했으므로 검색 서비스 전체의 연결 실패는
아니었다. 검색 실패는 작업 이력과 한계에 남기고 기존 원문·다른 작업은 계속한다.
실패한 한글 공개 검색어에는 입력된 그 검색어만으로 영어 키워드를 만드는
별도 단계를 한 번 추가한다. 내부 발췌문·계정 정보·대화 이력은 제공하지 않고
검색 횟수·중복 한도와 권한 취소 검사는 그대로 적용한다. 새 누락 조사 질의도
간결한 영어 학술 키워드를 쓰도록 지시한다. 실제 운영 UI에서 이어 조사를 누른
뒤 검색 21회·원문 선별 단계로 진행하고 오류와 실패 횟수가 0으로 복귀한 것을
확인했다. 운영 보고서의 최종 완성 상태는 검증 JSON의 최신 스냅샷을 참조한다.

운영 작성 중 장 전체에는 근거가 있어도 ‘초기 실험 결과’ 세부 질문을 기본
메커니즘으로 채우는 경우를 추가 확인했다. 세부 질문에도 원문 인용만으로
답변 가능 여부를 확인하고 결과를 체크포인트에 보존한다. 근거가 없는 질문은
서버의 짧은 ‘근거 미확보’ 문구로 끝내며 기본 설명을 생성하지 않는다. 장의
검사가 선택한 일부 출처는 전체 허용 출처 목록이 아니므로, 다른 이미 권한이
확인된 관련 원문도 세부 질문에 활용한다. 재시도 때 검토를 통과한 유용한
부분과 원문 수집 결과는 유지한다. 진행 중인 구형 작업의 미완료 설명·근거
부족 문구와 반복 설명이 섞인 부분은 새 질문 검사로 다시 작성한다. 완료된
과거 보고서를 자동으로 바꾸지는 않는다.

실제 로컬 Qwen에 GAT 원논문의 구조 설명 인용만 제공하고 Cora 정확도와
실험 조건을 요청한 격리 검증에서 ‘근거 미확보’를 반환했고 기본 설명을
반복하지 않았다. 모델 자기 검토만으로 임의의 학술적 정확성을 보장하는
것은 아니며, 운영 보고서 전체의 최종 검토와 구분한다.

마지막 이어쓰기 수정 이후 연구 작업 테스트 82개를 다시 통과했다(101.35초).
전체 묶음 314개와 마지막 재검증을 합쳐 서로 다른 Python 사례는 315개다.
운영 UI에서 재개한 뒤 초기 실험 부분은 Cora·Citeseer·Pubmed·PPI와 원문의
실험 설정 근거를 사용하고 수치·한계의 미확보 범위를 구분하는 설명으로
다시 작성됐다. 이 시점에는 다른 장의 작성과 전체 보고서 검토가 진행 중이다.
