# 말끝 우선 음성 수집 및 댓글 패널 교정

2026-09-13. 사용자 후속 요청 범위의 frontend 변경이다. AGENTS, SBE schema,
hot contract, 기존 immutable receipt와 전체 goal 완료 상태는 변경하지 않는다.

## 음성 수집

- 로컬 Whisper의 새 기본값: `말끝 우선 · 10~20초`.
- 최소 10초를 수집하고 연속 800ms 무음에서 전송한다. 멈추지 않는 소리/음악은
  최대 20초에서 나눈다. 사용자가 멈추거나 일시정지하면 짧은 마지막 구간도 보존한다.
- 실제 구현은 AudioWorklet 안의 20ms RMS 에너지 측정과 제한된 noise-floor 추적이다.
  새 신경망 VAD 또는 의미 완결 판별 LLM을 설치/호출한 것이 아니다. 전사 서버의 기존
  Silero VAD는 전송된 구간 안에서만 계속 동작한다. 브라우저의 음향적 무음과 의미상
  문장 끝은 다를 수 있으며, 배경음이 계속 있거나 음량이 작으면 오판/20초 상한이 가능하다.
- 모든 입력 PCM 샘플을 순서대로 한 번씩 전송한다. 무음·조용한 음성도 버리지 않는다.
  구간 길이와 누적 offset은 실제 샘플 수를 사용한다. 음성 시작/범위 격리는 직전
  recording-scope 수정 그대로 유지한다.
- 녹음 전 `고정 · 12초` 또는 기존 `고정 · 10초`를 선택할 수 있다. 선택은 해당 노트의
  `audio_chunk_mode`/`audio_chunk_seconds`에 저장된다. 새 모드 필드가 없는 기존 노트는
  다음 녹음부터 말끝 우선 기본값을 사용한다. 실행 중 수집 모드는 바뀌지 않는다.
- local_only가 아닌 기존 STT provider는 기존 chunk_seconds 고정 경로를 유지한다.
- 별도 LLM 판단/네트워크 호출은 추가하지 않는다. 전사와 번역의 모델 우선순위,
  Codex argument gate, 자동 번역 활성화 권한, API 인증과 저장 범위는 바꾸지 않는다.
- 이 모드는 2초 간격으로 회귀하지 않으며, 번역 응답이 일정 주기로 도착한다는 보장은 없다.

## 댓글 조사와 교정

공식 Notion 문서는 페이지 상단 토론, 문장 옆 인라인 댓글, 상단 아이콘으로 여는
전체 댓글 패널을 구분한다:
https://www.notion.com/help/comments-mentions-and-reminders

실제 Chrome 사용자 화면을 Computer Use로 읽기 전용 확인했다. 기존 댓글 drawer는
left 374px / top 328px / height 238px에 고정되며 overflow:hidden이었다.
실제 내용 높이 329px가 표시 높이 237px를 넘었고 닫기 버튼이 숨겨져 있었다.
본문 편집기에 196px margin을 더하는 CSS도 제거했다.

- 상단 댓글 버튼은 폭 최대 380px, 화면 오른쪽 패널을 연다. 작은 화면에서도 뷰포트
  안에 들어온다. 헤더/닫기/입력/보내기는 유지하고 댓글 목록만 독립 스크롤한다.
- 긴 문자열은 줄바꿈하며 답글은 원 댓글 아래 들여쓰기/연결선으로 표시한다.
  전송된 답글이 보이도록 목록 안에서 스크롤하고 입력 포커스를 돌려준다.
- 닫기 버튼, 같은 상단 버튼 재클릭, 패널 바깥 클릭, ESC로 닫는다. 닫기만으로
  초안은 지우지 않는다. 이 닫기 선택 전체가 공식 Notion과 픽셀/행동 동일하다는
  검증을 주장하지 않는다.
- 원 댓글 삭제 후 loadComments가 reply parent를 자동 해제하던 경로를 없앴다.
  삭제/접근 불가 대상은 초안과 parent를 유지하고 보내기를 막는다. 새 댓글로 전환하려면
  사용자가 `답글 대상 취소`를 명시적으로 선택해야 한다. 해결된 대상도 다시 열기 전에는
  보내기를 막으며, 답글이 새 root로 승격되지 않는다.
- 댓글 목록 요청은 페이지/요청 generation을 확인하여 늦은 다른 페이지 응답을 무시한다.
  초안은 페이지별 메모리에 분리하고 전송 중 중복 submit을 막는다.
- 댓글 저장소/서버 계약은 수정하지 않았다. 기존에 잘못 작성된 사용자 댓글을 추정으로
  재연결하거나 삭제하지 않는다.

## 검증

- 교정 전 새 댓글 테스트: 위치/잘림과 삭제된 답글 대상의 자동 해제 재현 실패 2개,
  기본 답글 저장/다시 열기 경로는 통과 1개. 실패가 단순 backend parent 지원 부재는
  아니라는 근거로 구분했다.
- 교정 후 댓글 browser 4개 + routes/store 회귀: **26 passed, 79.61초**.
  장문 답글이 실제 viewport 안에 보이는지, 재로드/해결/다시 열기/삭제 시 연결,
  초안 보존과 네 가지 닫기, 작은 화면 배치를 검증했다.
- Node endpointing / meeting audio / AI notes / notes translation / UI runtime 통과.
  PCM byte 비교로 sample 유실/중복 없음, 12.8초 말끝, 20초 상한, 짧은 숨 고르기,
  10/12초 고정 복귀, pause/resume/종료 tail을 검증했다.
- 합성 무음 입력 생성 시 음수 0의 바이트 차이로 대형 assertion diff를 생성하던
  테스트 프로세스 한 개를 정확한 command line 확인 후 종료했다. fixture를 양수 0으로
  정규화하고 bounded byte-equality assertion으로 교정하여 통과했다.
  사용자 녹음/서버 프로세스를 종료하거나 테스트에 사용하지 않았다.
- 음성/번역 browser 첫 묶음: **17 passed / 1 failed, 397.06초**.
  두 20초 구간을 40초 안에 번역/저장까지 기다리던 이전 timeout 계약 한 개가 실패했다.
  20초 상한 2개와 처리 overhead를 수용하도록 55초로 교정해 별도로 재검증한다.
  다른 새 browser 검증은 실제 WAV 업로드 길이 약 12.8초(말끝) / 20초(연속 소리),
  이전 미번역 이력 격리, 별도 LLM 호출 없음, 고정 12초 복귀/저장/재로드를 포함한다.
- 합성 UI 캡처를 직접 열어 확인했다:
  `.tmp/notion-speech-comments-20260913/comments-right-drawer-long-reply.png`,
  `.tmp/notion-speech-comments-20260913/speech-boundary-picker-and-fixed-rollback.png`.
- 실제 마이크/시스템 오디오를 테스트 fixture로 사용하거나 사용자 내용을 저장하지 않았다.

## 실제 탭 적용

사용자가 `회의 종료 후 새로고침 승인`으로 승인했다. 기존 댓글 창이 회의 종료
버튼 위를 가리는 것을 확인하여 ESC로 닫고 종료했다. 남은 전사 1구간과 마지막 번역이
완료되고 미번역 0자인 것을 확인한 뒤 자동 번역을 껐다. 이 문서 작성 시점에는
마지막 회귀 테스트를 기다리는 동안 새로고침을 보류하고 있다.
정적 frontend만 변경했으므로 10011/10322/10323 프로세스는 재시작할 필요가 없다.

### 최종 검증 및 승인 적용 결과

- timeout 계약을 교정한 마지막 양방향 통역 browser: **1 passed, 51.96초**.
  위 17개와 합쳐 음성/번역의 서로 다른 **18개 시나리오 통과**다.
  전체 묶음이 처음부터 모두 통과했다고 소급 기록하지 않는다.
- 사용자 Chrome 탭을 새로고침하고 실제 로드된 DOM에서 `speech` 기본값,
  `고정 · 12초`/`고정 · 10초` 선택, `이번 녹음만` 번역 범위를 확인했다.
- 새로고침 직전 원문과 번역을 이후 DOM 값과 비교하여 둘 다 완전히 보존된 것을
  확인했다. 실제 댓글 2개도 다시 로드됐으며 사용자 댓글은 수정/삭제하지 않았다.
- 실제 댓글 패널: right edge에 폭 380px, top 45px, 당시 높이 818px.
  닫기 버튼 표시, 상단 버튼 재클릭 닫기, 본문 클릭 닫기를 확인했다.
  격리 테스트에서 검증한 답글 추가/삭제/해결을 실제 사용자 페이지에서 재실행하지 않았다.
- 사용자 탭은 녹음 종료, 자동 번역 해제, 회의 시작 가능 상태로 남겼다.
  사용자가 회의를 시작하고 자동 번역을 켜면 새 수집 모드를 사용한다.
- 서비스 10011 PID 30616, 10322 PID 25100, 10323 PID 39592는 유지했다.
  서버 재시작이나 실제 STT/LLM 설정 변경은 하지 않았다.
