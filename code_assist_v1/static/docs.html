Second Brain Agent 사용자 가이드

Second Brain Agent는 대화, 문서, 코드 파일, 개인 지식 저장소, Notion 스타일 문서 작업공간을 함께 사용하는 지식 기반 작업 에이전트입니다.

개요

서비스기본 주소역할
Second Brain Agenthttp://localhost:10011채팅, 지식 검색, 문서 업로드, 세션 관리
Notion Workspacehttp://localhost:10012개인 문서 작성, 공유 페이지, 채팅/지식 연결

답변에는 대화 기록, Second Brain, Workspace 파일, Notion 페이지 context가 필요에 따라 함께 들어갑니다.

중요

계정별 데이터는 분리됩니다. 다른 사용자의 채팅, Notion 문서, Second Brain source는 기본적으로 보이지 않습니다.

계정과 접속

  • 10011과 10012는 같은 로그인 계정을 사용합니다.
  • 쿠키는 호스트 기준으로 공유됩니다. localhost:10011로 로그인했다면 localhost:10012로 여세요.
  • 처음 사용하는 Notion 계정은 Second Brain 템플릿 만들기로 기본 페이지를 만들 수 있습니다.

채팅

  1. 모델을 선택합니다. 잘 모르면 기본값을 사용합니다.
  2. 필요한 경우 스킬, Second Brain, Workspace 파일을 켭니다.
  3. 질문을 입력하고 Enter로 전송합니다. 줄바꿈은 Shift + Enter입니다.
  4. 응답을 멈추려면 Esc 또는 중단 버튼을 사용합니다.

수식은 읽기 쉬운 Unicode/일반 표기로 표현되고, 수식 덩어리는 하이라이트와 줄바꿈으로 렌더링됩니다.

세션

명령동작
/status모델, context window, 추정 토큰, 남은 context를 표시합니다.
/compact오래된 대화를 summary로 압축하고 최근 메시지만 유지합니다.
/clear현재 화면과 대화 context를 비웁니다. 저장된 과거 세션 삭제와는 다릅니다.

세션 명령 상세

/status는 지금 세션이 모델 context를 얼마나 쓰고 있는지 확인할 때 사용합니다. 모델명, context window, 추정 토큰, 남은 토큰, compact 권장 상태, compact summary 사용 여부를 보여줍니다. 답변이 길어지거나 파일/Notion/Second Brain context를 많이 붙인 상태에서 먼저 확인하면 좋습니다.

/compact는 대화가 길어졌을 때 오래된 메시지를 요약본으로 압축합니다. 이후 요청에는 compact summary + 최근 메시지가 들어가므로 context window를 아낄 수 있습니다. 원본 세션 기록을 삭제하는 기능은 아니며, 오래된 대화의 세부 문장보다 결정사항과 진행 맥락을 유지하는 데 목적이 있습니다.

/clear는 현재 화면과 모델에 전달되는 대화 context를 비우고 새 대화 상태로 돌아갑니다. 저장된 과거 세션, Second Brain 지식, Workspace 파일, 장기기억을 삭제하지 않습니다. 주제가 완전히 바뀌었거나 이전 대화가 답변에 섞이면 안 될 때 사용합니다.

자동 compact는 context 65% 이상 경고, 75% 이상 후보, 85% 이상 강제 기준으로 동작합니다.

Harness와 장기기억

Second Brain Agent는 공식 지식, 장기기억, Workspace 임시 인덱스를 분리해서 사용합니다.

계층역할저장 위치
Second Brain공식 지식, 승인 source, 업무 규칙, 문서 근거code_assist_v1/knowledge/<user>/wiki/
장기기억사용자 선호, 프로젝트 관습, 반복되는 작업 방식code_assist_v1/user_data/<user>/memory/
Workspace 임시 인덱스현재 세션/프로젝트에 올린 임시 문서 검색code_assist_v1/user_data/<user>/projects/

장기기억은 공식 지식이 아닙니다. Second Brain source, 스펙, 원문 근거와 충돌하면 Second Brain이 우선합니다.

장기기억

장기기억은 Mem0와 비슷한 흐름으로 동작합니다. 모든 대화를 통째로 외우는 기능이 아니라, 반복해서 쓸 사용자 선호, 프로젝트 관습, 결정사항, 오류 대응 규칙만 작게 저장하고 질문과 관련 있을 때만 꺼내 쓰는 방식입니다.

  1. 사용자의 입력에서 저장 신호를 찾습니다.
  2. 저장할 만한 문장이면 preference, project, decision, lesson 같은 유형으로 분류합니다.
  3. 계정별 장기기억 파일에 JSONL 형태로 저장합니다.
  4. 다음 질문을 받을 때 현재 질문과 관련 있는 기억만 검색합니다.
  5. 검색된 기억은 낮은 우선순위 context로 답변에 들어갑니다.
  6. Second Brain source, 스펙, 원문 근거와 충돌하면 장기기억보다 공식 지식이 우선합니다.
code_assist_v1/user_data/<user>/memory/
  memories.jsonl
  events.jsonl

memories.jsonl에는 현재 사용할 수 있는 기억이 저장되고, events.jsonl에는 저장/수정/삭제 같은 이력이 남습니다. 입력창의 기억 버튼은 이번 답변에 장기기억을 참고할지 결정하며, 끄더라도 저장된 기억은 삭제되지 않습니다.

어떻게 기억시키나

장기기억에 저장하고 싶은 내용은 평소처럼 말하되, 저장 의도가 드러나게 쓰는 것이 가장 안정적입니다.

입력 방식예시결과
명시 저장기억해. 나는 답변을 짧고 실무적으로 받는 걸 선호해.사용자 선호로 저장됩니다.
앞으로의 규칙앞으로 논문 설명은 수식, 변수 정의, 직관을 같이 정리해줘.반복 답변 규칙으로 저장됩니다.
항상 적용항상 포트는 10011을 먼저 확인해.프로젝트/작업 관습으로 저장될 수 있습니다.
프로젝트 규칙이 프로젝트에서는 Notion 초안은 확정 후 Second Brain으로 보낸다.프로젝트 기억으로 저장됩니다.
결정사항오늘 결정: 문서 업로드 후 sources를 정본으로 사용한다.결정 기억으로 저장됩니다.
교훈/주의다음부터 WinError 2가 나면 실행 파일 경로를 먼저 확인한다.반복 오류 대응 기억으로 저장됩니다.

저장 신호로 인식되는 대표 표현은 기억해, remember, 저장해, 앞으로, 항상, 기본적으로입니다. 질문이나 일회성 명령은 기본적으로 저장하지 않습니다.

어떻게 사용되나

장기기억은 답변 전에 현재 질문과 관련 있는 항목만 검색되어 context에 들어갑니다. 예를 들어 PDF 논문 설명을 요청했을 때, 과거에 논문 설명은 수식과 변수 정의를 같이 정리하라고 저장했다면 그 기억이 함께 들어갈 수 있습니다.

응답 하단 메타에 기억=1처럼 표시되면 이번 답변에 1개의 장기기억이 참고된 것입니다. 기억+active처럼 보이면 새 기억이 저장된 것입니다.

좋은 기억 후보저장하지 않는 것이 좋은 내용
답변 언어/길이 선호, 프로젝트 포트/명령, 반복되는 오류 대응, 검증된 작업 규칙단발성 질문, 임시 테스트, 이번 턴에서만 필요한 UI 취향, 검증되지 않은 추측

기억하지 않게 하려면 이건 기억하지마, 저장하지마처럼 명시하세요. 잘못된 기억은 이전 규칙은 취소하고 앞으로는 ...처럼 새 규칙으로 덮어쓰는 방식이 안전합니다.

장기기억과 Second Brain은 용도가 다릅니다. 문서 근거가 필요한 지식은 Second Brain source로 저장하고, 답변 방식이나 반복 작업 선호는 장기기억에 저장하는 것이 좋습니다.

Agent Harness

Agent Harness는 사용자가 직접 다루는 버튼이 아니라, 매 요청마다 실행되는 내부 계획 레이어입니다. 질문을 보고 coding, second_brain, spec_driven, memory_aware 모드를 조합합니다.

Harness는 현재 채팅, Workspace 파일, 검색된 Second Brain source, graph 관계, 장기기억, 활성 스킬 순서로 context를 정리합니다. 응답 완료 메타에 project=2, 기억=1, mode=coding+second_brain처럼 표시되면 어떤 보조 context가 들어갔는지 알 수 있습니다.

모델

API 모델과 로컬 GGUF 모델을 사용할 수 있습니다. GGUF는 code_assist_v1/MODEL_GGUF/의 .gguf 파일을 자동 인식합니다.

GGUF는 128000 context를 목표로 로드하고, 메모리 상황에 따라 65536, 32768, 8192 순서로 fallback합니다. 실제 값은 /status에서 확인합니다.

Second Brain

Second Brain은 장기적으로 재사용할 업무 지식을 저장하는 canonical knowledge 저장소입니다.

knowledge/<user>/wiki/
  index.md
  log.md
  sources/
  assets/
  graph/
    graph.json
    backlinks.json
    pending_diffs.json
  wiki_index.sqlite
항목의미
sources/업로드, 대화 지식화, Notion publish 결과가 저장되는 source markdown
assets/PDF/PPTX/DOCX 등에서 추출한 이미지와 페이지 asset
index.md지식 지도
log.md업로드, graph update, 품질 점검 이력
graph.json승인된 source 간 관계

현재 정본은 sources/입니다. pages/는 legacy 호환용이며 새 지식 흐름에서는 사용하지 않습니다.

지식 등록

방법절차
문서 업로드지식 탭에서 자료 업로드
복수 문서 업로드여러 파일을 선택하면 각 파일이 단건 업로드처럼 순차 처리됩니다.
대화 지식화현재 세션에서 재사용 가능한 개념, 수식, 절차, 결정을 source markdown으로 정리합니다.
Notion publishNotion 페이지의 Second Brain 버튼으로 preview 확인 후 승인합니다.

지원 파일은 Markdown, TXT, source code, PDF, PPTX, DOCX, XLSX, Notebook입니다. 이미지와 슬라이드/페이지 asset은 assets/에 저장되고 source markdown에 링크됩니다.

Graph는 내부 LLM curator가 의미 관계를 판단한 뒤 충분히 강한 edge만 저장합니다. keyword overlap, tag overlap, term overlap 같은 약한 이유는 자동 저장하지 않습니다.

외부 도구에서 Markdown 만들어 가져오기

Google NotebookLM 같은 외부 도구에서 원문을 먼저 읽히고, Second Brain Agent에 올릴 Markdown을 만들 수 있습니다. 목표는 보기 좋은 요약이 아니라, source markdown, index, graph 판단에 잘 맞는 구조화 문서입니다.

NotebookLM이 canonical source markdown 같은 내부 용어를 완전히 이해할 필요는 없습니다. 중요한 것은 원문 근거, 핵심 주장, 용어, 수식, 표/그림, 출처 단서를 분리해서 Markdown으로 출력하게 만드는 것입니다.

원칙

원문 근거를 유지하고, 제목, 요약, 핵심 주장, 용어, 수식, 표, 출처를 분리하세요. 문서 간 연결 후보는 원문에서 명시된 선행 연구, 비교 대상, 참조 문서, 데이터셋, 표준, 방법론이 있을 때만 적습니다.

NotebookLM에 아래 프롬프트를 사용할 수 있습니다.

너는 원문 문서를 구조화된 Markdown 지식 문서로 정제하는 문서 정제자다.
이 Markdown은 Second Brain Agent에 업로드할 canonical source로 사용된다.

목표:
- 원문 문서의 핵심 지식, 근거, 용어, 수식, 표, 결정사항을 Second Brain Agent가 검색하고 graph 관계를 판단하기 좋은 Markdown으로 변환한다.
- 단순 요약이 아니라, 나중에 다른 문서와 연결될 수 있는 source markdown을 만든다.
- 원문에 없는 사실은 추가하지 않는다.

출력 형식:

# <문서의 명확한 제목>

---
source_type: external_markdown
original_title: <원문 제목>
original_author_or_org: <알 수 있으면 작성, 모르면 unknown>
original_date: <알 수 있으면 YYYY-MM-DD, 모르면 unknown>
created_for: Second Brain Agent import
verification_status: source_derived
---

## 1. Executive Summary
- 문서 전체를 5~8개 bullet로 요약한다.
- 각 bullet은 원문에서 확인 가능한 내용만 쓴다.

## 2. Key Concepts
| Concept | Definition | Source Evidence |
|---|---|---|
| 핵심 용어 | 원문 기반 정의 | 페이지/섹션/문단 단서 |

## 3. Core Claims
| Claim | Evidence | Caveat |
|---|---|---|
| 주장 | 원문 근거 | 조건, 한계, 예외 |

## 4. Methods / Process / Architecture
- 절차, 알고리즘, 시스템 구조, workflow가 있으면 단계별로 정리한다.
- 입력, 처리, 출력, 의존성을 분리한다.

## 5. Equations and Formal Definitions
- 수식은 Unicode/일반 표기로 읽기 쉽게 작성한다.
- 각 변수의 의미와 단위를 바로 아래에 설명한다.
- 원문 LaTeX가 중요하면 별도 줄에 `Original notation:`으로 보존한다.

## 6. Tables, Figures, and Assets
- 원문 figure/table을 빠뜨리지 말고 설명한다.
- 이미지를 직접 첨부할 수 없으면 `Figure <번호>: <내용과 의미>` 형식으로 남긴다.
- 표는 가능한 Markdown table로 재구성한다.

## 7. Decisions / Rules / Reusable Knowledge
- 업무 규칙, 설계 결정, 반복 사용 가능한 패턴을 bullet로 정리한다.
- 임시 의견과 확정 사실을 구분한다.

## 8. Related Topics and Graph Hints
다음은 Second Brain Agent가 graph 후보를 판단할 때 참고할 힌트다.
단일 문서만 보고 알 수 있는 범위에서만 작성한다.
원문에 선행 연구, 비교 대상, 참조 문서, 데이터셋, 표준, 방법론, 충돌 주장 등이 명시된 경우만 적는다.
확실하지 않으면 `No reliable graph hint from this single source.`라고 쓴다.

| Related Topic | Possible Relation | Reason |
|---|---|---|
| 관련 주제/문서명 | extends/supports/contradicts/related 중 하나 | 원문 기반 이유 |

## 9. Open Questions
- 원문만으로 확인되지 않는 부분
- 추가 문서가 필요한 부분
- 모호한 용어

## 10. Source Trace
- 가능한 경우 페이지, 섹션, 슬라이드 번호, 표 번호, figure 번호를 남긴다.
- 정확한 페이지 번호를 모르면 원문 내 heading이나 주변 문구를 남긴다.

작성 규칙:
- 원문에 없는 내용을 만들지 마라.
- 광고성 표현이나 중복 문장은 제거하라.
- 너무 짧은 bullet만 나열하지 말고, 재사용 가능한 지식 단위로 정리하라.
- 숫자, 날짜, 모델명, 논문명, 변수명은 원문과 다르게 바꾸지 마라.
- 한국어로 작성하되, 고유명사와 기술 용어는 원문 표기를 함께 유지하라.
- 최종 출력은 Markdown 본문만 제공하라.

이렇게 만든 .md 파일을 지식 업로드에 올리면, Agent는 다시 source 저장, index/log 갱신, graph 후보 검색, 내부 LLM curator 판단을 수행합니다. 외부 도구가 만든 관련 주제 표는 확정 graph가 아니라 판단 힌트로만 취급됩니다.

단일 문서만 NotebookLM에 넣는 경우, 기존 Second Brain 전체 지식과의 관계를 NotebookLM이 알 수 없습니다. 따라서 Related Topics는 문서 내부에서 명시적으로 드러난 관계만 적고, 실제 graph 연결은 Second Brain Agent의 내부 curator가 기존 source들과 비교해 다시 판단합니다.

Workspace

Workspace는 현재 세션에서 참고할 파일을 올리는 곳입니다. 문서형 파일은 현재 세션 검색용 임시 인덱스로도 들어갑니다.

  • 파일 업로드: 입력창 파일 버튼 또는 우측 Workspace의 +
  • 다중 업로드: 여러 파일을 한 번에 선택
  • 파일 클릭: 미리보기
  • 첨부 토글: 현재 질문 context에 포함할지 선택
구분

Workspace는 Second Brain이 아닙니다. 현재 작업에 필요한 임시 자료는 Workspace에 두고, 장기 지식만 Second Brain으로 승격하세요.

스킬

스킬은 LLM에게 붙이는 작업 매뉴얼입니다. 특정 업무를 할 때 매번 같은 절차, 검증 기준, 출력 형식을 반복해서 설명하지 않도록 만드는 기능입니다.

스킬 선택

방법설명
좌측 스킬 탭사용할 스킬을 클릭하면 활성화되고 입력창 위에 칩으로 표시됩니다. 다시 클릭하거나 칩의 x를 누르면 비활성화됩니다.
입력창 /입력창 맨 앞에서 /를 입력하면 세션 명령과 스킬 자동완성이 뜹니다. Tab, ↑↓, Enter로 선택할 수 있습니다.
/skill-id 요청특정 스킬을 이번 요청에만 명시 적용합니다. 예: /backend-development 이 API 구조 리뷰해줘
Auto질문 내용을 보고 관련 스킬을 자동 선택합니다. 명시 선택한 스킬이 있으면 함께 적용됩니다.

/status, /compact, /clear는 세션 명령입니다. 스킬 ID와 같은 방식으로 자동완성에 뜨지만, 모델 답변을 부르는 것이 아니라 현재 세션 상태를 제어합니다.

Skill Creator

새 스킬은 스킬 탭의 +, 입력창의 Skill+, 또는 /skill-creator 만들고 싶은 스킬 설명으로 만들 수 있습니다. skill-creater, skillcreator, create-skill, new-skill도 같은 별칭으로 처리됩니다.

Skill Creator는 사용자가 입력한 목적, 현재 대화 내용, 고정된 Second Brain 노드, 자동 선택 설명, 태그, 도메인, 서비스, 필요한 도구, when_to_use, when_not_to_use를 바탕으로 사용자 스킬 초안을 만듭니다.

사용자 스킬:
code_assist_v1/user_data/<user>/skills/<skill_id>/SKILL.md

공용 스킬:
code_assist_v1/skills/<skill_id>/SKILL.md

공용 스킬을 수정하면 현재 계정의 사용자 사본으로 덮어쓰는 흐름이 안전합니다. 삭제는 사용자 스킬에 대해서만 사용하는 것을 권장합니다.

좋은 스킬 작성 기준

스킬은 길게 쓰는 것보다 언제 켜지고, 무엇을 보고, 어떤 순서로, 어떻게 검증하는지가 명확해야 합니다. description과 when_to_use는 Auto Skill이 스킬을 고르는 핵심 단서입니다.

---
name: backend-api-review
description: Use when reviewing backend API design, routing, validation, error handling, and tests.
metadata:
  tags: [backend, api, review]
  when_to_use: Backend API 구조, validation, error response, test coverage를 검토할 때
  when_not_to_use: 단순 UI 문구 수정이나 일반 설명 요청
  tool_dependencies: [rg, shell]
  allow_implicit_invocation: true
---

# Backend API Review

## Workflow

1. 요청 범위와 관련 파일을 확인한다.
2. route, schema, validation, error handling, auth 경계를 본다.
3. 테스트 누락과 회귀 위험을 우선 찾는다.
4. 수정이 필요하면 가장 작은 변경으로 제안한다.
5. 실행 가능한 검증 명령을 제시한다.

Notion Workspace

Notion Workspace는 개인 문서, 이미지 포함 노트, 공유 페이지, Second Brain publish 전 초안 정리에 사용합니다.

영역설명
최근 항목최근 수정한 페이지
공유된 페이지다른 사용자가 나에게 공유한 페이지
개인 페이지내가 소유한 페이지
휴지통삭제 페이지 복원 또는 영구 삭제

워크스페이스 이름에 마우스를 올리면 현재 워크스페이스와 공유받은 게스트 워크스페이스가 표시됩니다. 공유받은 페이지가 없으면 게스트 워크스페이스는 표시되지 않습니다.

권장 흐름

문서를 읽고 질문하기

  1. Workspace에 문서를 업로드합니다.
  2. 필요한 경우 Second Brain 토글을 켭니다.
  3. 질문합니다.
  4. 재사용할 내용은 대화 지식화 또는 Notion으로 정리합니다.

Notion에서 정리 후 지식화

  1. Notion에 초안 페이지를 작성합니다.
  2. 이미지, 파일, 표, 캘린더, 하위 페이지를 정리합니다.
  3. 필요한 사용자에게 공유합니다.
  4. 세션에서만 쓸 때는 Chat에 추가를 사용합니다.
  5. 장기 지식으로 확정되면 Second Brain으로 보냅니다.

계정별 적용

모든 UI 기능과 backend 처리는 계정 공통 코드로 동작합니다. admin에서 검증한 Notion 메뉴, 하위 페이지, drag/drop, 공유, Second Brain publish, 문서 업로드, 세션 명령은 다른 계정에서도 같은 방식으로 적용됩니다.

  • admin의 페이지는 다른 사용자에게 자동으로 보이지 않습니다.
  • 새 계정이 처음 접속했을 때 페이지가 없다면 정상입니다.
  • 새 계정은 자기 계정에서 Second Brain 템플릿 만들기를 눌러 페이지를 생성합니다.
  • 다른 사용자가 페이지를 공유하면 공유된 페이지와 게스트 워크스페이스가 표시됩니다.

문제 해결

증상확인할 것
페이지 목록이 비어 보임브라우저 캐시가 오래된 JS를 잡고 있을 수 있습니다. Ctrl + F5로 강력 새로고침하세요.
처음 쓰는 계정에 페이지가 없음Second Brain 템플릿 만들기를 눌러 기본 페이지를 만드세요.
공유 워크스페이스가 보이지 않음실제 공유받은 페이지가 있을 때만 표시됩니다.
문서 업로드가 멈춘 것처럼 보임지식 탭의 job 진행 상태를 확인하세요. PDF/PPTX/DOCX는 시간이 걸릴 수 있습니다.
GGUF 답변이 끝에서 잘림출력 한도입니다. 질문을 나누거나 /compact 후 다시 요청하세요.
graph가 이상하게 연결됨reason과 confidence를 확인하세요. 약한 keyword overlap 관계는 자동 저장하지 않는 것이 원칙입니다.
장기기억이 반영되지 않음입력창의 기억 버튼이 켜져 있는지 확인하세요. 장기기억은 공식 지식보다 낮은 우선순위입니다.
임시 자료가 장기 지식처럼 답변됨Workspace 파일인지 Second Brain source인지 확인하세요. 현재 세션용 자료는 Workspace에 두고, 공식 지식만 Second Brain에 올리세요.
